8.1l Writing Maintainable Programs
Code that YOU understand today isn't enough — it needs to make sense to someone else too. Completes Section 8.1.
Key Terms
Maintainable code
Code written so that another programmer (not just its original author) can understand, fix, and extend it.
Comment
Text in a program ignored by the computer, written purely to explain the code to a human reader.
Theory

A real program should be understandable to ANOTHER programmer

  • A program written for a genuine real-world task needs to be maintainable — someone OTHER than its original author should be able to read, understand, and safely modify it.
  • (Note: exam questions sometimes deliberately DON'T follow these rules, to test your ability to trace through unclear code or spot errors — real production code should always follow them.)

Three concrete habits that make code maintainable

  • Use MEANINGFUL names for every variable, constant, array, procedure, and function — a name like StudentTotal tells a reader what it's for; a name like x or temp2 doesn't.
  • Divide the program into MODULES for each distinct task, using procedures and functions — a program that's just one giant block of code is far harder to understand and fix than one broken into clearly-named pieces.
  • Fully COMMENT the code, using the programming language's own commenting feature.
LanguageHow comments are written
Python# starts a comment for that whole line
Pseudocode// starts a comment for that whole line (used throughout this course)

What comments are actually for

  • A comment is completely ignored by the computer when the program runs — it exists purely to explain something to a human reader.
  • Good comments explain WHY something is done a certain way (or what a tricky piece of logic is FOR), not just restate exactly what the code obviously already says.
  • Every worked example throughout this course (Chapters 7 and 8) has used exactly this kind of comment — e.g. explaining why a Counter starts at -1, or what a nested loop level is tracking.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the habits and features that make a program maintainable.

Short answer 1
What does it mean for a program to be "maintainable"?
Reveal answer

It means the code can be understood, fixed, and extended by someone OTHER than the person who originally wrote it — not just by its original author.

Short answer 2
Name the three concrete habits this subsection identifies for writing maintainable code.
Reveal answer

Meaningful names for every data store; dividing the program into modules using procedures/functions; and fully commenting the code.

Fill in the blank 3
In Python, a comment starts with the symbol ______.
Reveal answer

A hash symbol, #.

Spot the error 4
A student writes a program using only single-letter variable names (a, b, c, x, y) throughout, arguing it's faster to type. Why does this go against writing maintainable code?
Reveal answer

Single-letter names give no clue what a variable is actually FOR — another programmer (or the same student, returning to the code weeks later) would have to trace through the whole program just to work out what each one represents, exactly the opposite of the goal of meaningful naming.

Applied / scenario 5
Write a Python comment explaining why a Counter variable starts at -1 (referring back to the sequence-error worked example from 8.1c).
Reveal answer

# Counter starts at -1 so the extra "999" input (used only to end the loop) is not counted as a real mark — a good comment explains the REASON for a non-obvious choice, not just what the line does.

Short answer 6
Does a comment have any effect on how the program actually runs?
Reveal answer

No — a comment is completely ignored by the computer when the program executes. It exists purely to communicate with a human reader of the code.
