8.1h Nested Statements — Three Loops Deep
Selection and iteration can be nested inside each other — a genuinely realistic triple-nested-loop worked example.
Key Terms
Nesting
Placing one construct (loop or selection) entirely inside another.
Outer / middle / inner loop
In a triple-nested structure, the outermost loop runs least often; the innermost runs most often — once for every combination of the loops around it.
Theory

Why nest constructs at all

  • Selection and iteration can be nested one inside the other — this reduces how much code needs to be written, and makes a program simpler to test.
  • One construct can nest within another type — selection inside a loop, or a loop inside another loop (used here).

The task — three levels of statistics, one algorithm

  • Calculate and output the highest, lowest, and average mark for a CLASS of 20 students.
  • Calculate and output the highest, lowest, and average mark for EACH student (across all their subjects).
  • Calculate and output the highest, lowest, and average mark for EACH subject a student takes — 6 subjects, each with 5 tests.
  • All marks are whole numbers between 0 and 100.
Pseudocode — the full triple-nested algorithmDECLARE ClassAverage, StudentAverage, SubjectAverage : REAL DECLARE Student, Subject, Test, Mark : INTEGER DECLARE ClassHigh, ClassLow, ClassTotal : INTEGER DECLARE StudentHigh, StudentLow, StudentTotal : INTEGER DECLARE SubjectHigh, SubjectLow, SubjectTotal : INTEGER ClassHigh ← 0 ClassLow ← 100 ClassTotal ← 0 CONSTANT NumberOfTests ← 5 CONSTANT NumberOfSubjects ← 6 CONSTANT ClassSize ← 20 FOR Student ← 1 TO ClassSize // OUTER loop StudentHigh ← 0 StudentLow ← 100 StudentTotal ← 0 FOR Subject ← 1 TO NumberOfSubjects // MIDDLE loop SubjectHigh ← 0 SubjectLow ← 100 SubjectTotal ← 0 FOR Test ← 1 TO NumberOfTests // INNER loop OUTPUT "Please enter mark " INPUT Mark IF Mark > SubjectHigh THEN SubjectHigh ← Mark ENDIF IF Mark < SubjectLow THEN SubjectLow ← Mark ENDIF SubjectTotal ← SubjectTotal + Mark NEXT Test SubjectAverage ← SubjectTotal / NumberOfTests OUTPUT "Average mark for Subject ", Subject, " is ", SubjectAverage OUTPUT "Highest mark for Subject ", Subject, " is ", SubjectHigh OUTPUT "Lowest mark for Subject ", Subject, " is ", SubjectLow IF SubjectHigh > StudentHigh THEN StudentHigh ← SubjectHigh ENDIF IF SubjectLow < StudentLow THEN StudentLow ← SubjectLow ENDIF StudentTotal ← StudentTotal + SubjectTotal NEXT Subject StudentAverage ← StudentTotal / (NumberOfTests * NumberOfSubjects) OUTPUT "Average mark for Student ", Student, " is ", StudentAverage OUTPUT "Highest mark for Student ", Student, " is ", StudentHigh OUTPUT "Lowest mark for Student ", Student, " is ", StudentLow IF StudentHigh > ClassHigh THEN ClassHigh ← StudentHigh ENDIF IF StudentLow < ClassLow THEN ClassLow ← StudentLow ENDIF ClassTotal ← ClassTotal + StudentTotal NEXT Student ClassAverage ← ClassTotal / (NumberOfTests * NumberOfSubjects * ClassSize) OUTPUT "Average mark for Class is ", ClassAverage OUTPUT "Highest mark for Class is ", ClassHigh OUTPUT "Lowest mark for Class is ", ClassLow

Reading the structure — three "levels", each resetting its own counters

  • SubjectHigh/SubjectLow/SubjectTotal reset at the START of every MIDDLE loop pass — they only ever track ONE subject at a time.
  • StudentHigh/StudentLow/StudentTotal reset at the START of every OUTER loop pass — they only ever track ONE student's overall performance (across all 6 subjects) at a time.
  • ClassHigh/ClassLow/ClassTotal are initialised ONCE, before the outer loop even starts — they must accumulate across the ENTIRE class, all 20 students.
  • Each level's statistics feed UP into the level above it: SubjectHigh feeds into StudentHigh's check; StudentHigh feeds into ClassHigh's check — the same "compare and keep the best" pattern, applied three times at three different scales.
  • Constants (NumberOfTests, NumberOfSubjects, ClassSize) mean the whole algorithm's scale can be changed by editing just THREE values, rather than hunting through the code for every place a number like 5, 6, or 20 appears.

How many times does the innermost loop actually run?

  • 20 students × 6 subjects × 5 tests = 600 total INPUT Mark calls — the innermost loop body runs 600 times in total, even though it's written just once.
  • This is exactly why nesting reduces code: writing out 600 separate INPUT statements by hand would be absurd; three nested FOR loops express the same task in a handful of lines.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the triple-nested class/student/subject statistics algorithm.

Short answer 1
How many times does the innermost loop's body execute in total across the whole algorithm?
Reveal answer

600 times — 20 students × 6 subjects × 5 tests each.

Short answer 2
Why are SubjectTotal and StudentTotal reset at different points in the algorithm?
Reveal answer

SubjectTotal resets at the start of every MIDDLE loop pass (once per subject) because it only tracks ONE subject at a time. StudentTotal resets at the start of every OUTER loop pass (once per student) because it needs to accumulate across all 6 subjects for that ONE student.

Fill in the blank pseudocode 3
Complete the class average calculation: ClassAverage ← ClassTotal / (NumberOfTests * ______ * ClassSize)
Reveal answer

ClassAverage ← ClassTotal / (NumberOfTests * NumberOfSubjects * ClassSize).

Spot the error 4
A student accidentally moves ClassHigh ← 0 and ClassLow ← 100 to INSIDE the outer FOR loop (so they reset for every student), instead of before it. What breaks?
Reveal answer

ClassHigh/ClassLow would only ever reflect the MOST RECENT student, since they'd reset every time a new student starts — the final "Class" statistics would just be the last student's own statistics, not a genuine reflection of the whole class of 20.

Applied / scenario 5
Using CONSTANTs the way this algorithm does, what would you need to change to test this algorithm with a class of only 3 students, 2 subjects, and 2 tests each?
Reveal answer

Just the three CONSTANT lines: CONSTANT NumberOfTests ← 2, CONSTANT NumberOfSubjects ← 2, CONSTANT ClassSize ← 3 — nothing else in the algorithm needs to change, since every loop and calculation refers to these constants rather than hardcoded numbers.

Short answer 6
What real advantage does nesting loops give here, beyond just "less typing"?
Reveal answer

It makes the program genuinely easier to test — each level's logic (subject stats, student stats, class stats) can be reasoned about and checked on its own, and a bug found at one level (e.g. subject stats) doesn't require re-checking unrelated logic at another level.
