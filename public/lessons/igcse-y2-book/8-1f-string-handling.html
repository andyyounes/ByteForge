8.1f String Handling
Length, substrings, upper/lower case — and the one indexing trap that catches almost everyone once.
Key Terms
Length
The number of characters in a string — spaces count too.
Substring
Extracting part of a string, starting at a given position for a given length.
Position/index
A character's location within a string — pseudocode starts counting at 1, Python starts counting at 0.
Theory

Four string-handling methods you need to use

  • Length — the number of characters, e.g. "Computer Science" has length 16 (the space counts as a character too).
  • Substring — extracting part of a string, e.g. extracting "Science" out of "Computer Science".
  • Upper — converting every letter to uppercase, e.g. "Computer Science" → "COMPUTER SCIENCE".
  • Lower — converting every letter to lowercase, e.g. "Computer Science" → "computer science".

Substring — the ONE genuine trap: where counting starts

  • Pseudocode strings start counting positions at 1. Python strings start counting positions at 0.
  • Pseudocode's SUBSTRING(string, start, length) takes THREE arguments: the string, the START position, and HOW MANY characters to extract.
  • Python instead uses SLICING with square brackets: string[start:end] — where start is the first position INCLUDED, and end is the position AFTER the last one included (exclusive), not a length.
MethodExtracting "Science"Notes
Pseudocode (1-indexed)SUBSTRING("Computer Science", 10, 7)Start position 10, length 7 characters.
Python (0-indexed)"Computer Science"[9:16]Start position 9 (one less, since Python starts at 0), end position 16 (exclusive — the slice runs up to but not including index 16).

Why the Python numbers look "off by one" — but aren't actually wrong

  • "Science" starts at pseudocode position 10 — but at Python position 9, because Python starts counting from 0 instead of 1.
  • The pseudocode version's THIRD argument is a LENGTH (7 characters). The Python version's second number is an END POSITION (16) — 9 + 7 = 16, so they describe the exact same 7 characters, just via a different counting convention.
  • Always converting carefully between "pseudocode position" and "Python index" (subtract 1) is the single most common source of off-by-one string bugs.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the four string-handling methods and 1-indexed vs. 0-indexed positions.

Short answer 1
What is the length of the string "Computer Science", and why does the space count?
Reveal answer

16 characters — spaces are stored as real characters within a string, exactly like letters, so they're included in the length count.

Short answer 2
What position does the FIRST character of a string occupy in pseudocode, versus in Python?
Reveal answer

Pseudocode: position 1. Python: position (index) 0.

Fill in the blank pseudocode 3
Complete the Python call to convert MyString to uppercase: MyString.______()
Reveal answer

MyString.upper().

Spot the error 4
A student converts pseudocode's SUBSTRING(MyString, 1, 5) (the first 5 characters) directly into Python as MyString[1:5]. What's the actual mistake?
Reveal answer

Pseudocode position 1 is Python index 0, not 1 — using [1:5] in Python actually skips the FIRST character and only grabs characters 2-5. The correct Python slice is MyString[0:5].

Applied / scenario 5
Write the pseudocode SUBSTRING call, and the equivalent Python slice, to extract "Computer" (the first 8 characters) from "Computer Science".
Reveal answer

Pseudocode: SUBSTRING("Computer Science", 1, 8). Python: "Computer Science"[0:8].

Short answer 6
What is an "empty string", and is it a valid string?
Reveal answer

A string with no characters stored in it at all — length 0. It's a perfectly valid string, just the shortest possible one.
