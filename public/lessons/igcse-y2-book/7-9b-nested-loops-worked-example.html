7.9b A Real Nested-Loop Algorithm
Combining totalling, max/min/average, validation, and CASE OF into one genuinely realistic algorithm.
Key Terms
Outer loop
A loop that controls how many times an ENTIRE inner loop repeats.
Inner loop
A loop nested inside another loop, running to completion every single time the outer loop takes one step.
Theory
Worked example 2 — school test results

A school with 600 students wants to produce information from the results of four standard tests: Maths, Science, English, and IT — each out of 100 marks. The output should be the highest, lowest, and average mark for EACH test, and the highest, lowest, and average mark OVERALL. All the marks need to be input.

Pseudocode — nested loops, CASE OF, per-subject AND overall statistics// initialisation of overall counters OverallHighest ← 0 OverallLowest ← 100 OverallTotal ← 0 FOR Test ← 1 TO 4 // outer loop for the tests // initialisation of subject counters SubjectHighest ← 0 SubjectLowest ← 100 SubjectTotal ← 0 CASE OF Test 1 : SubjectName ← "Maths" 2 : SubjectName ← "Science" 3 : SubjectName ← "English" 4 : SubjectName ← "IT" ENDCASE FOR StudentNumber ← 1 TO 600 // inner loop for the students REPEAT OUTPUT "Enter Student ", StudentNumber, "'s mark for ", SubjectName INPUT Mark UNTIL Mark < 101 AND Mark > -1 IF Mark < OverallLowest THEN OverallLowest ← Mark IF Mark < SubjectLowest THEN SubjectLowest ← Mark IF Mark > OverallHighest THEN OverallHighest ← Mark IF Mark > SubjectHighest THEN SubjectHighest ← Mark OverallTotal ← OverallTotal + Mark SubjectTotal ← SubjectTotal + Mark NEXT StudentNumber SubjectAverage ← SubjectTotal / 600 OUTPUT SubjectName OUTPUT "Average mark is ", SubjectAverage OUTPUT "Highest Mark is ", SubjectHighest OUTPUT "Lowest Mark is ", SubjectLowest NEXT Test OverallAverage ← OverallTotal / 2400 OUTPUT "Overall Average is ", OverallAverage OUTPUT "Overall Highest Mark is ", OverallHighest OUTPUT "Overall Lowest Mark is ", OverallLowest

Reading the structure: two loops, two "levels" of statistics

  • The OUTER loop (FOR Test ← 1 TO 4) runs once per subject — Maths, Science, English, IT — using CASE OF to set the subject's name from the Test number.
  • The INNER loop (FOR StudentNumber ← 1 TO 600) runs once per student, EVERY single time the outer loop takes a step — so the inner loop's body genuinely executes 4 × 600 = 2400 times in total.
  • SubjectHighest/SubjectLowest/SubjectTotal are RESET back to their starting values at the start of every outer loop pass — they only need to track ONE subject at a time. OverallHighest/OverallLowest/OverallTotal are initialised ONCE, outside both loops, because they must track across ALL 2400 marks.
  • A validation REPEAT...UNTIL loop (Mark < 101 AND Mark > -1) sits inside the inner loop, re-asking for the SAME student's mark until it's a valid 0-100 value, before moving on.
  • Comments (the // lines) are used throughout purely to make the algorithm more understandable to a human reader — they have no effect on what the algorithm actually does.

Testing an algorithm this large — reduce the scale first

  • Dry-running this algorithm exactly as written would mean tracing 2400 individual inputs by hand — completely impractical.
  • The sensible approach: reduce the numbers for TESTING purposes only — e.g. 5 students and 2 subjects instead of 600 and 4 — trace THAT smaller version thoroughly, then trust the same logic scales up once it's proven correct on the small version.
  • This is a genuinely common real technique: test the same LOGIC at a manageable scale before ever running it at full, real-world scale.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the nested-loop school-results algorithm.

Short answer 1
How many times does the inner loop's body actually execute in total, across the whole algorithm?
Reveal answer

2400 times — the inner loop runs 600 times (once per student) for EACH of the 4 outer loop passes (once per subject): 4 × 600 = 2400.

Short answer 2
Why is SubjectTotal reset to 0 at the start of every outer loop pass, but OverallTotal is only initialised once?
Reveal answer

SubjectTotal only ever needs to track ONE subject at a time, so it must start fresh for each new subject. OverallTotal needs to accumulate across ALL subjects and all students, so it's only initialised once, before the outer loop even begins.

Fill in the blank pseudocode 3
Complete the CASE OF statement: CASE OF Test
  1 : SubjectName ← "Maths"
  2 : SubjectName ← ______
  ...
Reveal answer

SubjectName ← "Science".

Spot the error 4
A student moves the line SubjectTotal ← 0 to OUTSIDE the outer FOR loop (before it starts), instead of inside it. What goes wrong?
Reveal answer

SubjectTotal would never reset between subjects — Science's total would start from wherever Maths's total finished, English's from Science's, and so on, making every subject average AFTER the first one completely wrong (too high, accumulating marks from previous subjects).

Applied / scenario 5
Why does the validation loop use UNTIL Mark < 101 AND Mark > -1 rather than UNTIL Mark <= 100 AND Mark >= 0, even though both describe the same 0-100 range?
Reveal answer

They're mathematically equivalent ways of expressing the exact same valid range (0 to 100 inclusive) — either is correct; this is just a stylistic choice some algorithms make, and recognising that both forms describe the same condition is the actual skill being tested.

Short answer 6
Why would a real dry run of this algorithm reduce the number of students and subjects first, rather than tracing all 2400 inputs?
Reveal answer

Tracing 2400 individual inputs by hand is completely impractical. Reducing to a small number (e.g. 5 students, 2 subjects) still fully tests the same LOGIC, just at a manageable scale — the algorithm's structure doesn't change, only how many times it repeats.
