8.3a File Handling
Making data outlive the program that created it — completes Unit 8 (Programming).
Key Terms
File
A named, permanent store of data on a storage device, identified by its filename.
OPEN / CLOSE
Statements that begin and end a program's access to a file.
Theory

Why files exist — RAM alone isn't enough

  • Any data held in RAM is lost the instant the computer is switched off. Data saved to a FILE is stored permanently instead.
  • A file can be read again by the SAME program later, by a DIFFERENT program entirely, or even sent to be used on another computer.
  • Storing data in files is one of the most-used features of real programming.

The basic pattern — open, use, close

  • Every file is identified by its FILENAME.
  • Writing: OPEN the file for writing, WRITE the data to it, then CLOSE it.
  • Reading: OPEN the file for reading, READ the data from it, then CLOSE it.
  • Always CLOSING a file after use is important — it ensures the data is actually saved properly and the file isn't left "locked" for other programs to use.
Pseudocode — writing a line, then reading it backDECLARE TextLine : STRING DECLARE MyFile : STRING MyFile ← "MyText.txt" // writing the line of text to the file OPEN MyFile FOR WRITE OUTPUT "Please enter a line of text" INPUT TextLine WRITEFILE MyFile, TextLine CLOSEFILE(MyFile) // reading the line of text from the file OUTPUT "The file contains this line of text:" OPEN MyFile FOR READ READFILE MyFile, TextLine OUTPUT TextLine CLOSEFILE(MyFile)
Python — the exact same taskMyFile = open("MyText.txt", "w") TextLine = input("Please enter a line of text ") MyFile.write(TextLine) MyFile.close() print("The file contains this line of text") MyFile = open("MyText.txt", "r") TextLine = MyFile.read() print(TextLine) MyFile.close()
Opening for writingPseudocode: OPEN MyFile FOR WRITE
Python: open("MyText.txt", "w") — "w" means write mode.
Opening for readingPseudocode: OPEN MyFile FOR READ
Python: open("MyText.txt", "r") — "r" means read mode.

Reading the correspondence line by line

  • Python's open(filename, mode) combines opening AND specifying read/write mode into one call — pseudocode splits this into OPEN ... FOR WRITE or OPEN ... FOR READ.
  • MyFile.write(TextLine) and MyFile.read() correspond directly to pseudocode's WRITEFILE and READFILE.
  • MyFile.close() is exactly pseudocode's CLOSEFILE(MyFile) — always called once reading or writing is finished.
Practice — Test Yourself

These questions only cover what THIS subsection taught — file handling (completes Unit 8: Programming).

Short answer 1
What happens to data held in RAM when the computer is switched off, and how does storing it in a file change this?
Reveal answer

Data in RAM is lost the instant the power is switched off. Data saved to a FILE is stored permanently, surviving being switched off, and can be read again later.

Short answer 2
What is the basic three-step pattern for using a file, whether reading or writing?
Reveal answer

OPEN the file (specifying read or write), READ or WRITE the actual data, then CLOSE the file.

Fill in the blank pseudocode 3
Complete the Python call to open "Scores.txt" for writing: MyFile = open("Scores.txt", "______")
Reveal answer

MyFile = open("Scores.txt", "w").

Spot the error 4
A student writes data to a file but never calls CLOSEFILE / .close() afterwards. What real problem can this cause?
Reveal answer

The data may not actually be properly saved to the file at all (some systems buffer writes and only guarantee they're saved on close), and the file could remain "locked", preventing other programs from accessing it until it's properly closed.

Applied / scenario 5
Write pseudocode to open a file called "Log.txt" for writing, write the string "Program started", and close it.
Reveal answer

OPEN "Log.txt" FOR WRITE
WRITEFILE "Log.txt", "Program started"
CLOSEFILE("Log.txt")

Short answer 6
Give one real reason a program might read data from a file that was written by a COMPLETELY DIFFERENT program.
Reveal answer

Any genuine reason where two separate programs need to share the same data — e.g. one program exports a list of scores to a file, and a completely separate reporting program reads that same file later to produce a summary, without the two programs ever running at the same time or communicating directly.
