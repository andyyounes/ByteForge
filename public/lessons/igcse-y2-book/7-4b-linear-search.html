7.4b Standard Methods: Linear Search
Checking every item, one at a time, until you find what you're looking for (or run out of list).
Key Terms
Linear search
Searching a list from the start, checking each item in turn until a match is found or the list ends.
Flag
A variable (e.g. boolean Found) used to record whether a target condition has been met.
Theory

How a linear search works

  • Start at the FIRST item in the list, and compare it with the target value being searched for.
  • If it matches, the search stops — the item has been found.
  • If it doesn't match, move to the NEXT item and repeat the comparison.
  • Continue until either a match is found, OR the end of the list is reached with no match (item not found).
  • A linear search does not require the list to be sorted — it works on any list, but can be slow for very large lists since, in the worst case, every item must be checked.
Linear search — using a Found flagCounter ← 1 Found ← FALSE REPEAT IF Name[Counter] = "Ali" THEN Found ← TRUE ELSE Counter ← Counter + 1 ENDIF UNTIL Found = TRUE OR Counter > ClassSize IF Found = TRUE THEN OUTPUT "Ali found at position ", Counter ELSE OUTPUT "Ali not found" ENDIF

Reading the algorithm

  • The loop condition UNTIL Found = TRUE OR Counter > ClassSize is what stops the search EARLY once a match is found — without it, the algorithm would keep checking items pointlessly after already finding the target.
  • Counter > ClassSize is the safety condition — it stops the loop from running past the end of the list if the name is never found.
  • The Found flag starts as FALSE and is only ever set to TRUE — it never needs to be reset back to FALSE inside the loop.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the linear search algorithm.

Short answer 1
Why does a linear search stop as soon as a match is found, rather than checking the rest of the list?
Reveal answer

Because there's no need — the target has already been located, so continuing to check the remaining items would just waste time.

Short answer 2
What is the purpose of the condition Counter > ClassSize in the loop's UNTIL line?
Reveal answer

It's a safety check that stops the loop once every item in the list has been examined, so the algorithm doesn't try to read past the end of the list if the target is never found.

Fill in the blank pseudocode 3
Complete the initial values before a linear search begins: Counter ← ____ and Found ← ____
Reveal answer

Counter ← 1 (start at the first item) and Found ← FALSE (nothing has been matched yet).

Spot the error 4
A student's linear search never increments Counter inside the ELSE branch when there's no match. What will happen when the target isn't the first item?
Reveal answer

The algorithm will get stuck in an infinite loop — it keeps re-checking the same (non-matching) item forever, since Counter never advances to look at the next one.

Applied / scenario 5
A list has 500 items. In the WORST case, how many comparisons would a linear search need to make to determine an item is NOT in the list?
Reveal answer

500 — every single item must be checked before concluding the target isn't present, since there's no early match to stop on.

Short answer 6
Does a linear search require the list to be sorted first?
Reveal answer

No — a linear search works on a list in any order, since it simply checks items one at a time from the start.
