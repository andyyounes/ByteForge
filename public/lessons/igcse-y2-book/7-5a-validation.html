7.5a Validation
Automated checks that reject unreasonable data before it ever enters the system.
Key Terms
Validation
An automated check that data is reasonable, carried out by a computer system as data is entered.
Range check
Checks a value falls between a set lower and upper boundary.
Length check
Checks the number of characters entered — either an exact count, or within a range.
Type check
Checks data is of the expected data type, e.g. an integer.
Presence check
Checks a required field has not been left blank.
Format check & check digit
Format check: data matches a pre-defined pattern. Check digit: a final digit calculated from the others, used to catch data-entry errors.
Theory

What validation is

  • For a computer system to only accept data that is reasonable and accurate, every item of data needs to be examined before it is accepted.
  • Validation is an AUTOMATED check carried out by the computer system as data is entered.
  • If data FAILS a validation check, it is REJECTED, an explanatory error message is shown, and the user is given the opportunity to re-enter it.
  • More than one validation check can apply to the same piece of data — for example, an exam mark could need a range check, a type check, AND a presence check all together.
  • Six validation check types are covered here: range, length, type, presence, format, and check digit.
Range check — a percentage mark, 0 to 100 inclusiveOUTPUT "Please enter the student's mark " REPEAT INPUT StudentMark IF StudentMark < 0 OR StudentMark > 100 THEN OUTPUT "The student's mark should be in the range 0 to 100, please re-enter the mark " ENDIF UNTIL StudentMark >= 0 AND StudentMark <= 100

Length check — two forms

  • Exact length: e.g. a password must be exactly 8 characters — 7-or-fewer or 9-or-more characters is rejected.
  • Range of lengths: e.g. a family name between 2 and 30 characters inclusive — a 1-character or 31-plus-character name is rejected.
  • LENGTH(...) is the pseudocode operation returning the number of characters in a string.
Length check — exact length (an 8-character password)OUTPUT "Please enter your password of eight characters " REPEAT INPUT Password IF LENGTH(Password) <> 8 THEN OUTPUT "Your password must be exactly eight characters, please re-enter " ENDIF UNTIL LENGTH(Password) = 8
Length check — a range of lengths (family name, 2-30 characters)OUTPUT "Please enter your family name " REPEAT INPUT FamilyName IF LENGTH(FamilyName) > 30 OR LENGTH(FamilyName) < 2 THEN OUTPUT "Too short or too long, please re-enter " ENDIF UNTIL LENGTH(FamilyName) <= 30 AND LENGTH(FamilyName) >= 2
Type check — the number of brothers must be a whole numberOUTPUT "How many brothers do you have? " REPEAT INPUT NumberOfBrothers IF NumberOfBrothers <> DIV(NumberOfBrothers, 1) THEN OUTPUT "This must be a whole number, please re-enter" ENDIF UNTIL NumberOfBrothers = DIV(NumberOfBrothers, 1)
Presence check — an email address must not be left blankOUTPUT "Please enter your email address " REPEAT INPUT EmailAddress IF EmailAddress = "" THEN OUTPUT "*Required " ENDIF UNTIL EmailAddress <> ""

Format check

  • A format check confirms that the characters entered conform to a pre-defined PATTERN — for example, a code that must be in the form CUB9999 (three letters, then four digits).

Check digit

  • A check digit is the FINAL digit in a code, calculated from all the other digits in that code.
  • Used on barcodes, product codes, ISBNs (International Standard Book Numbers), and VINs (Vehicle Identification Numbers).
  • Check digits are designed to catch errors made when typing or scanning data:
  • — an incorrect digit, e.g. 5327 entered instead of 5307
  • — a transposition error, where two digits swap places, e.g. 5037 instead of 5307
  • — omitted or extra digits, e.g. 537 or 53107 instead of 5307
  • — a phonetic error, e.g. entering "13" (thirteen) instead of "30" (thirty)
Validation catchesData that is out of range, the wrong length, the wrong type, missing, badly formatted, or has a mistyped/mis-scanned digit.
Validation does NOT catchData that is plausible but simply wrong — e.g. a valid-format but incorrect email address that was typed correctly but is not actually the user's own. That's verification's job (or beyond either check).
Practice — Test Yourself

These questions only cover what THIS subsection taught — the six validation check types.

Short answer 1
What happens when data fails a validation check?
Reveal answer

It is rejected, an explanatory error message is displayed, and the user is given the opportunity to re-enter the data.

Short answer 2
Which validation check would you use to make sure an "Age" field entered by a user is never left blank?
Reveal answer

A presence check.

Fill in the blank pseudocode 3
Complete this length check's loop condition, for a password that must be exactly 8 characters: UNTIL LENGTH(Password) ____ 8
Reveal answer

UNTIL LENGTH(Password) = 8.

Spot the error 4
A check digit system catches transposition errors (e.g. 5037 instead of 5307) and incorrect digits — but a student claims it will catch EVERY possible typing mistake. Is this true?
Reveal answer

No — check digits only reliably catch specific known error patterns (incorrect digit, transposition, omitted/extra digits, phonetic errors). Some combinations of multiple simultaneous errors could still produce a code that happens to pass the check digit calculation despite being wrong.

Applied / scenario 5
Write pseudocode to validate a child's age for a fairground ride, where the age must be over 7 and under 12.
Reveal answer

OUTPUT "Please enter the child's age "
REPEAT
  INPUT Age
  IF Age <= 7 OR Age >= 12
  THEN
    OUTPUT "Age must be over 7 and under 12, please re-enter "
  ENDIF
UNTIL Age > 7 AND Age < 12

Applied / scenario 6
A part number must be in the form XXX999 (three letters followed by three digits). Which validation check type is this, and name one OTHER check that could ALSO reasonably apply to entering a telephone number.
Reveal answer

The part number example is a FORMAT check. For a telephone number, a LENGTH check (a reasonable number of digits) and/or a TYPE check (digits only) could also reasonably apply — multiple checks are often combined on the same piece of data.
