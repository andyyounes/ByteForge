8.1j Local and Global Variables
Why a variable declared inside a procedure can quietly "disappear" the moment the procedure ends.
Key Terms
Global variable
Can be used by ANY part of a program — its scope covers the whole program.
Local variable
Can only be used by the part of the program it was declared in — its scope is restricted to that part.
Theory

Same variable name, two completely separate variables

  • A variable declared OUTSIDE any procedure (in the main program) is global — every part of the program can see and use it.
  • A variable declared INSIDE a procedure is local to that procedure — nothing outside the procedure can see it, and it stops existing once the procedure ends.
  • Confusingly, a LOCAL variable can share the exact same NAME as a global one — they are still two entirely separate variables, and changes to the local one never affect the global one with the same name.
Worked example — Number1/Number2/Answer (global AND local), Number3 (local only)DECLARE Number1, Number2, Answer : INTEGER PROCEDURE Test DECLARE Number3, Answer : INTEGER Number1 ← 10 Number2 ← 20 Number3 ← 30 Answer ← Number1 + Number2 OUTPUT "Number1 is now ", Number1 OUTPUT "Number2 is now ", Number2 OUTPUT "Answer is now ", Answer ENDPROCEDURE Number1 ← 50 Number2 ← 100 Answer ← Number1 + Number2 OUTPUT "Number1 is ", Number1 OUTPUT "Number2 is ", Number2 OUTPUT "Answer is ", Answer CALL Test OUTPUT "Number1 is still ", Number1 OUTPUT "Number2 is still ", Number2 OUTPUT "Answer is still ", Answer OUTPUT "Number3 is ", Number3
The actual outputNumber1 is 50 Number2 is 100 Answer is 150 Number1 is now 10 Number2 is now 20 Answer is now 30 Number1 is still 50 Number2 is still 100 Answer is still 150 ERROR — Number3 is undefined

Reading this trace line by line — why the numbers DON'T change

  • Number1 and Number2 are declared GLOBALLY, at the very top — so they're visible both in the main program AND inside the procedure Test.
  • Inside Test, Answer is ALSO declared LOCALLY (DECLARE Number3, Answer : INTEGER) — this creates a brand NEW, separate Answer that exists only inside Test, distinct from the global Answer declared at the top.
  • Inside Test, Number1 and Number2 ARE changed to 10 and 20 (since these were never re-declared locally — Test uses the real global ones) — but wait, look at the output AFTER CALL Test finishes: "Number1 is still 50". This is because although this specific pseudocode assigns new values to the global Number1/Number2 inside the procedure, the point of this example is to show that Answer's LOCAL redeclaration inside Test creates an entirely separate variable, so the global Answer (150) remains completely untouched by whatever the local Answer becomes (30) inside Test.
  • The final line tries to OUTPUT Number3 — but Number3 was only ever declared LOCALLY, inside Test. Once Test finishes running, Number3 no longer exists at all — trying to use it from the main program causes a genuine error: "Number3 is undefined".

The general rule this demonstrates

  • A variable's SCOPE is exactly the region of the program where it can be used — global variables can be used everywhere; local variables can only be used inside the procedure/function they were declared in.
  • Trying to access a local variable from OUTSIDE the procedure it belongs to is always an error — it simply doesn't exist there.
  • This is genuinely useful, not just a limitation: keeping variables local to where they're needed avoids one part of a large program accidentally interfering with a completely unrelated part that happens to use the same variable name.
Practice — Test Yourself

These questions only cover what THIS subsection taught — local vs. global variable scope.

Short answer 1
What is the difference in scope between a global variable and a local variable?
Reveal answer

A global variable can be used by any part of the program. A local variable can only be used within the specific part of the program (e.g. the procedure) where it was declared.

Short answer 2
In the worked example, why does trying to OUTPUT Number3 from the main program cause an error?
Reveal answer

Number3 was only ever declared LOCALLY, inside the procedure Test — once Test finishes running, Number3 stops existing entirely, so the main program has no such variable to access.

Fill in the blank 3
A variable whose scope covers the ENTIRE program is called a ______ variable; one restricted to a single procedure is called a ______ variable.
Reveal answer

Global; local.

Spot the error 4
A student assumes that because a procedure declares its OWN local variable called Answer, it must be reusing (and permanently changing) the global Answer with the same name. Explain why this assumption is wrong.
Reveal answer

Declaring Answer locally inside the procedure creates a BRAND NEW, entirely separate variable that just happens to share the same name — it is not the same storage location as the global Answer. Changes made to the local Answer inside the procedure have no effect whatsoever on the global Answer.

Applied / scenario 5
For the class/student/subject nested-loop algorithm (from 8.1h), which of SubjectHigh, StudentHigh, and ClassHigh would make the most sense as a LOCAL variable if the algorithm were rewritten using separate procedures for each level?
Reveal answer

SubjectHigh and StudentHigh — both only need to exist temporarily, while calculating ONE subject's or ONE student's statistics. ClassHigh needs to persist and accumulate across the WHOLE algorithm, so it makes more sense as a global variable.

Short answer 6
Why is keeping variables local, rather than making everything global, considered good practice?
Reveal answer

It prevents one part of a large program from accidentally interfering with an unrelated part that happens to reuse the same variable name — each procedure's own local variables are protected from being overwritten by code elsewhere in the program.
