7.4c Standard Methods: Bubble Sort
Repeatedly comparing neighbours and swapping them — the simplest sorting algorithm you'll meet.
Key Terms
Bubble sort
A sorting algorithm that repeatedly steps through a list, swapping adjacent items that are in the wrong order.
Swapped flag
A boolean recording whether any swap happened during a pass — used to detect the list is already sorted.
Theory

How bubble sort works

  • Compare each PAIR of adjacent items in the list, working from the start to the end.
  • If a pair is in the wrong order (the first is bigger than the second, for an ascending sort), SWAP them.
  • After one full pass through the list, the largest unsorted value has "bubbled" to the end — hence the name.
  • Repeat the whole pass again, and again, until an ENTIRE pass completes with NO swaps made — at that point the list is fully sorted.
  • A flag variable (e.g. Swapped) records whether any swap happened during the current pass, so the algorithm knows when to stop repeating.
Bubble sort — sorting Temperature[] into ascending orderREPEAT Swapped ← FALSE FOR Counter ← 1 TO (ArraySize - 1) IF Temperature[Counter] > Temperature[Counter + 1] THEN Last ← Temperature[Counter] Temperature[Counter] ← Temperature[Counter + 1] Temperature[Counter + 1] ← Last Swapped ← TRUE ENDIF NEXT Counter UNTIL Swapped = FALSE

Reading the algorithm

  • The swap itself needs a temporary variable (Last) — without it, assigning Temperature[Counter] ← Temperature[Counter+1] directly would overwrite and lose the original value before it could be placed into Temperature[Counter+1].
  • The outer REPEAT ... UNTIL Swapped = FALSE loop is what makes this a genuine sort — a SINGLE pass (the inner FOR loop) is not enough to guarantee a fully sorted list, since large values only move one position per pass unless swapped repeatedly across several passes.
  • Swapped is reset to FALSE at the START of every new pass — if it stayed TRUE from a previous pass, the algorithm could never detect that the list has become fully sorted.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the bubble sort algorithm.

Short answer 1
Why is a temporary variable (like Last) needed to swap two array elements?
Reveal answer

Because directly assigning one element to the other would overwrite it and permanently lose its original value before it can be moved into the other position — the temporary variable holds onto that value during the swap.

Short answer 2
How does the algorithm know the list is fully sorted and stop repeating passes?
Reveal answer

Once an entire pass through the list completes with NO swaps made, the Swapped flag stays FALSE, and the outer UNTIL Swapped = FALSE loop condition ends the sort.

Fill in the blank pseudocode 3
Complete the reset that must happen at the start of every pass: Swapped ← ____
Reveal answer

Swapped ← FALSE — it must be reset every pass so a genuinely sorted pass can be detected.

Spot the error 4
A student's bubble sort never resets Swapped to FALSE at the start of a new pass. What goes wrong?
Reveal answer

Once Swapped is set to TRUE on any pass, it stays TRUE forever, so UNTIL Swapped = FALSE is never satisfied — the algorithm runs forever in an infinite loop, even after the list is already sorted.

Applied / scenario 5
A list [5, 2, 8, 1] undergoes ONE pass of bubble sort. Trace through it (as shown in the diagram) and write the resulting list after that single pass.
Reveal answer

[2, 5, 1, 8] — 5&2 swap → [2,5,8,1]; 5&8 no swap; 8&1 swap → [2,5,1,8]. Note it is NOT fully sorted after just one pass — a further pass is needed to move the 1 further left.

Short answer 6
In the pseudocode, why does the FOR loop run to ArraySize - 1 rather than ArraySize?
Reveal answer

Because each comparison looks at Temperature[Counter] AND Temperature[Counter + 1] — if Counter reached ArraySize, Counter + 1 would go past the end of the array, which doesn't exist.
