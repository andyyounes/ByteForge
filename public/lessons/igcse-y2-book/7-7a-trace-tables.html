7.7a Trace Tables to Document Dry Runs of Algorithms
Working through an algorithm by hand, one step at a time, and recording exactly what happens.
Key Terms
Dry run
The manual exercise of working through an algorithm step by step, by hand.
Trace table
A table used to record the value of each variable every time it changes during a dry run, plus a column for any output.
Theory

Why trace tables are used

  • Finding out the purpose (or correctness) of an algorithm requires a thorough, structured approach — recording and studying the result of each individual step, using test data.
  • A trace table has one column for EACH variable in the algorithm, plus a column for any OUTPUT.
  • During the dry run: every time a variable's value CHANGES, the new value is written in that variable's column on a new row; every time a value is OUTPUT, it is written in the output column.
  • If a variable does not change on a given step, its column is usually left blank on that row (not re-written).

The algorithm being traced

  • The flowchart initialises A←0, B←0, C←100, then loops 10 times: it inputs a value X, updates B (a running maximum) if X is bigger, updates C (a running minimum) if X is smaller, then increments the counter A.

What the completed trace table shows

  • Reading the final output (15, 2) reveals the PURPOSE of the algorithm: it selects the LARGEST and SMALLEST numbers from a list of ten positive values (B ends up holding the largest, C the smallest).
  • Exam questions often deliberately use single-letter variables (A, B, C, X) instead of meaningful names precisely so you have to trace the algorithm to work out its purpose.
  • The exact same trace table works whether the algorithm is shown as a flowchart OR as equivalent pseudocode — the trace table only cares about the sequence of variable changes, not how the algorithm is written down.

Practice — Test Yourself

These questions only cover what THIS subsection taught — trace tables and dry runs.

Short answer 1
What is a "dry run"?
Reveal answer

The manual exercise of working through an algorithm step by step, by hand.

Short answer 2
What goes into a trace table, and when is a new value written into a column?
Reveal answer

One column for each variable plus a column for output. A new value is written into a variable's column every time that variable's value CHANGES; a value is written into the output column every time something is output.

Fill in the blank pseudocode / concept 3
In the worked example, B tracks the running ______ of the input values, while C tracks the running ______.
Reveal answer

B tracks the running MAXIMUM (largest value seen so far); C tracks the running MINIMUM (smallest value seen so far).

Spot the error 4
A student building a trace table re-writes EVERY variable's current value on EVERY row, even when a variable hasn't changed. Why is this against standard trace-table convention, even if not technically wrong?
Reveal answer

Standard convention only records a NEW value when a variable actually changes — leaving other columns blank on that row. Re-writing unchanged values on every row makes it harder to see, at a glance, exactly which step changed which variable, defeating the purpose of a clean trace.

Applied / scenario 5
Using the same algorithm and test data 400, 800, 190, 170, 300, 110, 600, 150, 130, 900 — what would the final OUTPUT be?
Reveal answer

900, 110 — B (the maximum) ends at 900, and C (the minimum) ends at 110.

Short answer 6
Why do exam questions sometimes deliberately use single-letter variable names like A, B, C, X instead of meaningful names?
Reveal answer

So the exam can ask you to work out the PURPOSE of the algorithm yourself by tracing it, rather than the variable names giving the purpose away.
