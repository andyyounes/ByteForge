3.01 The Memory System
Two jobs, one trade-off: running programs needs speed, storing data needs capacity and low cost.
Key Terms
Memory
Storage the processor can access directly.
(File) store
Long-term storage, not directly accessible by the processor.
Primary storage
Registers, cache and main memory — fast, directly accessible, limited capacity.
Secondary storage
Long-term storage (hard disk, etc.) — slower, but much higher capacity and cheaper per byte.
Theory

A computer system has two main uses — and each has a different bottleneck

  • The FIRST main use is to run programs. Increasing performance here first requires faster PROCESSOR speed — but that improvement is only useful if the time taken to ACCESS the stored program keeps up too.
  • In reality, access speeds have improved over time, but they haven't kept full pace with processor speed improvements — access is usually the bottleneck.
  • The SECOND main use is to store data. Here, the major issues are CAPACITY and COST — access speed matters far less than for running programs.

Two different ways to describe the same components

  • One way to categorise: "memory" is what the processor can access directly; "(file) store" is used for long-term storage.
  • An alternative way: distinguish between PRIMARY storage and SECONDARY storage.
  • Terminology in this area is genuinely inconsistent across sources — both descriptions are used, and neither is simply "wrong".

The memory hierarchy — a useful way to see the trade-off

  • Moving DOWN the hierarchy (registers → cache → main memory → hard disk → auxiliary storage): access time gets SLOWER, but capacity gets LARGER and cost per byte gets LOWER.
  • Computer users would ideally want a large amount of primary storage that costs little and allows quick access — but this genuinely isn't possible. The fastest components always cost more and have limited capacity.
  • In practice, every real system's design is a COMPROMISE between these competing factors.

Why secondary storage exists at all

  • One argument: secondary storage exists because using ONLY primary storage would be far too expensive.
  • A more accurate way to see it: long-term storage of data genuinely requires separate, DEDICATED components — it's not simply a cost-saving workaround.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the memory system and its hierarchy (completes Section 3.01).

Short answer 1
What are the two main uses of a computer system, and what is the KEY performance concern for each?
Reveal answer

Running programs (concern: processor and access speed) and storing data (concern: capacity and cost).

Short answer 2
Name the two alternative ways of categorising storage components described in this lesson.
Reveal answer

Memory vs (file) store; OR primary storage vs secondary storage.

Fill in the blank 3
Moving down the memory hierarchy from registers to auxiliary storage, access time gets ______ but capacity gets ______.
Reveal answer

Slower; larger (and cost per byte falls).

Spot the error 4
A student says: "In theory we could just build a huge amount of super-fast primary storage and skip secondary storage entirely — it's only cost holding us back." What's the more accurate view given in this lesson?
Reveal answer

It's more sensible to recognise that long-term storage of data genuinely requires separate DEDICATED components — this isn't purely a cost compromise that better technology could one day eliminate.

Applied / scenario 5
Why has processor speed increasing over the decades NOT automatically translated into a proportional real-world performance increase for running programs?
Reveal answer

Because the time taken for the processor to ACCESS the stored program also needs to keep pace — and access speed improvements haven't fully kept up with processor speed improvements, creating a bottleneck.

Short answer 6
Why does access speed matter far less for storing data than for running programs?
Reveal answer

For storing data, the major issues are capacity and cost — the processor isn't constantly waiting on that data the way it is for a running program's instructions.
