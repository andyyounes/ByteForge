23.09 Dictionaries
Key-value pairs, built on top of a hash table for direct-access lookup. Completes Chapter 23.
Theory

The dictionary ADT

  • A real-world dictionary is a collection of KEY-VALUE pairs — you look up a KEY (e.g. an English word) to find its VALUE (e.g. the French translation).
  • An ADT dictionary in computer science is IMPLEMENTED using a hash table — so a value can be found using DIRECT ACCESS, rather than a slow search.
  • Python has a BUILT-IN dictionary type, with its hashing function handled internally by Python. In VB and Pascal, you'd need to implement your own.

Python dictionaries in practice

# Python EnglishFrench = {} # empty dictionary EnglishFrench["book"] = "livre" # add a key-value pair EnglishFrench["pen"] = "stylo" print(EnglishFrench["book"]) # access a value → "livre" # alternative way to set up a dictionary directly ComputingTerms = {"Boolean": "can be TRUE or FALSE", "Bit": "0 or 1"} print(ComputingTerms["Bit"])

Implementing a dictionary from scratch (pseudocode)

TYPE DictionaryEntry DECLARE Key : STRING DECLARE Value : STRING ENDTYPE DECLARE EnglishFrench[0:999] OF DictionaryEntry // empty dictionary
  • Inserting a key-value pair and looking up a value both use the SAME hashing approach as Section 23.08 — the dictionary is essentially "a hash table where each stored record is a key-value pair", rather than a novel structure of its own.

Chapter 23 summary

  • Computational thinking = abstraction + decomposition + data modelling + pattern recognition + algorithm design.
  • Standard algorithms: bubble sort, insertion sort, linear search, binary search.
  • ADTs covered: stack (LIFO), queue (FIFO, often circular), linked list (node + pointer, with a free list), binary tree (ordered, at most 2 children per node), hash table (address calculated from key, collisions resolved e.g. via open hashing), and dictionary (key-value pairs, built from a hash table).
  • Every ADT needs: create, find, insert, delete, and systematically access all elements.
Practice — Test Yourself

These questions cover dictionaries and draw together the whole of Chapter 23 (completes Section 23.09 and Chapter 23).

Short answer 1
What underlying data structure is a dictionary ADT typically implemented from?
Reveal answer

A hash table.

Short answer 2
In Python, who determines the hashing function used by the built-in dictionary type?
Reveal answer

Python itself — it's handled internally by the language, unlike VB or Pascal where the programmer must implement their own.

Fill in the blank 3
A dictionary is a collection of ______-______ pairs.
Reveal answer

Key; value.

Spot the error 4
A student says dictionaries are "a completely different kind of structure from hash tables, with nothing in common". What's the misunderstanding?
Reveal answer

A dictionary ADT is BUILT FROM a hash table — the "value" part of each key-value pair is simply the data stored at the hashed address for that key. They aren't unrelated; the dictionary is essentially a specific application of hash table techniques.

Applied / scenario 5
Write Python code to create an empty dictionary called Capitals, then add the pair "France" → "Paris".
Reveal answer

Capitals = {}
Capitals["France"] = "Paris"

Short answer 6
Why is a dictionary implemented via a hash table rather than, say, a plain linear list of key-value pairs?
Reveal answer

A hash table gives DIRECT ACCESS — calculating the address from the key straight away — while a linear list would require searching through potentially every pair to find a match, which is much slower.
