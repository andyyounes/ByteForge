17.04 The TCP/IP Protocol Suite
A stack of layered protocols — how TCP and IP work together to deliver a message across the Internet.
Theory

Protocols and protocol suites

  • A PROTOCOL is a set of rules for data transmission, agreed by sender and receiver — from the simplest (a voltage level = bit 1) to the complex (the exact byte format of a packet header).
  • A PROTOCOL SUITE is a collection of related protocols. TCP/IP is the dominant suite for the Internet.

The layered stack model

  • Each layer (except the physical layer) is SOFTWARE running on an end-system or router.
  • Each layer's software can send and receive data in FULL-DUPLEX mode to/from the ADJACENT layer.
  • An upper-layer protocol is SERVICED by the layers below it — this lets an application behave as though it has a DIRECT connection to an application on a different end-system, even though the actual data passes through many layers and devices.
  • TCP/IP itself only operates at the TOP THREE layers (application, transport, network); the lower layers use a DIFFERENT suite, such as Ethernet. A router has NO awareness of the top two layers.
LayerExample protocols
ApplicationHTTP, SMTP, DNS, FTP, POP3
TransportTCP, UDP, SCTP
NetworkIP, IGMP, ICMP, ARP

TCP (Transmission Control Protocol)

  • Receives the "message" from the application layer and takes responsibility for its SAFE DELIVERY — splitting it into enough packets, each with a header plus the user data.
  • Includes a PORT NUMBER in the header identifying which application-layer protocol should receive the response (e.g. port 80 for HTTP). TCP itself is NOT concerned with the receiving end-system's address — that's IP's job.
  • Includes a SEQUENCE NUMBER for multi-packet transmissions, so the data can be correctly reassembled.
  • TCP is CONNECTION-ORIENTED: only the first packet is initially sent; once the connection is established (acknowledged), the rest follow, with missing packets identified and re-sent as needed.

IP (Internet Protocol)

  • Ensures correct ROUTING across the Internet — takes the packet from the transport layer and adds its OWN header containing sender and receiver IP addresses.
  • Uses DNS to resolve a URL into an IP address when needed (Chapter 2).
  • The resulting IP packet ("datagram") is passed to the data-link layer, which assembles it into a "frame". Once handed off, IP has NO further duty for that packet.
  • IP is CONNECTIONLESS — it simply passes packets along without tracking acknowledgements itself; that's TCP's responsibility.

The router's role in this stack

  • A frame arriving at a router has its datagram content handed back to IP, which uses the router's ROUTING TABLE to choose the NEXT target host.
  • No router can hold a GLOBAL routing table — the Internet is far too large — so routing decisions are made incrementally, hop by hop.
  • A SWITCH, by contrast, forwards a frame WITHOUT making any routing decision — it operates only at the data-link layer, not the network layer.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the TCP/IP layered stack, TCP, IP, and the router's role (completes Section 17.04).

Short answer 1
What is the division of responsibility between TCP and IP?
Reveal answer

TCP is responsible for the SAFE DELIVERY of the message — splitting it into packets, tracking sequence, and re-sending missing packets. IP is responsible for ROUTING each packet across the Internet using sender/receiver IP addresses.

Short answer 2
Why can no router hold a complete, global routing table?
Reveal answer

The Internet is far too large and complex — routing decisions are instead made incrementally, one hop at a time, using a partial routing table appropriate to that router.

Fill in the blank 3
A router has no awareness of the ______ and ______ layers — it only sees the network layer and below.
Reveal answer

Application; transport.

Spot the error 4
A student says a switch makes routing decisions just like a router, only "smaller-scale". What's wrong?
Reveal answer

A switch operates at the DATA-LINK layer and forwards frames WITHOUT making any routing decision — it has no concept of IP addressing or routing tables at all. Only a router (operating at the network layer) makes genuine routing decisions.

Applied / scenario 5
Why does TCP include a port number in its header, given that IP already handles addressing?
Reveal answer

IP's address only gets a packet to the correct END-SYSTEM — the port number is needed additionally to identify which specific APPLICATION-layer protocol on that end-system (e.g. a web server vs. a mail server) should receive the data.

Short answer 6
Is IP connection-oriented or connectionless?
Reveal answer

Connectionless — it simply forwards packets without tracking whether they were acknowledged; that responsibility belongs to TCP.
