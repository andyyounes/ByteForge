19.02 Pipelining
Overlapping instructions to make a processor much faster — and the interrupt-handling problem it creates.
Theory

The idea: split the fetch-decode-execute cycle into stages

  • Pipelining is INSTRUCTION-LEVEL parallelism — a form of parallel processing applied specifically to instruction execution.
  • A common breakdown uses FIVE stages: Instruction Fetch (IF), Instruction Decode (ID), Operand Fetch (OF), Instruction Execute (IE), result Write Back (WB).
  • For pipelining to work, the processor needs FIVE INDEPENDENT units, each handling one stage — and crucially, each unit needs access to its OWN set of registers. This is exactly why RISC processors need multiple register sets.

  • "1.1" means instruction 1, stage 1 (IF), etc. Initially only the FIRST stage of instruction 1 is active.
  • By cycle 6, instruction 1 has fully LEFT the pipeline, and instruction 6 has just ENTERED — from then on, the pipeline is handling FIVE stages of FIVE DIFFERENT instructions simultaneously.
  • Once fully underway, ONE complete instruction finishes at EVERY clock cycle — without the pipeline, processing would take FIVE TIMES longer.

The interrupt-handling problem

  • In a non-pipelined processor (Chapter 5), instructions are handled sequentially — an interrupt has a clean, single point to intervene.
  • In a pipelined processor, up to FIVE instructions may be mid-execution at once when an interrupt occurs.
  • OPTION 1: erase the pipeline contents for the four LATEST instructions to have entered, then handle the interrupt normally for the one remaining (oldest) instruction.
  • OPTION 2: give each processing unit its OWN program counter register, so the CURRENT data for every in-flight instruction can be preserved while the interrupt is handled.

A related hazard — data dependency

  • Consider: ADD R1,R2,R3 then ADD R5,R1,R4 — the second instruction needs R1's NEW value, but in a pipeline, the second instruction may try to READ R1 before the first instruction has finished WRITING to it.
  • This is a genuine hazard that pipelined processor designs must specifically guard against (e.g. via forwarding/stalling techniques) — the coursebook raises it as a discussion point rather than fully solving it here.
Practice — Test Yourself

These questions only cover what THIS subsection taught — pipelining and its interrupt-handling challenge (part of Section 19.02).

Short answer 1
Why does pipelining require multiple independent register sets?
Reveal answer

Because each of the five pipeline stages is handled by its own independent processing unit, and each unit needs access to its own set of registers to work on its instruction without conflicting with the others.

Short answer 2
Once a 5-stage pipeline is fully underway, how many instructions complete per clock cycle?
Reveal answer

One — even though five different instructions are being processed simultaneously (each at a different stage), exactly one instruction fully completes at every clock cycle.

Fill in the blank 3
Without pipelining, processing the same instructions would take ______ times longer, for a 5-stage pipeline.
Reveal answer

Five.

Spot the error 4
A student says pipelining means five instructions are each fully finished at the same instant, every fifth cycle. What's actually happening?
Reveal answer

Once the pipeline is full, ONE instruction completes EVERY single cycle (not five at once every fifth cycle) — the five instructions in flight at any moment are each at a DIFFERENT stage, staggered so completions happen continuously, one per cycle.

Applied / scenario 5
Describe the two options a pipelined processor has for handling an interrupt correctly.
Reveal answer

Option 1: erase the pipeline contents of the four most-recently-entered instructions and handle the interrupt for the one remaining. Option 2: give each processing unit its own program counter register, preserving current data for ALL in-flight instructions during the interrupt.

Short answer 6
In the ADD R1,R2,R3 / ADD R5,R1,R4 example, what specifically could go wrong in a pipelined processor?
Reveal answer

The second instruction might read R1's OLD value before the first instruction has finished writing R1's NEW value — because the two instructions overlap in the pipeline rather than running one fully after the other.
