16.03 Converting to Floating-Point, and Its Problems
Denary-to-binary conversion, rounding errors, overflow, and underflow. Completes Chapter 16.
Theory

Converting a positive denary real number — the method

  • 1. Convert the whole-number part to binary (Chapter 1 method).
  • 2. Add the sign bit (0 for positive).
  • 3. Convert the fractional part to binary (the "multiply by 2, record whole-number parts" method).
  • 4. Combine the two parts, with the exponent temporarily set to zero.
  • 5. Shift the binary point and adjust the exponent to reach the NORMALISED form.

Worked example — converting 8.75

1. 8 converts to 1000; adding the sign bit gives 01000 2. .75 is exactly .11 in binary 3. Combined: 01000.11 (exponent = 0) 4. Shift the binary point: 0.100011 (exponent = denary 4) 5. With 10 mantissa bits and 4 exponent bits: mantissa = 0100011000, exponent = 0100

Worked example — converting 8.63 (an inexact fraction)

  • Most denary fractional parts do NOT convert to an exact binary value — binary fractions represent halves, quarters, eighths, etc. Of the values .1 through .9, only .5 converts exactly.
  • The "multiply by 2" method for .63: .63×2=1.26 → 1; .26×2=.52 → 0; .52×2=1.04 → 1; .04×2=.08 → 0 ...
  • Since this keeps producing near-zero results, the process is stopped, APPROXIMATING .63 as .625 — an unavoidable rounding step baked into the conversion.

Rounding errors in extended calculations

  • Because converting a real value to binary almost always introduces some approximation, ANY calculation using floating-point numbers carries a small rounding error.
  • In programs with REPEATED calculations (e.g. weather forecasting, economic modelling), these small errors can ACCUMULATE and become significant.
  • The fix: use more mantissa bits, via "double precision" or "quadruple precision" modes offered by programming languages — more bits reduces (but never fully eliminates) the rounding error per calculation.

Overflow and underflow

  • OVERFLOW: a calculation produces a value LARGER than the representation's maximum magnitude (e.g. exceeding 112 in the 8-bit example from the previous lesson).
  • UNDERFLOW: dividing a very small number by a number greater than 1 can produce a result SMALLER in magnitude than the smallest value the representation can store.
  • Depending on the situation, a program facing underflow might simply convert the tiny result to zero and continue — but this carries its own risk of silently losing meaningful precision.
Overflow: a calculated value exceeds the maximum magnitude a representation can store.
Underflow: a calculated value is smaller in magnitude than the smallest value a representation can store.

Chapter 16 summary

  • Non-composite user-defined types: enumerated, pointer. Composite: record, set, class.
  • File organisation: serial, sequential, or direct access (hashed).
  • Floating-point trades some precision for far greater range compared to fixed-point.
  • Normalisation maximises precision by using the largest possible magnitude for the mantissa.
  • Floating-point values are rarely an EXACT match for their denary equivalent, due to unavoidable rounding during conversion — and repeated calculations can accumulate this error, or trigger overflow/underflow.
Practice — Test Yourself

These questions cover converting denary to floating-point, rounding errors, overflow, and underflow (completes Section 16.03 and Chapter 16).

Short answer 1
Why does converting 0.63 to binary require an approximation, but converting 0.5 does not?
Reveal answer

0.5 is exactly representable as a binary fraction (½), but 0.63 is not a sum of exact binary fractions (halves, quarters, eighths...) — so its binary representation must be truncated at some point, introducing an approximation.

Short answer 2
What is the difference between overflow and underflow?
Reveal answer

Overflow occurs when a value is too LARGE in magnitude for the representation to store. Underflow occurs when a value is too SMALL in magnitude (closer to zero than the smallest representable value) to be stored accurately.

Fill in the blank 3
Using more bits for the mantissa, via "double" or "quadruple" precision, reduces (but does not eliminate) ______ errors that accumulate over repeated calculations.
Reveal answer

Rounding.

Spot the error 4
A programmer assumes that because a program's floating-point calculations look correct on the first few test runs, rounding errors aren't a concern for their weather-forecasting simulation. Why is this risky?
Reveal answer

Weather forecasting involves REPEATED calculations over a long simulation — small rounding errors from each step can ACCUMULATE over many iterations, becoming significant even if any single calculation looks negligible in isolation.

Applied / scenario 5
A program divides a very small floating-point number by a number greater than 1, and the result silently becomes zero. What error condition caused this, and what's the risk of the program just continuing anyway?
Reveal answer

Underflow — the true result was smaller in magnitude than the representation could store. Continuing by treating it as zero risks losing meaningful precision in later calculations that depend on that value, potentially producing an incorrect final result without any visible crash.

Short answer 6
List, in order, the five steps for converting a positive denary real number into normalised floating-point binary.
Reveal answer

1) Convert the whole-number part to binary. 2) Add the 0 sign bit. 3) Convert the fractional part to binary. 4) Combine both parts with exponent zero. 5) Adjust the binary point's position and the exponent to reach normalised form.
