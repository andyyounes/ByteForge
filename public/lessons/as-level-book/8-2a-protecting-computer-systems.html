8.02 Security Measures for Protecting Computer Systems
Hot sites, authentication, firewalls, and why "just install antivirus" was never the whole story.
Key Terms
Authentication
Verification of a user's identity.
Hot site
A full, ready-to-go replacement system kept remote from the original, so it survives natural disasters affecting the original site.
Theory

Two primary aims of system security — not just protecting data

  • Ensure SYSTEM FUNCTIONALITY.
  • Ensure only AUTHORISED users have access.

Four categories of threat

  • Internal mismanagement.
  • Natural disasters.
  • Unauthorised intrusion by an individual.
  • Malicious software entering the system.

Disaster recovery — contingency planning and hot sites

  • For large installations, continuity of operation is VITAL — measures must keep the system functional, or at least guarantee resumption within a very short time.
  • This falls under disaster recovery CONTINGENCY PLANNING, based on a RISK ASSESSMENT, with provision for an alternative system.
  • A "hot site" — a full always-ready replacement system — must be REMOTE from the original, specifically so it can survive natural disasters (earthquake, flood) that might destroy the original site.
  • For a major hardware/software update: traditionally done over a weekend when no service was needed. In the modern era of globally-available, never-closed systems, organisations may need the ORIGINAL and REPLACEMENT running IN PARALLEL for a period, to ensure continuity.

User accounts and authentication

  • Even a single-user PC should have a user account — essential for any multi-user (timesharing) system.
  • The main security feature of a user account is AUTHENTICATION, normally via a password. For effectiveness, a password needs many characters, ideally drawing from a wide variety of ASCII characters.
  • Alternative/additional authentication methods: BIOMETRIC (fingerprint, face, eye) and SECURITY TOKENS (hardware, or a software equivalent requiring further input after the password). Normal practice COMBINES one of these with the password system.
  • General good practice: don't leave a computer switched on unattended; don't let others observe you accessing it; don't write down your access details.

Beyond login — portable devices and the Internet

  • Portable storage devices attached by users can carry viruses — the safest policy is BANNING their use, though this isn't always practical if business processes require data portability.
  • Internet connection is a "virtually unavoidable" threat — incoming transmissions may carry malicious software, AND sensitive data could be exported OUT to another system.

Firewalls — the primary defence

  • Ideally a HARDWARE firewall — like an airport security gate, nothing passes without inspection.
  • Alternatively, SOFTWARE-based — the transmission must enter the system first, but is inspected immediately.
  • A firewall might focus purely on ADDRESSES in a transmission, or additionally examine the DATA itself for anything inappropriate.
  • For email specifically, sender authentication is addressed by requiring a DIGITAL CERTIFICATE attached to the email.

Access restriction isn't the whole solution — ongoing monitoring is needed too

  • A virus checker — regular system scans to detect and remove/deactivate viruses.
  • An intrusion detection system — takes an audit record of system use as input, and looks for ANOMALOUS use.
  • Attackers' methods keep becoming more sophisticated — defences must be continually improved to keep up.
Practice — Test Yourself

These questions only cover what THIS subsection taught — protecting computer systems (completes Section 8.02).

Short answer 1
Why must a "hot site" be located remotely from the original system?
Reveal answer

So it can survive natural disasters (like earthquake or flood) that might destroy or disable the original site — a hot site next door wouldn't help with that specific threat.

Short answer 2
Why might a modern organisation need its old and new systems running in PARALLEL during a major update, unlike in the past?
Reveal answer

Modern globally-available systems mean a company is never "closed" — there's no safe weekend window to take the system offline for testing, so continuity of service requires both systems running together during the transition.

Fill in the blank 3
The two primary aims of system security are ensuring system ______, and ensuring only ______ users have access.
Reveal answer

Functionality; authorised.

Spot the error 4
A student says: "A firewall guarantees that no malicious software can ever enter a system." What does this lesson imply is wrong with that claim?
Reveal answer

Security measures restricting access do NOT guarantee removal of all threats — this is exactly why the lesson also requires ONGOING monitoring (virus checkers, intrusion detection systems) running alongside the firewall, and notes that attacker methods keep evolving to be more sophisticated.

Applied / scenario 5
A company wants extra confidence in the identity of email senders before trusting an incoming email. What solution does this lesson describe?
Reveal answer

Insisting the sender attaches a digital certificate to the email.

Short answer 6
What input does an intrusion detection system use, and what is it looking for?
Reveal answer

It takes an audit record of system use as input, and looks for anomalous (unusual/suspicious) use.
