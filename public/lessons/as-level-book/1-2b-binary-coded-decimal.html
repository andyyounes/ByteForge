1.02 Binary Coded Decimal (BCD)
When storing denary digits directly beats storing a "real" binary number — completes Section 1.02.
Key Terms
BCD
Binary Coded Decimal — each individual denary DIGIT (0-9) stored as its own 4-bit binary code.
Nibble
4 bits — half a byte. Exactly enough to encode one denary digit (0-9) in BCD.
Packed BCD
Storing TWO BCD digits per byte (one per nibble), instead of one digit per byte.
Theory

BCD is genuinely different from normal binary integer coding

  • A normal binary integer treats the WHOLE number as one value (e.g. denary 246 → binary 11110110, one continuous number).
  • BCD instead encodes EACH denary digit SEPARATELY as its own 4-bit code — denary 246 in BCD is three separate nibbles: 0010 (2), 0100 (4), 0110 (6), simply placed next to each other.
  • A 4-bit nibble can represent 16 different values, but BCD only ever uses 10 of them (0000-1001, for digits 0-9) — the remaining 6 combinations (1010-1111) are simply never used.

One digit per byte vs. packed BCD

  • ONE BCD digit per byte wastes 4 bits per byte (half the byte's capacity), but is simpler to work with.
  • PACKED BCD stores TWO digits per byte (one per nibble), using space far more efficiently — at the cost of slightly more complex logic to extract each digit.

Why BCD is actually used, despite wasting space compared to plain binary

  • Obvious use: displaying denary digits directly — e.g. a calculator's screen or a digital clock, where each digit needs to be shown individually anyway.
  • Less obvious use: representing CURRENCY values precisely. A value like $300.25 is a fixed-point decimal number — storing it as a "real" (floating-point) number can introduce small rounding errors (covered further in Chapter 16), which is completely unacceptable for money.
  • Storing each denary digit as its own BCD code avoids this rounding problem entirely, since no conversion between binary and decimal fractions ever needs to happen.
Why BCD arithmetic needs special handling

Adding two BCD-encoded values isn't as simple as adding the raw binary bytes — a normal binary ADD can produce a result like 1010 (denary 10) inside a single nibble, which is NOT a valid single BCD digit (valid BCD digits only go up to 1001/9). When this happens, a correction step is needed to "carry" into the next digit, similar to how carrying works in ordinary denary addition by hand.

Practice — Test Yourself

These questions only cover what THIS subsection taught — Binary Coded Decimal (completes Section 1.02).

Short answer 1
How is BCD fundamentally different from encoding a number as one continuous binary value?
Reveal answer

BCD encodes EACH denary digit separately as its own 4-bit (nibble) code, rather than treating the whole number as one continuous binary value.

Short answer 2
Out of the 16 possible 4-bit combinations, how many does BCD actually use, and why?
Reveal answer

Only 10 (0000 through 1001) — because there are only 10 denary digits (0-9) to represent. The remaining 6 combinations (1010-1111) are never used in BCD.

Fill in the blank pseudocode 3
Complete: packed BCD stores ______ digit(s) per byte; one-digit-per-byte BCD stores ______ digit(s) per byte.
Reveal answer

Packed BCD stores TWO digits per byte; one-digit-per-byte BCD stores ONE digit per byte.

Spot the error 4
A student encodes denary digit 12 as a single BCD nibble, "1100". What's wrong with this?
Reveal answer

12 is not a single denary DIGIT (it's two digits, "1" and "2") — a single BCD nibble can only ever represent one digit, 0-9. "1100" is also outside the valid BCD range (it equals denary 12 in plain binary, but 1010-1111 are never valid BCD codes) — 12 would need TWO separate nibbles: 0001 (1) and 0010 (2).

Applied / scenario 5
Write the packed BCD representation of the denary number 47 (one byte, two nibbles).
Reveal answer

4 → 0100, 7 → 0111. Packed into one byte: 01000111.

Short answer 6
Why is BCD preferred over floating-point (real number) representation for storing currency values?
Reveal answer

Floating-point representation can introduce small rounding errors when representing decimal fractions — completely unacceptable for money. BCD stores each denary digit exactly, with no binary-fraction rounding involved at all.
