1.03 Internal Coding of Text: ASCII & Unicode
A unique binary code for every character — and why one scheme wasn't enough forever.
Key Terms
Character code
A coding scheme giving a unique binary code to each distinct character.
ASCII
American Standard Code for Information Interchange — a 7-bit character code, the longest-standing scheme.
Unicode
A character coding scheme aiming to represent EVERY possible text, in every language.
Code point
Unicode's term for a single character's code, e.g. U+0041 for 'A'.
Theory

ASCII — a 7-bit standard, stored in a byte

  • ASCII is a 7-bit code — 2⁷ = 128 distinct codes — with the most significant bit of the byte set to 0 and the remaining 7 bits holding the actual character code.
  • Most codes represent PRINTING characters; the first few (0-31ish) are non-printing CONTROL characters, originally for data transmission/terminal use — these have very limited use in modern computing.
  • ASCII covers upper- and lower-case letters, punctuation, digits, and arithmetic symbols — but these NUMBER codes are purely for STORING/DISPLAYING text — completely separate from the binary coding schemes used for actual numeric values in calculations.

Two genuinely useful properties of ASCII's design

  • Sequential codes: the codes for digits (and for letters) are in ORDER — adding 1 to the code for "7" gives the code for "8". This means simple arithmetic can move between adjacent characters.
  • Case conversion via one bit: an upper-case letter's code differs from its lower-case equivalent ONLY in bit 5 — e.g. 'A' = 1000001, 'a' = 1100001. Converting case is as simple as flipping ONE specific bit.

Unicode — why ASCII eventually wasn't enough

  • ASCII can only represent the English alphabet plus basic symbols — completely inadequate for representing every language in the world.
  • Unicode was designed with backward compatibility built in: the FIRST 128 Unicode codes are IDENTICAL to ASCII — any pure ASCII text is automatically valid Unicode text too.
  • Unicode calls a character's code a "code point" — written like U+0041 for 'A' (0041 is the HEXADECIMAL code, using two bytes' worth of hex digits).
  • Once a Unicode code point is assigned, it's NEVER changed — this is a deliberate design guarantee, so old Unicode text never becomes invalid.

Avoiding ambiguity between 1-byte and multi-byte codes

  • An ASCII character's most significant bit is always 0 (since ASCII only ever needs 7 bits) — Unicode exploits this: a genuine 2-byte code is specifically formatted so it can NEVER be confused with a 1-byte ASCII code.
  • A 2-byte code follows the pattern 11?????? 10?????? — starting bits that no valid single ASCII byte could ever produce, so a reader can always tell whether it's looking at one ASCII byte or the start of a longer code.
Practice — Test Yourself

These questions only cover what THIS subsection taught — ASCII and Unicode character coding.

Short answer 1
How many distinct codes does a 7-bit ASCII scheme provide?
Reveal answer

2⁷ = 128 distinct codes.

Short answer 2
Why does Unicode make the first 128 code points identical to ASCII?
Reveal answer

So that any existing ASCII text is automatically valid Unicode text too, with no conversion needed — genuine backward compatibility.

Fill in the blank pseudocode 3
ASCII 'A' is 1000001 and 'a' is 1100001. These differ only in bit ______.
Reveal answer

Bit 5.

Spot the error 4
A student claims the ASCII code for the character "7" can be used directly in a mathematical calculation, since it's "just a number". Why is this wrong?
Reveal answer

ASCII number codes exist purely to STORE/DISPLAY the character "7" as text — they are entirely separate from the binary coding schemes used for genuine numeric values in calculations. The ASCII code for "7" is not the same as the integer value 7 stored as a plain binary number.

Applied / scenario 5
Using the sequential-codes property, if the ASCII code for "5" is 0110101, what is the ASCII code for "6"?
Reveal answer

0110110 — adding 1 to the binary code for "5" gives the code for "6", since digit codes are sequential.

Short answer 6
Why can a Unicode 2-byte code never be confused with a plain single ASCII byte?
Reveal answer

Every ASCII byte's most significant bit is always 0. A genuine Unicode multi-byte code is deliberately formatted to start with bits (like 11??????) that no ASCII byte could ever produce, so the two can always be told apart.
