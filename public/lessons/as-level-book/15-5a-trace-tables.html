15.05 Dry-Running an Algorithm
Trace tables — checking an algorithm works by hand, one line at a time, without running any code.
Theory

What a dry-run is

  • A DRY-RUN checks an algorithm's execution by recording variable values in a TRACE TABLE, WITHOUT actually running it on a computer.
  • A trace table has one column for each variable (and often each condition) used in the algorithm.
Dry-run: checking the execution of an algorithm or program by recording variable values in a trace table.
Trace table: a table with a column for each variable that records its changing values.

The core rule: only write down what CHANGES

  • You only make an entry in a cell when an ASSIGNMENT actually occurs for that variable at that step.
  • A blank cell means the value from the previous row REMAINS unchanged — you don't need to keep repeating unchanged values.
  • Start a NEW row for each iteration of a loop (each time round the loop).

Worked example — number-guessing game

SecretNumber ← 34 INPUT "Guess a number: ", Guess NumberOfGuesses ← 1 REPEAT IF Guess = SecretNumber THEN OUTPUT "You took ", NumberOfGuesses, " guesses" ELSE IF Guess > SecretNumber THEN INPUT "Guess a smaller number: ", Guess ELSE INPUT "Guess a larger number: ", Guess ENDIF NumberOfGuesses ← NumberOfGuesses + 1 ENDIF UNTIL Guess = SecretNumber

Practice — Test Yourself

These questions only cover what THIS subsection taught — dry-running and trace tables (completes Section 15.05).

Short answer 1
What is a dry-run?
Reveal answer

Checking an algorithm's execution by recording variable values in a trace table, without actually running it on a computer.

Short answer 2
What does a blank cell in a trace table mean?
Reveal answer

That variable's value hasn't changed since the last row where it was recorded — the previous value still applies.

Fill in the blank 3
A new row in a trace table should be started for each ______ of a loop.
Reveal answer

Iteration.

Spot the error 4
A student fills in EVERY cell of a trace table on EVERY row, even repeating a value that hasn't changed since the previous row. Is this wrong?
Reveal answer

It's not strictly incorrect, but it goes against the standard convention — the coursebook convention is to leave a cell blank when the value hasn't changed, which makes it much clearer at a glance WHICH assignments actually happened at each step.

Applied / scenario 5
In the number-guessing game trace table, why does the "Guess > SecretNumber" column exist as a separate column from Guess itself?
Reveal answer

Because it records the result of a CONDITION (used to decide which branch of the algorithm runs next), not a variable's value — trace tables track both variables and important condition outcomes, since the condition determines the algorithm's path just as much as a variable does.

Short answer 6
Why is a dry-run useful even before you've typed any actual program code?
Reveal answer

It lets you verify the LOGIC of a pseudocode algorithm is correct before investing time coding it — catching design errors early, when they're cheapest to fix.
