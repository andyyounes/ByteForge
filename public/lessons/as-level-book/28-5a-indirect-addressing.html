28.05 Indirect Addressing
When the address to use is itself stored somewhere else — a worked queue implementation. Completes Chapter 28.
Theory

When is indirect addressing useful?

  • Indirect addressing helps when the memory address an instruction should use CHANGES during program execution.
  • Two classic uses: subroutines with parameters passed BY REFERENCE (beyond this book's scope), and implementing a POINTER VARIABLE.

Worked example — a simple queue using pointers

  • Structured English design:
Add a character to the queue (JOINQ): 1. Store the contents of the accumulator at the memory location POINTED TO by the tail pointer. 2. Increment the tail pointer. Remove a character from the queue (LEAVEQ): 1. Load the contents of the memory location POINTED TO by the head pointer. 2. Increment the head pointer.

Why this NEEDS indirect addressing

  • The tail pointer's VALUE (an address) changes every time a new item joins the queue — so the instruction can't use a FIXED direct address. It must look up the CURRENT address stored in the pointer variable, then act on THAT location.
  • This is exactly what STI (store, indirect) and LDI (load, indirect) do: STI TAILPTR stores ACC's contents at the address CURRENTLY held in TAILPTR — not at TAILPTR's own location.
JOINQ: STI TAILPTR // store ACC at the address TAILPTR currently points to LDD TAILPTR INC ACC STO TAILPTR // increment the tail pointer itself LEAVEQ: LDI HEADPTR // load from the address HEADPTR currently points to OUT LDD HEADPTR INC ACC STO HEADPTR // increment the head pointer itself HEADPTR: QSTART // pointer to the start of the queue data TAILPTR: QSTART // pointer to the next free slot in the queue QSTART: // reserved memory for the queue data, currently empty
  • As values are ADDED, TAILPTR's value increases to point further along the queue. As values are REMOVED, HEADPTR's value increases to follow.
  • Note the crucial distinction: STO TAILPTR (direct) changes the POINTER's own value; STI TAILPTR (indirect) changes the DATA at the address the pointer refers to.

Chapter 28 summary

  • A value must be loaded into ACC before it can be processed — via keyboard input, immediate addressing, or a load instruction using direct/relative/indirect/indexed addressing.
  • Assignment, selection, iteration, and I/O each have reusable assembly "design patterns" built from this instruction set.
  • An address can be absolute (a fixed number) or symbolic (a label) — relative addressing (base register + offset) lets a program be loaded anywhere in memory.
  • Indirect addressing is essential whenever the target address itself can change during execution — most notably for pointer variables, as in a queue implementation.
Practice — Test Yourself

These questions cover indirect addressing and draw together the whole of Chapter 28 (completes Section 28.05 and Chapter 28).

Short answer 1
Why does implementing a queue with pointers require indirect addressing rather than direct addressing?
Reveal answer

The tail/head pointer's VALUE (the address of the next free/occupied slot) changes as items are added/removed — a fixed direct address can't follow this, but indirect addressing looks up whatever address the pointer CURRENTLY holds.

Short answer 2
What is the difference between STO TAILPTR and STI TAILPTR?
Reveal answer

STO TAILPTR (direct) stores ACC's value AT the location labelled TAILPTR — changing the pointer itself. STI TAILPTR (indirect) stores ACC's value at the address that TAILPTR currently CONTAINS — changing the queue's actual data.

Fill in the blank 3
Two classic uses of indirect addressing are ______ variables and by-reference parameter passing.
Reveal answer

Pointer.

Spot the error 4
In the JOINQ routine, a student swaps the order to increment TAILPTR BEFORE storing the new character. What goes wrong?
Reveal answer

The character would be stored at the WRONG (already-incremented) position, meaning it lands one slot further along than intended — the first "next free" slot would be skipped and left with stale/uninitialised data.

Applied / scenario 5
In LEAVEQ, why must HEADPTR be incremented AFTER the character has been loaded and output, not before?
Reveal answer

The current front-of-queue character must be read from the CURRENT head position first — incrementing beforehand would read and remove the WRONG (next) character instead of the one actually at the front.

Short answer 6
What does HEADPTR and TAILPTR both initially point to, before any items join the queue?
Reveal answer

QSTART — the start of the memory reserved for the queue's data, since the queue begins empty.
