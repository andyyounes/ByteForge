27.02 Designing Classes and Objects
Constructors, getters, and setters — the anatomy of a well-designed class.
Theory

Instantiation and the constructor

  • Creating a new object from a class is called INSTANTIATION.
  • A CONSTRUCTOR is a special method called to CREATE a new object and INITIALISE its attributes.
  • Attributes ALREADY KNOWN at creation time (e.g. a car's VehicleID and EngineSize, fixed at manufacture) are set BY the constructor.
Constructor: a special type of method that is called to create a new object and initialise its attributes.

Getters and setters

  • GETTERS retrieve (get) an attribute's current value — since attributes are PRIVATE, a getter is the only way outside code can read them.
  • SETTERS update an attribute's value AFTER instantiation — needed for any property that might change later (e.g. Registration is set only once the car is SOLD, not at manufacture).
  • Properties that get set ONLY at instantiation and never change afterward don't NEED a setter — deliberately omitting one makes the object MORE robust, since it becomes literally impossible to change something that was never meant to change.

Worked example — the Car class identifier table

IdentifierDescription
VehicleIDUnique ID assigned at time of manufacture
RegistrationAssigned after time of purchase
DateOfRegistrationDate of registration
EngineSizeAssigned at time of manufacture
PurchasePriceAssigned at time of purchase
Constructor()Creates a Car object; sets VehicleID and EngineSize
SetPurchasePrice(), SetRegistration(), SetDateOfRegistration()Setters — for values known only after purchase/registration
GetVehicleID(), GetRegistration(), GetDateOfRegistration(), GetEngineSize(), GetPurchasePrice()Getters — for reading each attribute
  • Notice: VehicleID and EngineSize have NO setters at all — they're fixed forever once the car is manufactured, matching real-world behaviour exactly.

The class diagram convention

  • A class diagram lists ATTRIBUTES (top section, with data types) and METHODS (bottom section) — by convention, ATTRIBUTES must be shown as PRIVATE and METHODS as PUBLIC.
Practice — Test Yourself

These questions only cover what THIS subsection taught — constructors, getters, and setters (completes Section 27.02).

Short answer 1
What is instantiation?
Reveal answer

The process of creating a new object from a class.

Short answer 2
Why might a property have no setter at all?
Reveal answer

Because it's only ever meant to be set once, at instantiation (by the constructor) — deliberately omitting a setter prevents it from ever being changed afterward, making the object more robust.

Fill in the blank 3
A ______ retrieves an attribute's value; a ______ updates an attribute's value after instantiation.
Reveal answer

Getter; setter.

Spot the error 4
A student's Car class adds a SetVehicleID() method, even though VehicleID is meant to be permanently fixed at manufacture. What design flaw does this introduce?
Reveal answer

Adding a setter for something that should never change removes the protection the design was supposed to provide — it becomes possible to (accidentally or otherwise) change a value that real-world logic says is permanent, weakening the class's robustness.

Applied / scenario 5
In a class diagram, how are attributes and methods conventionally marked for visibility?
Reveal answer

Attributes are shown as private; methods are shown as public.

Short answer 6
Which two attributes of the Car class are set by the constructor, since they're known at manufacture time?
Reveal answer

VehicleID and EngineSize.
