27.04 Inheritance
Writing shared code once in a base class, and specialising it in subclasses.
Theory

The core idea

  • Design a BASE CLASS (or SUPERCLASS), then DERIVE further classes (SUBCLASSES) from it.
  • The base class's code is written ONCE; subclasses automatically get its attributes and methods, PLUS their own additional ones.
Inheritance: all attributes and methods of the base class are copied to the subclass.

Worked example — a library system

  • A library lends BOOKS and CDs. Both share MANY attributes: Title, Author/Artist, unique ID, whether on loan, due date. But books ALSO need "IsRequested" (can be requested by another borrower); CDs ALSO need "Genre".
  • Design: a base class LibraryItem holding the SHARED attributes/methods, with Book and CD as SUBCLASSES adding their own specific attribute.

Abstract classes

  • A base class NEVER used to create objects DIRECTLY is an ABSTRACT class. LibraryItem is abstract — real objects are always specifically Books or CDs, never a plain "LibraryItem".
Abstract class: a base class that is never used to create objects directly.

Declaring inheritance in Python

import datetime class LibraryItem: def __init__(self, t, a, i): self.Title = t self.AuthorArtist = a self.ItemID = i self.OnLoan = False self.DueDate = datetime.date.today() def GetTitle(self): return self.Title # other Get methods go here class Book(LibraryItem): # Book INHERITS from LibraryItem def __init__(self, t, a, i): LibraryItem.__init__(self, t, a, i) # call the base class constructor self.IsRequested = False # Book's OWN extra attribute
  • In Python, class Book(LibraryItem): establishes the inheritance relationship — putting the base class name in parentheses.
  • The subclass constructor typically CALLS the base class's constructor first (to set up the shared attributes), then adds its OWN extra initialisation.
Practice — Test Yourself

These questions only cover what THIS subsection taught — inheritance, base classes, subclasses, and abstract classes (completes Section 27.04).

Short answer 1
What does a subclass automatically get from its base class?
Reveal answer

All the base class's attributes and methods — plus it can define its own additional attributes and methods on top.

Short answer 2
What is an abstract class?
Reveal answer

A base class that is never used to create objects directly — only its subclasses are actually instantiated.

Fill in the blank 3
In the library example, LibraryItem is the ______ class; Book and CD are its ______.
Reveal answer

Base (super); subclasses.

Spot the error 4
A student's Book subclass constructor sets up Title, ItemID, and IsRequested manually, duplicating the LibraryItem constructor's code, instead of calling it. What's the drawback?
Reveal answer

This duplicates code that already exists in the base class — defeating the purpose of inheritance (write shared logic once). If the base class initialisation logic ever needs to change, the duplicated code in every subclass would ALSO need updating separately, risking inconsistency.

Applied / scenario 5
Why does IsRequested belong specifically to the Book subclass, rather than the shared LibraryItem base class?
Reveal answer

Only books, not CDs, can be requested by another borrower in this system's design — it's an attribute specific to ONE subclass's behaviour, not something shared by every library item.

Short answer 6
In Python, how is the inheritance relationship between a subclass and its base class declared?
Reveal answer

By putting the base class name in parentheses after the subclass name: class Book(LibraryItem):.
