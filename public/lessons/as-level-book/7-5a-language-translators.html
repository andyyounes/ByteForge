7.05 Language Translators
Two-pass assemblers, the real step-by-step difference between a compiler and an interpreter, and why Java does something different again. Completes Chapter 7.
Key Terms
Two-pass assembler
An assembler that processes the source twice: pass 1 builds symbol/literal tables, pass 2 generates object code.
Java Byte Code
The intermediate code produced by compiling Java, run by interpretation inside a Java Virtual Machine.
Theory

The two-pass assembler

  • A two-pass structure isn't essential, but it clearly separates the two stages needed for translation.
  • PASS 1: every assembly-language "helper" feature (from 6.02) is removed or acted on — remove comments; build a SYMBOL TABLE (binary codes for symbolic names/labels); build a LITERAL TABLE for any constants used; EXPAND macros; identify system calls and subroutines used.
  • PASS 2 (only if no errors found): generate the OBJECT CODE — this involves replacing symbolic addresses with ABSOLUTE addresses.
  • Object code is NOT executable on its own — a LINKER makes the program's object code and any associated procedures' object code mutually consistent in memory; a LOADER (or the loader part of a link-loader) then actually transfers the result into memory, making any final address adjustments.

Interpreter — step by step

  1. Interpreter, source code file, AND the program's data are all made available.
  2. Interpreter begins execution.
  3. First line of source code is read.
  4. The line is analysed.
  5. If an error is found: reported, and execution HALTS immediately.
  6. If no error: the line is converted to intermediate code.
  7. The interpreter uses this intermediate code to EXECUTE the action right away.
  8. Next line is read; steps 4-8 repeat.

Compiler — step by step

  1. Compiler and source code file are made available — NO data is needed yet.
  2. Compiler begins execution.
  3. First line of source code is read.
  4. The line is analysed.
  5. If an error is found: it's RECORDED (not halted).
  6. If no error: converted to intermediate code.
  7. Next line read; steps 4-7 repeat.
  8. Once the WHOLE source has been processed: if no errors anywhere, the full intermediate code becomes OBJECT code; if any errors were found, a list is output and NO object code is produced.
  • Execution can only begin once compilation shows NO errors — either automatically (if data is ready) or later, with the object code stored and run with no further involvement from the compiler.

The crucial difference in HOW errors are handled

  • An interpreter stops IMMEDIATELY the moment it hits an error — line by line, live.
  • A compiler keeps going, RECORDING each error, and only reports the full list at the very END, after processing the entire source.

A constraint that applies to BOTH

  • Whichever is used, a program can only run on a computer whose PROCESSOR the interpreter/compiler was specifically written for.

Java — a genuinely different philosophy

  • Every different type of computer needs its OWN Java Virtual Machine (JVM) created for it.
  • A Java program is first COMPILED into "Java Byte Code" — an intermediate form, not final machine code.
  • When run, this Byte Code is INTERPRETED by the JVM.
  • Because the Byte Code itself is the same everywhere, it can be transferred to ANY computer with a JVM installed — combining a compile step with the portability of interpretation.
Practice — Test Yourself

These questions only cover what THIS subsection taught — language translators, assemblers, compilers/interpreters, and Java (completes Section 7.05 and Chapter 7).

Short answer 1
What happens in PASS 1 of a two-pass assembler?
Reveal answer

Comments are removed, a symbol table and literal table are built, macros are expanded, and system calls/subroutines are identified — everything except generating the final object code.

Short answer 2
If an interpreter finds an error on line 5 of a source file, what happens immediately?
Reveal answer

The error is reported and the interpreter HALTS execution right there — it doesn't continue to later lines.

Fill in the blank 3
A compiler only produces object code if ______ errors are found across the whole source file.
Reveal answer

No (zero).

Spot the error 4
A student says: "An interpreter is always strictly better for a programmer because it finds ALL errors in a program before it finishes running." What's the flaw in this claim?
Reveal answer

An interpreter only analyses lines it actually EXECUTES during a given run — parts of the code containing syntax errors that are never REACHED during that particular execution won't be discovered until later (or never), unlike a compiler which analyses the entire source regardless of execution path.

Applied / scenario 5
A software company wants to distribute a finished, error-free program to thousands of customers WITHOUT exposing its source code. Should they distribute it compiled or interpreted, and why?
Reveal answer

Compiled — a compiler produces an executable object code file that can be distributed without the source code ever being shared. An interpreted program would require sending the source code to every user.

Short answer 6
How does Java's approach let the SAME compiled program run on genuinely different types of computer?
Reveal answer

Java compiles to Java Byte Code (an intermediate form, the same regardless of the target machine), which is then interpreted by a Java Virtual Machine written specifically for each type of computer — the Byte Code itself doesn't need to change.
