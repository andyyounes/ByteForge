7.02 Operating System Activities
Seven overlapping categories of task, all happening constantly and mostly invisibly.
Key Terms
Process
A program that has begun execution.
Theory

No single all-embracing description — but a useful generalisation

  • Operating systems are extremely complex — no single description can fully capture what one is.
  • Generalisation: an OS provides an ENVIRONMENT within which programs beneficial to a user can run.
  • Its activities split into categories with genuine OVERLAP between them — but the classification is still worthwhile.

1. User-system interface

  • Needed so the user can get software and hardware to do something useful.
  • An OS should provide AT LEAST: a command-line interface, AND a graphical user interface (GUI).

2. Program-hardware interface

  • Programmers write software; users run it; the software uses the hardware. The OS must ensure the hardware genuinely does what the software wants.
  • Program development tools let a programmer write code WITHOUT needing to know the processor's low-level details — the OS provides the mechanism for actually EXECUTING that developed program.

3. Resource management

  • Once execution has begun, a running program is called a PROCESS. Many processes run "simultaneously" (in practice, none run to completion uninterrupted), all needing access to shared system resources.
  • Resource management aims for optimum system efficiency, mainly via: SCHEDULING of processes, and RESOLVING conflicts when two processes want the same resource.

4. Memory management

  • Memory PROTECTION — ensures one program can't use the same memory locations as another.
  • Memory ORGANISATION scheme — chosen for optimum use of limited memory (e.g. virtual memory via paging or segmentation).
  • Memory usage OPTIMISATION — deciding which processes should be in main memory at any given time, and where.

5. Device management

  • Every system has "devices" (monitor, keyboard, printer, webcam, etc.), requiring: installation of the appropriate device driver software, AND control of usage by processes.

6. File management

  • Three major features: file NAMING conventions, DIRECTORY (folder) structures, and ACCESS CONTROL mechanisms.

7. Security management, and error detection/recovery

  • Security management: provision for RECOVERY when data is lost, PREVENTION of intrusion, and ensuring data PRIVACY.
  • Errors arise from badly-written programs, inappropriate data, or malfunctioning devices. The OS should be able to INTERRUPT a running process and provide diagnostics — and in extreme cases, shut the system down in an organised way without losing data.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the categories of operating system activity (completes Section 7.02).

Short answer 1
What is a "process", as defined in this lesson?
Reveal answer

A program that has begun execution.

Short answer 2
Name the two most important aspects of resource management.
Reveal answer

Scheduling of processes, and resolving conflicts when two processes need the same resource.

Fill in the blank 3
Memory ______ ensures that one program cannot use the same memory locations as another program.
Reveal answer

Protection.

Spot the error 4
A student says: "These seven categories of OS activity are completely separate, with zero overlap between them." What does this lesson actually say?
Reveal answer

The lesson explicitly notes there IS overlap between many of these categories — the classification is still worthwhile for discussion, but the boundaries aren't perfectly clean.

Applied / scenario 5
A new webcam is plugged into a laptop and immediately starts working. Which category of OS activity is primarily responsible for this, and what two things does it require?
Reveal answer

Device management — it requires installation of the appropriate device driver software, and control of the device's usage by processes.

Short answer 6
Name the two interfaces an operating system should provide AT LEAST, according to this lesson.
Reveal answer

A command-line interface, and a graphical user interface (GUI).
