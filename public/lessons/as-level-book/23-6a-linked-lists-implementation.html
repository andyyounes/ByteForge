23.06 Linked Lists: Array Implementation
Building a linked list from an array of records, with a "free list" tracking unused nodes. Completes Section 23.06.
Theory

Storing a linked list in an array of records

  • Recall the RECORD type from Chapter 16. One record represents ONE node: its data, plus a pointer field.
  • A pointer's VALUE is simply the ARRAY INDEX of the node it points to — no real memory addresses needed.
  • When a node is inserted or deleted, only POINTER FIELDS change — nothing else in the array moves.

The free list — tracking unused slots

  • Unused array slots are linked together into a SEPARATE linked list: the FREE LIST. A FreeListPtr points to the first available slot.
  • To INSERT a node: take a slot from the FRONT of the free list, fill it with data, and update FreeListPtr to the NEXT free slot.
  • To DELETE a node: add its slot back onto the FRONT of the free list, ready to be reused.

Setting up the structure

CONSTANT NullPointer = 0 TYPE ListNode DECLARE Data : STRING DECLARE Pointer : INTEGER ENDTYPE DECLARE StartPointer : INTEGER DECLARE FreeListPtr : INTEGER DECLARE List[1:7] OF ListNode PROCEDURE InitialiseList StartPointer ← NullPointer // list starts empty FreeListPtr ← 1 // free list starts at slot 1 FOR Index ← 1 TO 6 List[Index].Pointer ← Index + 1 // link each slot to the next ENDFOR List[7].Pointer ← NullPointer // last free slot ends the free list END PROCEDURE

Inserting into an ordered linked list

PROCEDURE InsertNode(NewItem) IF FreeListPtr <> NullPointer THEN NewNodePtr ← FreeListPtr List[NewNodePtr].Data ← NewItem FreeListPtr ← List[FreeListPtr].Pointer // take next free slot ThisNodePtr ← StartPointer WHILE ThisNodePtr <> NullPointer AND List[ThisNodePtr].Data < NewItem PreviousNodePtr ← ThisNodePtr ThisNodePtr ← List[ThisNodePtr].Pointer ENDWHILE IF PreviousNodePtr = StartPointer THEN List[NewNodePtr].Pointer ← StartPointer StartPointer ← NewNodePtr ELSE List[NewNodePtr].Pointer ← List[PreviousNodePtr].Pointer List[PreviousNodePtr].Pointer ← NewNodePtr ENDIF ENDIF END PROCEDURE
  • The WHILE loop walks the list looking for the correct INSERTION POINT (keeping data in order) — very similar in structure to the traversal used for finding or deleting.

Finding, deleting, and outputting

  • FIND: walk from StartPointer, following pointers, until either the item is found OR the null pointer is reached (not found).
  • DELETE: walk to find the target node (remembering the PREVIOUS node along the way), then re-link the previous node's pointer to skip over it — and add the freed slot back onto the FREE LIST.
  • OUTPUT ALL: walk from StartPointer to the null pointer, outputting each node's data in turn — this naturally visits nodes in their LINKED order.

Stacks and queues as special-case linked lists

  • A linked-list STACK only ever adds/removes nodes at the FRONT — much simpler than the general ordered-insert case.
  • A linked-list QUEUE adds nodes at the END and removes from the FRONT — this typically needs an EXTRA pointer that always tracks the end of the queue, updated whenever a new node is added.
Practice — Test Yourself

These questions only cover what THIS subsection taught — array-based linked list implementation and the free list (completes Section 23.06).

Short answer 1
What is a pointer's actual VALUE when a linked list is implemented using an array?
Reveal answer

The array index of the node it points to.

Short answer 2
What is the purpose of the free list?
Reveal answer

To keep track of which array slots are currently UNUSED, so a new node insertion knows exactly which slot to reuse, and a deleted node's slot can be added back for future reuse.

Fill in the blank 3
A linked-list stack only ever adds and removes nodes at the ______ of the list; a linked-list queue adds at the ______ and removes from the ______.
Reveal answer

Front; end; front.

Spot the error 4
A student's DeleteNode procedure removes a node from the main list but never links its slot back into the free list. What problem does this cause over time?
Reveal answer

The array slowly "leaks" usable slots — deleted nodes' memory is never reclaimed, so eventually FreeListPtr runs out even though there are technically free slots sitting unused and unreachable.

Applied / scenario 5
Why does inserting into an ORDERED linked list need a WHILE loop, while inserting into a linked-list STACK does not?
Reveal answer

An ordered list must find the CORRECT position to preserve order, requiring traversal to compare data values. A stack always inserts at a FIXED position (the front), so no search/traversal is needed at all.

Short answer 6
Why would a linked-list queue implementation typically add an extra pointer beyond StartPointer?
Reveal answer

To track the END of the queue directly — without it, adding a new node at the end would require traversing the ENTIRE list every time just to find the last node, which is inefficient.
