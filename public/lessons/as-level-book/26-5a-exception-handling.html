26.04–26.05 Exception Handling & Programming Environments
Catching run-time errors gracefully, and choosing between a compiler and an interpreter. Completes Chapter 26.
Theory

What an exception is

  • Run-time errors (division by zero, invalid array index, opening a non-existent file) are called EXCEPTIONS.
  • Rather than letting the program CRASH, an EXCEPTION HANDLER can catch and resolve them.
TRY <statementsA> EXCEPT <statementsB> ENDTRY
  • Any run-time error during <statementsA> is caught, and <statementsB> runs instead of crashing.
  • There can be MULTIPLE EXCEPT blocks, each handling a DIFFERENT exception type.
  • An optional FINALLY block runs REGARDLESS of whether an exception occurred or not.

Two philosophies of exception handling

  • VB.NET and Delphi treat exceptions as ABNORMAL, unpredictable error situations.
  • Python is DESIGNED to use exception handling as a genuine FLOW-CONTROL structure — e.g. reading records from a file until an end-of-file EXCEPTION naturally signals "stop".

Python's specific exception types

  • IOError (file can't be opened), ImportError (module not found), ValueError (inappropriate argument value), KeyboardInterrupt (user presses Ctrl+C), EOFError (end-of-file reached), ZeroDivisionError.

Worked example — handling bad input

# Python NumberString = input("enter an integer: ") try: n = int(NumberString) print(n) except: print("This was not an integer")
  • Without this TRY/EXCEPT, a non-numeric input would crash the program with an unhandled ValueError.
  • Note: in VB.NET/Delphi IDEs, the INTEGRATED DEBUGGER must be switched OFF for exception handling to actually work as intended.

Programming environments — compilers vs. interpreters, revisited

  • In THEORY, an interpreter is ideal DURING development (test partial programs instantly, no compile wait); compiled code is better for FINAL DISTRIBUTION (source code stays hidden, runs faster, and guarantees no remaining syntax errors).
  • In PRACTICE, this choice rarely truly exists: Pascal and VB.NET MUST be compiled before execution. Python ALWAYS runs under an interpreter.
  • Internally, Python source is translated into BYTECODE, which is then executed by the Python VIRTUAL MACHINE — a hybrid approach, neither pure interpretation nor pure compilation to native machine code.

Chapter 26 summary

  • Programming paradigms: low-level, imperative, object-oriented, declarative.
  • Records are user-defined types, implemented as classes in Python, Structures in VB.NET, records in Pascal.
  • Records can be stored serially, sequentially, or via random (direct) access using a hashing function.
  • Exception handling (TRY/EXCEPT/FINALLY) avoids program crashes from run-time errors.
  • Pascal and VB.NET require compilation; Python runs via an interpreter/virtual machine using bytecode.
Practice — Test Yourself

These questions cover exception handling and programming environments, and draw together the whole of Chapter 26 (completes Sections 26.04–26.05 and Chapter 26).

Short answer 1
What is an exception?
Reveal answer

A run-time error, such as division by zero, an invalid array index, or trying to open a non-existent file.

Short answer 2
What is the difference in philosophy between how VB.NET/Delphi and Python treat exceptions?
Reveal answer

VB.NET/Delphi treat exceptions as abnormal, unpredictable error situations. Python is designed to use exception handling as a genuine flow-control mechanism (e.g. using an end-of-file exception to naturally end a reading loop).

Fill in the blank 3
A ______ block, if present, runs regardless of whether an exception occurred or not.
Reveal answer

FINALLY.

Spot the error 4
A student says "Python programs are compiled, just like Pascal, since they're translated into bytecode first". What's the nuance being missed?
Reveal answer

Python's bytecode is executed by the Python VIRTUAL MACHINE at run time — it's not compiled to native machine code the way Pascal/VB.NET are. Python still runs under an interpreter (via this bytecode layer), it's a hybrid, not a true ahead-of-time compiled language.

Applied / scenario 5
A VB.NET student adds a TRY/CATCH block but the exception still isn't caught properly during testing. What IDE setting should they check?
Reveal answer

Whether the integrated debugger is switched on — it must be switched OFF (via Debugger Options) for exception handling to behave correctly during testing.

Short answer 6
Name one advantage of compiled code over interpreted code, and one advantage of interpreted code during development.
Reveal answer

Compiled code: runs faster and is guaranteed free of syntax errors, and hides the source code from distribution. Interpreted: lets partial programs be tested instantly without waiting for a full compilation.
