26.01 Programming Paradigms
Four fundamentally different styles of programming — low-level, imperative, object-oriented, and declarative.
Theory

What a paradigm is

  • A PROGRAMMING PARADIGM is a fundamental STYLE of programming — each supports a different way of thinking about and solving problems.
  • Paradigms are NOT mutually exclusive — many languages support MORE than one paradigm.
ParadigmCore ideaExample languages
Low-levelDirect manipulation of memory addresses/registers, exploiting a specific processor's architectureAssembly language (x86, ARM, etc.)
ImperativeA sequence of explicit steps telling the computer HOW to get a resultPascal, C, BASIC
Object-orientedObjects (data + methods) interacting with one anotherPython, Java, Delphi/Object Pascal, VB.NET
DeclarativeFormal logic statements; computation is deduction from those statements, describing WHAT is wantedSQL, Prolog

Low-level programming

  • Gives direct control over memory addresses and registers, exploiting a specific PROCESSOR's architecture.
  • Each type of processor has its OWN language — though "families" of similarly-designed processors (e.g. the Intel x86 family) share similar instruction sets.

Imperative programming

  • A sequence of EXPLICIT steps executed by the processor — tells the computer HOW to reach a result, in contrast to declarative programming, which describes WHAT the result should be.
  • PROCEDURAL programming (Chapter 14) is a SUBSET of the imperative paradigm.

Object-oriented programming (OOP)

  • Based on OBJECTS interacting — objects are data structures WITH associated methods (Chapter 27).
  • Some languages were originally imperative and later EXTENDED to support OOP (Pascal → Delphi/Object Pascal; VB → VB.NET). Others (Python, Java) were designed to be object-oriented from the start.

Declarative programming

  • Programs are expressed as FORMAL LOGIC; computations are DEDUCTIONS from those logic statements, rather than a sequence of instructions.
  • SQL (Chapter 10) and Prolog (Chapter 29) are declarative languages.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the four programming paradigms (completes Section 26.01).

Short answer 1
What is the key difference between imperative and declarative programming?
Reveal answer

Imperative programming tells the computer HOW to get a result, via a sequence of explicit steps. Declarative programming describes WHAT the desired result should be, expressed as formal logic.

Short answer 2
Which paradigm is procedural programming a subset of?
Reveal answer

Imperative programming.

Fill in the blank 3
Object-oriented programming is based on ______ interacting with one another — data structures combined with their associated ______.
Reveal answer

Objects; methods.

Spot the error 4
A student says "a language can only ever support ONE programming paradigm". What's wrong?
Reveal answer

Paradigms are not mutually exclusive — many real languages support MORE than one. Python, for instance, supports imperative, procedural, AND object-oriented styles all at once.

Applied / scenario 5
A SQL query says "SELECT Name FROM Customers WHERE Balance > 1000" without specifying HOW to search the table. Which paradigm does this reflect?
Reveal answer

Declarative — the query states WHAT result is wanted, leaving the database engine to determine HOW to actually retrieve it.

Short answer 6
Why does each type of processor typically require its own distinct low-level programming language?
Reveal answer

Low-level languages directly exploit a specific processor's architecture (its registers, memory layout, instruction set) — different processor designs need different low-level instructions, though processors within the same "family" (like x86) can share a similar language.
