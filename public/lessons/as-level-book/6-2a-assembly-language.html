6.02 Assembly Language
A human-friendly stand-in for machine code — plus extra features the assembler strips out or converts.
Key Terms
Assembler
A translation program that converts assembly language into machine code.
Directive
An instruction to the assembler program itself (not converted into binary code).
Theory

Why assembly language exists at all

  • Writing a program as raw machine code instructions would be extremely time-consuming and error-prone.
  • Assembly language directly controls the processor's actions (arguably giving optimum efficiency) while being far more manageable for a human to write than raw binary.
  • Each processor has BOTH a unique machine code language AND its own corresponding assembly language.

The essence of assembly language — a direct 1:1 mapping

  • For EVERY machine code instruction, there's an equivalent assembly language instruction, made up of: a MNEMONIC (symbolic abbreviation) for the opcode, plus a character representation for the operand.
  • An assembly language program must be TRANSLATED into machine code by an assembler before the processor can run it.

Seven extra features an assembler allows a programmer to use

  • Comments — removed entirely by the assembler (never reach the final machine code).
  • Symbolic names for constants — converted to binary by the assembler.
  • Labels for addresses — also converted to binary by the assembler.
  • Macros — a sequence of instructions intended to be used MORE THAN ONCE in a program.
  • Subroutines — similarly, reusable sequences of instructions.
  • Directives — instructions TO the assembler about how to build the final executable (e.g. how memory should be used) — NOT converted into binary code themselves.
  • System calls — also instructions guiding how the assembler builds the output, not converted to binary directly.

Grouping these seven features by PURPOSE

  • Comments, symbolic names, and labels — these three exist to directly help the PROGRAMMER write and read the program more easily.
  • Macros and subroutines — exist to avoid repeating the same instruction sequence multiple times in the source.
  • Directives and system calls — exist to instruct the ASSEMBLER itself on how to construct the final machine code output (e.g. memory layout, defining files/procedures used) — they do not need converting into binary code.
Practice — Test Yourself

These questions only cover what THIS subsection taught — assembly language and the assembler (completes Section 6.02).

Short answer 1
What two components make up an assembly language instruction?
Reveal answer

A mnemonic for the opcode, and a character representation for the operand.

Short answer 2
What happens to COMMENTS when an assembly language program is assembled?
Reveal answer

They are removed entirely by the assembler — they never appear in the final machine code.

Fill in the blank 3
A ______ is an instruction to the assembler program itself, and does NOT get converted into binary code.
Reveal answer

Directive.

Spot the error 4
A student says: "Every single feature available in an assembly language program — comments, labels, macros, directives — eventually gets converted into some form of binary machine code." Is this true?
Reveal answer

No — comments are removed entirely (never converted to anything), and directives/system calls are instructions purely FOR the assembler, not converted into binary code either. Only symbolic names, labels, and the actual instructions themselves get converted to binary.

Applied / scenario 5
A programmer writes the same 5-instruction sequence at three different points in their assembly program. Which assembly language feature is specifically designed to avoid this repetition?
Reveal answer

A macro or a subroutine — both are designed to hold a sequence of instructions intended to be used more than once.

Short answer 6
What is the name of the program that translates assembly language into machine code?
Reveal answer

An assembler.
