15.04 Program Testing Using the IDE
Breakpoints, single-stepping, and variable watch windows — the debugger's toolkit.
Theory

Debugging

  • DEBUGGING is finding and correcting errors ("bugs") in a program. Most IDEs include built-in tools to make this easier than reading code line by line.
Debugging: finding and correcting errors in a program.

Breakpoints

  • A BREAKPOINT marks a specific line where execution should PAUSE, so you can inspect the program's state at that exact moment.
  • Set by clicking in the editor's margin (VB.NET, Pascal) or right-clicking the line (Python IDLE).
  • Running the program with the debugger active stops it as soon as it reaches the breakpoint — the rest of the program hasn't executed yet.

Single-stepping

  • Once paused at a breakpoint, "Step" / "Step Into" / "Trace into" buttons let you execute ONE instruction at a time.
  • This lets you watch exactly how each line changes the program's variables, pinpointing the EXACT line where behaviour diverges from what was expected.

Variable watch windows

  • A WATCH WINDOW displays the current value of chosen variables, updating live as you step through the program.
  • Set up via the Debug menu (VB.NET: Windows → Watch; Pascal/Delphi: Run → Add Watch...), typing in the variable name(s) you want to monitor.
  • This avoids having to manually print variable values just to check them — a much faster way to catch exactly where a value goes wrong.
Practice — Test Yourself

These questions only cover what THIS subsection taught — debugging, breakpoints, single-stepping, and watch windows (completes Section 15.04).

Short answer 1
What is a breakpoint, and what does it do when the program runs?
Reveal answer

A marker on a specific line of code that causes execution to PAUSE when it reaches that line, letting you inspect the program's state at that point.

Short answer 2
What does single-stepping let you do that just running the whole program doesn't?
Reveal answer

Execute ONE instruction at a time, so you can watch exactly how each individual line changes the program's variables and pinpoint precisely where things go wrong.

Fill in the blank 3
A ______ window displays the live values of chosen variables as you step through a program.
Reveal answer

Watch.

Spot the error 4
A student sets a breakpoint AFTER the line where a bug occurs, then wonders why the debugger doesn't help them see what went wrong. What's the issue?
Reveal answer

By the time execution pauses at the breakpoint, the buggy line has already run — its effect on the variables is already baked in. The breakpoint should be set BEFORE (or on) the suspect line, so you can single-step through it and watch the exact moment a variable takes on the wrong value.

Applied / scenario 5
You suspect a variable Total is being calculated incorrectly somewhere inside a loop. What two debugging tools together would best help you find the exact line responsible?
Reveal answer

A breakpoint set just before or inside the loop, combined with a watch window on Total — then single-stepping through each iteration to see exactly which line causes it to take on an unexpected value.

Short answer 6
In the Delphi (Pascal) editor, what must be enabled in Debugger Options before breakpoints will work?
Reveal answer

The Integrated Debugger option.
