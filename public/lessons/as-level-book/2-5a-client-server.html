2.05 Client-Server Architecture
Middleware, static vs dynamic pages, and why payroll still runs as a batch job.
Key Terms
Client-server architecture
A distributed system where a client does part of the processing and a server does another part.
Middleware
Software needed for a client and server to cooperate — now handles data transmission plus scripting support.
Static web page
A page whose content doesn't change based on the request — the original style of web browsing.
Dynamic web page
A page whose displayed content is determined by the specific request the client makes.
Theory

Where client-server architecture came from

  • After the PC arrived in the 1980s, it became clear that stand-alone PCs weren't viable in a large organisation — a PC needed a network connection to get enough resource.
  • Servers were first used just to provide extra shared facilities (filestore, software applications, printing).
  • The further development into "client-server" architecture was seen as a competitor to the traditional mainframe-with-terminals model: networked PCs (clients) accessing one or more powerful minicomputers acting as servers.

The essence of client-server, and middleware's role

  • The core idea: a distributed computer system where the CLIENT carries out part of the processing and the SERVER carries out another part.
  • For client and server to cooperate at all, software called "middleware" must be present — this basic concept still holds today, even though the vocabulary describing it has changed.

The modern vocabulary — web server, browser, middleware

  • The server is now a "web server" — a suite of software installable on virtually any computer system, providing access to a web application.
  • The client is the web browser software.
  • Middleware is now the software supporting the transmission of data across the network, together with the provision for scripting.

Static pages (the original web) vs dynamic pages (client-server applications)

  • The ORIGINAL use of the web involved a browser displaying static web pages containing information — downloading was possible, but the pages themselves were essentially fixed.
  • In a genuine client-server APPLICATION, the web page is "dynamic" — what's displayed is determined by the specific request the client makes.
  • The only requirement for this style of application is that it involves USER INTERACTION — beyond that, there's almost no limit to the variety of applications supported.
What counts as a client-server application — and what doesn't

The most obvious category is "ecommerce" (a customer buying products online from a company). Others include: e-business, email, searching library catalogues, online banking, and travel timetable information. Most require a "web-enabled" database installed on, or accessible from, the server.

By contrast: the monthly payroll run typifies an application that is UNSUITABLE for implementation as a dynamic web application, and will continue to be handled by batch processing instead — not every task benefits from this architecture.

Practice — Test Yourself

These questions only cover what THIS subsection taught — client-server architecture (completes Section 2.05).

Short answer 1
In the original client-server model, what genuinely different role did the "client" and the "server" each play?
Reveal answer

The client (networked PC) carried out part of the processing; the server (a powerful minicomputer) carried out another part — a genuinely distributed system, not just a PC talking to a shared disk.

Short answer 2
What is middleware, in the modern client-server picture?
Reveal answer

The software supporting the transmission of data across the network, together with the provision for scripting — required for the client (browser) and server (web server) to cooperate.

Fill in the blank 3
A ______ web page's content never changes with the request; a ______ web page's content is determined by the specific request the client makes.
Reveal answer

Static; dynamic.

Spot the error 4
A student says: "Every business application should be rebuilt as a dynamic web application — it's always the better architecture." Give a genuine counter-example from the theory.
Reveal answer

The monthly payroll run — it typifies an application UNSUITABLE for a dynamic web application, and continues to be handled by batch processing instead. Dynamic web applications specifically require user interaction; payroll doesn't fit that requirement.

Applied / scenario 5
A library wants customers to search its catalogue online, get personalised results, and interact with the system. Should this be built as a static or dynamic web page, and why?
Reveal answer

Dynamic — searching a catalogue involves user interaction and the displayed results depend on the specific request/search terms made, which is exactly what a dynamic page (and the client-server model behind it) is designed for.

Short answer 6
What is the ONE requirement that any client-server application must involve, regardless of how varied the applications are?
Reveal answer

User interaction.
