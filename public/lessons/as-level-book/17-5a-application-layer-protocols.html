17.05 Application-Layer Protocols: HTTP, Email, and FTP
The protocols that actually carry web pages, emails, and files.
Theory

HTTP (HyperText Transfer Protocol)

  • Underpins the World Wide Web — used every time a browser accesses a website, though hidden from the user.
  • TRANSACTION-oriented, client-server protocol: the client sends a REQUEST message, the server sends back a RESPONSE.
  • The request line format is <Method> <URL> <Version>CRLF, using ASCII coding. GET is the usual method, but several alternatives exist, making HTTP more broadly useful than just fetching web pages.
1. HTTP transmits a request message to TCP. 2. TCP creates packet(s), sends the first to IP (destination port 80, temporary sending port). 3. IP resolves the URL to an address using DNS, sends a datagram. 4. At the server, IP forwards the datagram to TCP. 5. Server TCP sends an acknowledgement. 6. Connection established — TCP sends remaining packets via IP to server TCP. 7. HTTP transmits a response message back via TCP/IP to the client browser.

Email protocols: SMTP, POP3, IMAP

  • Traditional email involves THREE separate client-server interactions: sender client → sender's mail server → receiver's mail server → receiver client.
  • SMTP (Simple Mail Transfer Protocol) is a "PUSH" protocol — it sends mail onward.
  • POP3 (Post Office Protocol v3) is a "PULL" protocol — the receiving client requests mail FROM the server.
  • IMAP (Internet Message Access Protocol) offers the same facilities as POP3, but MORE (e.g. leaving mail synced on the server across multiple devices).
  • Web-based mail has largely SUPERSEDED this traditional flow — a browser uses HTTP to access the mail application, though SMTP still handles server-to-server transfer.

FTP (File Transfer Protocol)

  • Handles any file transfer between two end-systems — a more capable alternative to emailing a file as an attachment.
  • Copes with end-systems running DIFFERENT operating systems / file systems by separating the CONTROL process from the DATA-TRANSFER process.
Practice — Test Yourself

These questions only cover what THIS subsection taught — HTTP, email protocols, and FTP (completes Section 17.05).

Short answer 1
What is the difference between SMTP and POP3?
Reveal answer

SMTP is a "push" protocol used to send mail onward. POP3 is a "pull" protocol used by the receiving client to request/retrieve mail from the server.

Short answer 2
What kind of protocol is HTTP, in terms of the client-server relationship?
Reveal answer

A transaction-oriented, client-server protocol — the client sends a request, the server sends back a response.

Fill in the blank 3
FTP handles differing operating systems by separating the ______ process from the ______ process.
Reveal answer

Control; data-transfer.

Spot the error 4
A student says HTTP can only be used for fetching web pages, since GET is "the" HTTP method. What's the oversight?
Reveal answer

GET is the USUAL method, but HTTP defines several ALTERNATIVES — this range of methods makes HTTP a genuinely general-purpose protocol, not one limited only to retrieving web pages.

Applied / scenario 5
Why does traditional email delivery involve THREE separate client-server interactions rather than just one direct connection from sender to receiver?
Reveal answer

The sender's client only connects to their OWN mail server; that server then acts as a CLIENT itself when forwarding (via SMTP) to the receiver's mail server; finally the receiver's client retrieves (via POP3/IMAP) from their own server — three separate hops rather than a single direct link.

Short answer 6
Which protocol offers the same facilities as POP3, but more (such as staying synced across devices)?
Reveal answer

IMAP (Internet Message Access Protocol).
