21.02 Digital Signatures and Digital Certificates
Using asymmetric keys backwards to prove identity — and the trust problem that certificates solve.
Theory

The digital signature idea: reversing the key roles

  • If a sender encrypts with their OWN PRIVATE key, anyone with the matching PUBLIC key can decrypt it. This does NOT provide confidentiality (anyone with the public key can read it) — but it DOES prove identity, since ONLY the private key's owner could have created ciphertext that decrypts correctly with that public key.
  • Used this way, the encrypted result acts as a DIGITAL SIGNATURE.

Using a hash instead of encrypting the whole message

  • Encrypting the ENTIRE message just to sign it is inefficient. Instead: a CRYPTOGRAPHIC ONE-WAY HASH FUNCTION creates a "DIGEST" — a number uniquely tied to that specific message.
  • The sender's private key encrypts just the DIGEST — this is much faster, and is the actual digital signature sent alongside the plaintext message.
SENDER: Message → hash function → Digest → encrypt with sender's PRIVATE key → Digital signature (Message sent as plaintext + digital signature, as two parts) RECEIVER: Message → SAME public hash function → Digest (recomputed) Digital signature → decrypt with sender's PUBLIC key → Digest (recovered) If both digests MATCH → message is authentic AND unaltered
  • If the two digests match, the receiver can be confident the message is BOTH authentic (really from that sender) AND unaltered (integrity confirmed).

The remaining gap: what if the public key itself is forged?

  • This whole scheme assumes the receiver has the SENDER's genuine public key — but someone could forge a public key and pretend to be someone else entirely.
  • The fix: a CERTIFICATION AUTHORITY (CA), part of a PUBLIC KEY INFRASTRUCTURE (PKI).

Obtaining a digital certificate

  • 1. A would-be receiver (Person A) with a public-private key pair contacts a local CA.
  • 2. The CA CONFIRMS Person A's identity; Person A's public key is given to the CA.
  • 3. The CA creates a DIGITAL CERTIFICATE containing Person A's public key.
  • 4. The CA encrypts with ITS OWN private key to add its digital signature to the certificate.
  • 5. The signed certificate is given to Person A, who typically posts it publicly (their own website, or a dedicated certificate-hosting site).
  • Anyone wanting Person A's genuine public key downloads the certificate and uses the CA's OWN (widely trusted) public key to verify the CA's signature and extract Person A's public key with confidence.
  • The relevant standard for this whole process is X.509.
Practice — Test Yourself

These questions only cover what THIS subsection taught — digital signatures, hashing, and digital certificates (completes Section 21.02).

Short answer 1
Why does encrypting a message with a sender's private key NOT provide confidentiality?
Reveal answer

The corresponding public key is not secret — anyone who has it can decrypt the message. This technique proves WHO sent it, not that only one person can READ it.

Short answer 2
Why is a digest used instead of encrypting the entire message for a digital signature?
Reveal answer

Encrypting an entire message just to sign it is inefficient; hashing produces a much smaller, unique digest that can be signed (encrypted) far faster while still proving both authenticity and integrity.

Fill in the blank 3
A digital certificate is issued by a ______ ______, which is part of a Public Key Infrastructure.
Reveal answer

Certification Authority.

Spot the error 4
A student says a digital certificate stores the CA's private key so anyone can verify it. What's the mistake?
Reveal answer

A certificate contains the SUBJECT's public key, signed using the CA's PRIVATE key. Verification uses the CA's PUBLIC key — the CA's private key must stay secret, exactly like any other private key, or the whole trust system collapses.

Applied / scenario 5
A receiver recomputes a digest from a received message and finds it does NOT match the digest recovered from the digital signature. What does this indicate?
Reveal answer

Either the message was altered in transit, or the signature wasn't genuinely created by the claimed sender's private key — either way, authenticity and/or integrity has failed, and the message should not be trusted.

Short answer 6
What real-world problem does a Certification Authority solve that a plain digital signature alone cannot?
Reveal answer

It prevents someone from forging a public key and falsely claiming to be a different person — the CA independently verifies identity before vouching for a public key via its own trusted signature.
