16.01 User-Defined Data Types
Enumerated types, pointers, records, and sets — data types the programmer defines rather than uses ready-made. Opens the A-Level portion of the course.
Theory

What "user" means here

  • Normally, a programmer writes a program for a "user". But when DEFINING a new data type, the programmer becomes the "user" of the programming language itself — hence "user-defined data type".
  • A NON-COMPOSITE user-defined type has a definition that does NOT reference another type. A COMPOSITE type's definition DOES reference at least one other type.

Non-composite: enumerated data type

  • Defines a list of possible values for a type.
  • The values LOOK like strings, but are NOT — they must never be enclosed in quote marks.
  • Enumerated values are ORDINAL — they have an implied order, which is what makes them genuinely useful (not just a list of names).
TYPE TDirections = (North, East, South, West) TDays = (Monday, Tuesday, Wednesday, Thursday, Friday, Saturday, Sunday) DECLARE Direction1 : TDirections DECLARE StartDay : TDays Direction1 ← North StartDay ← Wednesday // because TDays is ordinal, comparisons are meaningful: DECLARE Day : TDays DECLARE Weekend : BOOLEAN Weekend ← TRUE IF Day > Friday
Enumerated data type: a list of possible data values.

Non-composite: pointer data type

  • References a memory location — used to build dynamically varying data structures.
  • Its definition must relate to the TYPE of the variable being pointed to.
  • DEREFERENCING a pointer means accessing the value stored at the address it points to.
TYPE TMyPointer = ^<TypeName> DECLARE MyPointer : TMyPointer // no caret needed to declare ValuePointedTo ← MyPointer^ // dereferencing — get the value it points to

Composite: record, set, and class

  • A RECORD holds a FIXED NUMBER of components (fields), which can be of DIFFERENT types — the most widely-used composite type, because it groups related values into one coherent whole.
  • Individual fields are accessed with DOT NOTATION: Employee1.DateEmployed.
  • A SET type supports mathematical set operations: union, intersection, difference, testing membership, including/excluding an element.
  • A CLASS (object-oriented programming) is also a user-defined type — every class you define is used to create objects (Chapter 27).
TYPE TEmployeeRecord DECLARE EmployeeFirstName : STRING DECLARE EmployeeFamilyName : STRING DECLARE DateEmployed : DATE DECLARE Salary : CURRENCY ENDTYPE Employee1.DateEmployed ← #16/05/2017#
Record data type: a data type that contains a fixed number of components, which can be of different types.

Why bother with user-defined types at all?

  • Without object-oriented programming, a programmer COULD avoid user-defined types entirely — but for any reasonably large program, using them makes the code more understandable and less error-prone.
  • There CANNOT be a single built-in "record" type, because every different problem needs its OWN specific combination of fields — user-definition becomes inevitable once you need a structure that isn't one of the built-in simple types.
Practice — Test Yourself

These questions only cover what THIS subsection taught — enumerated types, pointers, records, and sets (completes Section 16.01).

Short answer 1
Why must enumerated data type values NOT be written in quote marks?
Reveal answer

Because although they look like strings, they are NOT strings — they are their own distinct ordinal data type, and quoting them would be treating them as the wrong type.

Short answer 2
What makes an enumerated data type "ordinal", and why does that matter?
Reveal answer

Its values have an implied ORDER (e.g. Monday comes before Tuesday) — this lets you use comparison operators like > and < meaningfully with them, which wouldn't make sense for a plain unordered list of names.

Fill in the blank 3
A ______ type's definition does not reference another type; a ______ type's definition references at least one other type.
Reveal answer

Non-composite; composite.

Spot the error 4
A student declares DECLARE StartDay : TDays then writes StartDay ← "Wednesday", with quote marks. What's wrong?
Reveal answer

Enumerated values must NOT be quoted — they aren't strings. It should be StartDay ← Wednesday, without quote marks.

Applied / scenario 5
Write pseudocode to define a record type storing an animal's name (STRING), age (INTEGER), and enclosure location (STRING).
Reveal answer

TYPE TAnimalRecord
  DECLARE AnimalName : STRING
  DECLARE AnimalAge : INTEGER
  DECLARE Location : STRING
ENDTYPE

Short answer 6
Why can't there be a single, universal, built-in "record" type provided by every programming language?
Reveal answer

Because every different problem needs its own specific combination of fields — unlike a simple type like INTEGER, which works identically for any program, a record's structure is inherently problem-specific and must be individually defined.
