25.04 Running a Recursive Subroutine: Stack Frames
What the compiler and runtime actually do under the hood to make recursion work.
Theory

Recursion needs a stack

  • Recursive subroutines can only run if the compiler produces object code that uses a STACK to push RETURN ADDRESSES and LOCAL VARIABLES every time the subroutine is called.
  • Each call's saved information (return address + local variable values) is called a STACK FRAME.
Stack frame: the return address and the values of the local variables saved for one subroutine call.

Worked example — running Factorial(3)

160 Answer ← Factorial(Number) // n=3, first call ... 080 Result ← n * Factorial(n - 1) // the recursive call
  • Line 160 makes the FIRST call — a return address is pushed onto the stack, and execution jumps into the function.
  • Every time line 080 makes a further recursive call, ANOTHER stack frame (return address + current local variables) is pushed. Each recursive call ADDS a stack frame — they build up until the base case is reached.
  • At the BASE CASE (n=0), the function's result (1) is pushed onto the stack.
  • UNWINDING: each return POPS a result and its stack frame off the stack, uses the popped result to compute a new value, and pushes THAT new result — repeating until control returns all the way to line 160, with the final answer on top of the stack.

Why this matters for memory usage

  • Every recursive call ADDS a stack frame — so DEEP recursion (many nested calls before reaching the base case) consumes correspondingly MORE stack memory.
  • Example: CountDownFrom(100) requires 100 stack frames before it completes — this scales with the DEPTH of recursion, not just the total work done.
Practice — Test Yourself

These questions only cover what THIS subsection taught — stack frames and how recursion is actually executed (completes Section 25.04).

Short answer 1
What two things does a stack frame store?
Reveal answer

The return address and the values of the local variables for that particular subroutine call.

Short answer 2
What happens to the stack each time a recursive subroutine calls itself?
Reveal answer

A new stack frame (return address + current local variable values) is pushed onto the stack.

Fill in the blank 3
When a recursive call returns, its stack frame is ______ off the stack, and the local variable values are ______.
Reveal answer

Popped; restored.

Spot the error 4
A student believes recursion "doesn't really use any extra memory, since it's just calling the same function repeatedly". What's the misconception?
Reveal answer

Each recursive call, even of the "same" function, gets its OWN stack frame with its own copy of local variables and its own return address — memory usage genuinely scales with the DEPTH of recursion, it isn't free just because the code being executed is identical each time.

Applied / scenario 5
Why does CountDownFrom(100) require exactly 100 stack frames?
Reveal answer

Because it makes one recursive call for each value from 100 down to 0, and each of those calls needs its own stack frame active simultaneously until the base case is reached and unwinding begins.

Short answer 6
What is pushed onto the stack when a recursive function's base case is finally reached?
Reveal answer

The result computed by the base case (e.g. 1, for Factorial(0)) — this becomes the starting value that gets used and modified as each enclosing call unwinds.
