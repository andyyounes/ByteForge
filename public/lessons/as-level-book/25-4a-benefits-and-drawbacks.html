25.05 Benefits and Drawbacks of Recursion
When recursion is the right tool — and when its overhead outweighs its elegance. Completes Chapter 25.
Theory

The case for recursion

  • Recursion is an important technique across different PROGRAMMING PARADIGMS (Chapter 29 covers declarative languages, where recursion is central).
  • For a problem that is INHERENTLY recursive by its mathematical definition, the EASIEST way to write a solution is often to directly implement the recursive definition.
  • Recursive solutions are often MORE ELEGANT and use LESS program code than the equivalent iterative solution — the code can closely mirror the problem's own natural structure.

The case against recursion

  • Repeated recursive calls carry a real OVERHEAD in MEMORY USAGE (one stack frame per call) and PROCESSOR TIME (managing all that pushing/popping).
  • Deep recursion can use significantly MORE resources than an equivalent iterative loop, which typically needs only a FIXED, small amount of memory regardless of how many iterations it runs.

Chapter 25 summary

  • A recursive routine is defined in terms of itself, with a base case and a general case.
  • It must reach the base case after a finite number of calls, or it never terminates.
  • Tracing recursion requires care with statements AFTER the recursive call — they execute during unwinding, in reverse order of the original calls.
  • Each recursive call pushes a stack frame (return address + local variables); each return pops one off.
  • Recursion can be more elegant and concise, but carries real memory and processing overhead compared to iteration.
Practice — Test Yourself

These questions cover the trade-offs of recursion, and draw together the whole of Chapter 25 (completes Section 25.05 and Chapter 25).

Short answer 1
Name one advantage and one disadvantage of using recursion instead of iteration.
Reveal answer

Advantage: recursive solutions are often more elegant and use less code, especially for inherently recursive problems. Disadvantage: repeated calls carry memory and processing overhead from all the stack frames.

Short answer 2
Why is recursion often the natural choice for a mathematically-defined problem?
Reveal answer

The recursive code can directly mirror the problem's own mathematical definition, since many mathematical definitions are themselves stated recursively (like the factorial function).

Fill in the blank 3
Repeated recursive calls carry overheads in terms of ______ usage and ______ time.
Reveal answer

Memory; processor.

Spot the error 4
A student says "recursion is always better than iteration because it's shorter and more elegant". What's the oversight?
Reveal answer

Elegance and brevity come at the cost of memory and processing overhead — for very deep recursion (e.g. CountDownFrom(100) needing 100 stack frames), an iterative loop would typically use far less memory, making iteration the more PRACTICAL choice despite being less "elegant".

Applied / scenario 5
A programmer needs to sum the numbers from 1 to 1,000,000. Would recursion or iteration be the more sensible practical choice, and why?
Reveal answer

Iteration — a recursive solution would require 1,000,000 stack frames, an enormous and likely impractical amount of memory, whereas an iterative loop uses a small, fixed amount of memory regardless of how many times it repeats.

Short answer 6
In which broader category of programming languages is recursion described as a particularly important technique?
Reveal answer

Declarative programming languages (covered in Chapter 29).
