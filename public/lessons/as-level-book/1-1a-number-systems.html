1.01 Number Systems
Denary, binary, and hexadecimal — the same value, three different symbol sets.
Key Terms
Denary (base-10)
The everyday number system using 10 symbols, 0-9.
Binary (base-2)
A number system using just 2 symbols, 0 and 1 — every computer's native representation.
Hexadecimal (base-16)
A number system using 16 symbols (0-9, then A-F) — a compact way to WRITE binary for humans.
Bit
One binary digit — short for "binary digit".
Theory

Why binary, specifically

  • Every computer component is engineered to reliably distinguish only TWO states (on/off, high/low voltage) — this is why binary (base-2) is the system computers are actually built around.
  • A denary number like 346 really means 3 × 10² + 4 × 10¹ + 6 × 10⁰ — each digit's position is worth a power of the BASE. Binary works identically, just with powers of 2 instead of 10.

Why hexadecimal exists at all

  • Raw binary is accurate for a computer but unwieldy for a HUMAN to read or write — a byte in binary is 8 characters long.
  • Hexadecimal groups every 4 bits into ONE symbol (0-9, then A=10, B=11, C=12, D=13, E=14, F=15) — a full byte becomes just 2 hex characters, far more compact and readable.
  • Leading zeros are commonly kept in a hex byte (e.g. 08, not just 8) to make clear exactly how many bits it represents.

Worked example — binary to denary: 11001

Position values from the right: 2⁰=1, 2¹=2, 2²=4, 2³=8, 2⁴=16.

Binary 11001 has 1s in positions 2⁴, 2³, and 2⁰: 16 + 8 + 1 = 25.

Faster method — double-and-add: starting from the MOST significant bit, repeatedly double the running total and add the next digit. For 11001: 1 → (×2)+1=3 → (×2)+0=6 → (×2)+0=12 → (×2)+1=25.

Worked example — denary to binary: 246

Repeatedly divide by 2, noting the remainder each time, then read the remainders in REVERSE order:

246÷2=123 r0 · 123÷2=61 r1 · 61÷2=30 r1 · 30÷2=15 r0 · 15÷2=7 r1 · 7÷2=3 r1 · 3÷2=1 r1 · 1÷2=0 r1

Reading remainders bottom-to-top: 11110110. Sanity check: 8 bits can represent 0 to 255, and 246 fits comfortably — a 7-bit number could only reach 127, so 8 bits was the right size to expect.

Converting between binary and hexadecimal directly

  • Binary → hex: starting from the LEAST significant bit, group into 4s, converting each group to its one hex digit.
  • Hex → binary: convert each hex digit separately into its 4-bit binary equivalent (F → 1111, E → 1110, and so on), then just concatenate them.
  • Denary → hex is usually done via binary first (denary → binary → hex) — going directly is possible but more error-prone.
Practice — Test Yourself

These questions only cover what THIS subsection taught — binary, hexadecimal, and the conversions between them.

Short answer 1
Why is binary the number system computers are actually built around?
Reveal answer

Because every computer component is engineered to reliably distinguish only TWO physical states (e.g. on/off, high/low voltage) — binary's two symbols (0, 1) map directly onto this.

Short answer 2
Why is hexadecimal used, if computers themselves only ever use binary?
Reveal answer

Purely for HUMAN readability — hex compresses every 4 bits into one symbol, turning an 8-character binary byte into just 2 hex characters, much easier for a person to read, write, and document.

Fill in the blank pseudocode 3
Complete the hex value for binary 1111: F converts from ______; and E converts from ______.
Reveal answer

F converts from 1111; E converts from 1110.

Spot the error 4
A student converts binary 11111111 to hex as "F F" (treating it as two separate 4-character groups from the left, "1111" and "1111", which happens to work here) but then tries the SAME left-grouping method on 101 (3 bits) and gets stuck. What should they do differently?
Reveal answer

Groups of 4 must be formed starting from the LEAST significant bit (the right-hand end), not the left — for a number that isn't a clean multiple of 4 bits, the leftmost group gets padded with leading zeros instead of trying to group from the left.

Applied / scenario 5
Convert the denary number 374 into hexadecimal (convert to binary first, then group into hex).
Reveal answer

374 in binary is 101110110. Padded to 12 bits (3 hex digits): 0001 0111 0110 → hex 176.

Applied / scenario 6
Convert the hexadecimal number 3A2C to denary.
Reveal answer

3A2C = 3×16³ + 10×16² + 2×16¹ + 12×16⁰ = 12288 + 2560 + 32 + 12 = 14892.
