27.05–27.06 Polymorphism & Garbage Collection
Same method name, different behaviour per class — and how memory gets reclaimed automatically.
Theory

The problem polymorphism solves

  • A method like PrintDetails, defined only in the BASE class, can only print the base class's OWN attributes — it has no way to know about a SUBCLASS's extra attributes (like Book's IsRequested).
  • The fix: REDEFINE the method in the subclass, using the SAME identifier — but giving it DIFFERENT behaviour appropriate to that subclass.
Polymorphism: the method behaves differently for different classes in the hierarchy.

Redefining a method — calling the base version first

# Python — Book's version of PrintDetails def PrintDetails(self): print("Book Details") LibraryItem.PrintDetails(self) # calls the BASE CLASS method of the same name print(self._IsRequested)
  • Rather than reimplementing everything, the subclass's method typically CALLS the base class's version first (to handle the shared attributes), then adds its OWN extra output.

Language-specific syntax for polymorphism

  • VB.NET: the base class method needs the keyword Overridable; the subclass version uses Overrides, and calls the base version via MyBase.PrintDetails().
  • Pascal: the base class method header needs virtual; the subclass's header needs override, and calls the base version via inherited;.
  • Python needs NO special keyword — simply redefining a method with the same name in the subclass is enough; calling the base version is done explicitly (LibraryItem.PrintDetails(self)).

Garbage collection

  • When an object is created, it occupies MEMORY. If objects never release that memory when no longer needed, eventually there's NO free memory left — this is called MEMORY LEAKAGE.
  • Python and VB.NET: a GARBAGE COLLECTOR automatically reclaims memory from objects no longer referenced by the running program — the programmer does NO manual housekeeping.
  • Pascal: the programmer must EXPLICITLY release memory using .Free (e.g. ThisBook.Free;) — NOT automatic.
Practice — Test Yourself

These questions only cover what THIS subsection taught — polymorphism and garbage collection (completes Sections 27.05–27.06).

Short answer 1
What is polymorphism?
Reveal answer

A method with the same identifier behaves differently depending on which class in the hierarchy it's called on.

Short answer 2
What keyword must Pascal add to a base class method's header to allow it to be overridden?
Reveal answer

virtual.

Fill in the blank 3
In Pascal, memory must be manually released using the ______ method, whereas Python and VB.NET use an automatic ______ ______.
Reveal answer

.Free; garbage collector.

Spot the error 4
A student writes a VB.NET subclass method with Overrides, but the base class method was never marked Overridable. What happens?
Reveal answer

This will cause a compile error — VB.NET requires the base class method to be explicitly marked Overridable before any subclass can legally use Overrides to redefine it.

Applied / scenario 5
Why does a Pascal program need to explicitly call ThisBook.Free before the program ends, but a Python program doesn't need an equivalent call?
Reveal answer

Pascal does not have automatic garbage collection — memory occupied by objects must be explicitly released by the programmer. Python's garbage collector automatically detects when an object is no longer referenced and reclaims its memory without any programmer action.

Short answer 6
What term describes the situation where a program eventually runs out of free memory because objects never release it?
Reveal answer

Memory leakage.
