30.01–30.02 Program Generators & Why Errors Occur
Tools that write code for you, and the human causes behind most software bugs. Opens the final chapter of the course.
Theory

Program generators — not a new idea

  • Early computers were programmed directly in MACHINE CODE — extremely tedious. ASSEMBLERS were invented to generate machine code from assembly instructions; later, INTERPRETERS and COMPILERS generate low-level code from high-level programs.
  • Program generators have therefore existed for a very long time — the trend continues toward tools that translate ever more ABSTRACT models into working code.
  • Modern IDEs offer advanced generation: interactive GUI DESIGNERS, code generated from a WIZARD or TEMPLATE, and Computer-Aided Software Engineering (CASE) tools.
Program generator: a computer program that can be used to create other computer programs.
Program library: a collection of pre-compiled routines or modules that a program can use.

Program libraries

  • Built-in functions (Chapter 13) are part of a program LIBRARY — pre-written, pre-TESTED code that saves you from writing (and re-testing) the same logic from scratch.

Why software fails to perform as expected

  • A CODING mistake by the programmer.
  • The REQUIREMENT SPECIFICATION wasn't drawn up correctly in the first place.
  • A DESIGN error made by the software designer.
  • A poorly designed USER INTERFACE that leads users to make mistakes.
  • HARDWARE failure.

Finding errors — and why finding them EARLY matters

  • An END USER reporting an error damages the software developer's REPUTATION — testing BEFORE release is essential.
  • Research consistently shows: the EARLIER an error is found, the CHEAPER it is to fix.
  • Edsger Dijkstra (famous computer scientist): "Program testing can be used to show the presence of bugs, but never to show their absence!" — testing can never PROVE a program is bug-free, only reveal bugs that exist.
Practice — Test Yourself

These questions only cover what THIS subsection taught — program generators, libraries, and why errors occur (completes Sections 30.01–30.02).

Short answer 1
Give two examples of program generators mentioned in this section.
Reveal answer

Any two of: assemblers, interpreters/compilers, IDE GUI wizards/templates, CASE tools.

Short answer 2
What does Dijkstra's quote mean in practice?
Reveal answer

No matter how much testing a program passes, this only proves the TESTED cases work — it can never guarantee there are no bugs remaining in UNTESTED cases.

Fill in the blank 3
The earlier an error is found during development, the ______ it is to fix.
Reveal answer

Cheaper.

Spot the error 4
A team assumes all their software bugs must be the programmer's fault, since "that's who writes the code". What other sources of error does this overlook?
Reveal answer

Errors can also stem from an incorrect requirement specification, a design flaw introduced by the software designer, a poorly designed user interface causing user mistakes, or hardware failure — not just coding mistakes.

Applied / scenario 5
Why is a user reporting a bug considered worse for a software developer than the bug being caught during in-house testing?
Reveal answer

It damages the software developer's reputation — customers experiencing bugs firsthand reflects poorly on the quality of the release, whereas catching it internally before release avoids that reputational cost entirely.

Short answer 6
What is a program library?
Reveal answer

A collection of pre-compiled routines or modules that a program can use, rather than needing to write and test equivalent code from scratch.
