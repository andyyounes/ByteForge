28.04 Absolute and Relative Addressing
Why a program that only knows absolute addresses can't be loaded just anywhere in memory.
Theory

Absolute addressing — the restriction

  • An ABSOLUTE address is the actual numeric address of a memory location.
  • A program written using absolute addresses can ONLY be loaded at the ONE specific memory location it was designed for — it cannot be relocated.

Relative addressing — the solution

  • RELATIVE addresses are expressed relative to a BASE address (typically the address of the program's first instruction).
  • When the program loads, this base address is stored in a BASE REGISTER (BR). Every address reference then combines the BASE REGISTER's value with an OFFSET.
  • Example: STO [BR] + 10 stores ACC's contents at the address calculated from (contents of BR) + 10.
  • This lets an assembler produce a program that can be LOADED ANYWHERE in memory — the offsets stay the same regardless of where the base address actually ends up.
Absolute address: the actual numeric address of a memory location.
Relative address: an address expressed relative to a base address, resolved via a base register plus an offset.

Three ways of writing the same instruction

Symbolic (label-based): LDD A Relative (offset from base): LDD [BR] + 3 Absolute (raw number): LDD 203
  • All three could refer to the EXACT SAME memory location — they differ only in HOW that location is expressed, not in what the instruction actually does.
  • Symbolic addressing (labels) is what the PROGRAMMER writes; the ASSEMBLER translates this into either relative or absolute addresses depending on the target system.

Why the END instruction is critical

  • Once program execution reaches the end, control MUST be passed back to the operating system via END.
  • Without it, the processor would try to EXECUTE whatever binary pattern happens to occupy the next memory location as if it were an instruction — if that pattern doesn't correspond to a valid instruction, the processor CRASHES.
Practice — Test Yourself

These questions only cover what THIS subsection taught — absolute and relative addressing (completes Section 28.04).

Short answer 1
Why can't a program using only absolute addresses be loaded at a different memory location than the one it was designed for?
Reveal answer

Every address reference in the program is a fixed, specific number — if the program is loaded somewhere else, those hard-coded addresses would no longer point to the correct data/instructions.

Short answer 2
What is stored in the base register (BR)?
Reveal answer

The address at which the program was actually loaded into memory (typically the address of its first instruction).

Fill in the blank 3
A relative address is calculated as the contents of the ______ register, plus an ______.
Reveal answer

Base; offset.

Spot the error 4
A student's assembly program omits the final END instruction. What is the risk?
Reveal answer

Execution will continue past the intended end of the program and try to interpret whatever data happens to sit in the next memory location as an instruction — if it isn't a valid instruction, the processor crashes.

Applied / scenario 5
Why does using relative addressing make a program more flexible for an operating system to run?
Reveal answer

The OS can load the program at ANY available memory location, simply setting the base register accordingly — since all internal address references are relative offsets from that base, the program works correctly regardless of exactly where it ends up in memory.

Short answer 6
What role does symbolic addressing (labels) play relative to absolute and relative addressing?
Reveal answer

It's what the programmer actually writes — the assembler then translates these labels into either absolute or relative addresses, depending on how the target system needs the final machine code structured.
