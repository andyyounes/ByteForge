20.02 Process Scheduling
Process states, interrupts, and the algorithms that decide which process runs next.
Theory

Three levels of scheduler

  • LONG-TERM (high-level) scheduler: selects a program on disk to be loaded into main memory.
  • MEDIUM-TERM scheduler: moves a program back to disk if memory gets overcrowded.
  • SHORT-TERM (low-level) scheduler: controls when an in-memory program actually gets CPU access.

The five process states

  • NEW → READY: a process arrives in memory, a process control block (PCB) is created.
  • READY → RUNNING: the dispatcher gives the process CPU access.
  • RUNNING → READY: the process is halted by an interrupt (e.g. its time slice ran out).
  • RUNNING → WAITING: the process can't progress until an event completes (e.g. I/O) — also called "suspended" or "blocked".
  • WAITING → READY: the awaited event completes.
  • RUNNING → TERMINATED: the process finishes execution.
Process: a program in memory that has an associated process control block.
Process control block (PCB): a complex data structure containing all data relevant to the running of a process.
Thread: part of a process being executed.

Interrupts and register saving

  • An interrupt happens for one of two main reasons (besides error termination): a running process makes an I/O system call and must move to WAITING; or the scheduler decides to halt the process for its own reasons.
  • Whatever the cause, the OS kernel's interrupt-handling routine must run, possibly deciding on PRIORITY between multiple pending interrupts.
  • Crucially, the CURRENT register values must be saved into the process's PCB — this is what allows the process to resume correctly later, exactly where it left off.

Scheduling algorithms — preemptive vs. non-preemptive

  • PREEMPTIVE: can halt a running process before it would naturally finish/pause itself.
  • NON-PREEMPTIVE: cannot interrupt a running process.
  • FIRST COME FIRST SERVED (FCFS): non-preemptive, implemented as a FIFO queue. Simple but very INEFFICIENT if used alone — usually combined with other algorithms.
  • ROUND-ROBIN: gives each process a fixed TIME SLICE — preemptive, since the process is halted once the slice expires. Normally no prioritisation, unless separate round-robin queues are set up per priority level.
  • PRIORITY-BASED: more complex — priorities may need RE-EVALUATING every time a process enters the ready queue or gets halted. Possible criteria: estimated total execution time, estimated remaining time, time already spent waiting, or whether a process is I/O-bound vs. CPU-bound.

Why I/O-bound processes deserve high priority

  • A process doing heavy I/O (e.g. printing wage slips) uses very LITTLE CPU time overall — giving it high priority lets that small CPU burst happen quickly, after which the process moves to WAITING while the slow I/O proceeds, freeing the CPU for other work.
Practice — Test Yourself

These questions only cover what THIS subsection taught — process states, interrupts, and scheduling algorithms (completes Section 20.02).

Short answer 1
Why must a process's register values be saved to its PCB when an interrupt occurs?
Reveal answer

So the process can later resume execution exactly where it left off, with all its working values intact, once it returns to the running state.

Short answer 2
What is the key difference between a preemptive and a non-preemptive scheduling algorithm?
Reveal answer

A preemptive algorithm can halt a running process before it would naturally stop itself. A non-preemptive algorithm cannot interrupt a running process.

Fill in the blank 3
A process moves from the running state to the ______ state when it needs to wait for an event such as I/O to complete.
Reveal answer

Waiting (also called suspended or blocked).

Spot the error 4
A student claims round-robin scheduling is non-preemptive because it just cycles through processes fairly. What's wrong?
Reveal answer

Round-robin IS preemptive — each process is forcibly halted once its allocated time slice expires, even if it wasn't finished or ready to yield the CPU voluntarily.

Applied / scenario 5
Why should an I/O-bound process (like one printing wage slips) typically be given HIGH priority, even though it doesn't need much CPU time overall?
Reveal answer

Giving it priority lets its brief CPU burst run quickly, so it can move on to the WAITING state (during the slow I/O operation) sooner — freeing the CPU for other processes rather than making them wait behind a process that barely needs the CPU anyway.

Short answer 6
Which scheduler level is responsible for deciding which program on disk gets loaded into main memory?
Reveal answer

The long-term (high-level) scheduler.
