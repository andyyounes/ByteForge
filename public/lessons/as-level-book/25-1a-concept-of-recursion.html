25.01–25.02 The Concept of Recursion
A routine defined in terms of itself — base case, general case, and coding it in pseudocode.
Theory

What recursion is

  • A RECURSIVE routine is a function or procedure defined IN TERMS OF ITSELF.
  • Classic example: the factorial function. 0! = 1 (the BASE CASE — explicit, no recursion needed). n! = n × (n-1)! (the GENERAL CASE — defined using the SAME function, on a SMALLER value).
Recursive routine: a function or procedure defined in terms of itself.
Base case: an explicit solution to a recursive function.
General case: a definition of a recursive function in terms of itself.

The three rules every recursive routine must follow

  • 1. Must have a BASE CASE.
  • 2. Must have a GENERAL CASE.
  • 3. Must reach the base case after a FINITE number of calls to itself — each recursive step must move CLOSER to the base case, for any valid starting value.
  • Break rule 3, and the recursion never terminates — e.g. calling Factorial(-2) on the pseudocode below would keep subtracting 1 forever, NEVER reaching n=0.

Coding the factorial function — iterative vs. recursive

// Iterative version FUNCTION Factorial(n : INTEGER) RETURNS INTEGER Result ← 1 FOR i ← 1 TO n Result ← Result * i ENDFOR RETURN Result ENDFUNCTION // Recursive version — closely mirrors the mathematical definition FUNCTION Factorial(n : INTEGER) RETURNS INTEGER IF n = 0 THEN Result ← 1 // base case ELSE Result ← n * Factorial(n - 1) // general case — recursive call ENDIF RETURN Result ENDFUNCTION
  • The recursive version's structure directly mirrors the ORIGINAL mathematical definition — this is a common reason recursion feels natural for mathematically-defined problems.

A recursive procedure — counting down

PROCEDURE CountDownFrom(n : INTEGER) OUTPUT n IF n > 0 THEN CALL CountDownFrom(n - 1) ENDIF END PROCEDURE
  • The base case is n=0 (outputs 0, but makes NO further call). The general case outputs n, then recurses on a SMALLER value (n-1) — each call moves one step closer to the base case.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the concept of recursion and writing recursive routines (completes Sections 25.01–25.02).

Short answer 1
What are the three rules a recursive subroutine must satisfy?
Reveal answer

It must have a base case, have a general case, and reach the base case after a finite number of calls to itself.

Short answer 2
What is the base case of the factorial function?
Reveal answer

0! = 1 — an explicit result requiring no further recursive call.

Fill in the blank 3
A recursive routine's general case must move ______ to the base case with every call, for the recursion to terminate.
Reveal answer

Closer.

Spot the error 4
Calling the recursive Factorial function with n = -2. Which of the three rules is broken, and what actually happens?
Reveal answer

Rule 3 (reaching the base case in a finite number of calls) is broken — since n decreases by 1 each call starting from -2, it goes -2, -3, -4... and NEVER equals 0. The recursion never terminates (in practice, it would eventually crash from exhausting available memory/stack space).

Applied / scenario 5
In the CountDownFrom procedure, what happens if it's called with n = 0 directly?
Reveal answer

It outputs 0, then checks n > 0 (FALSE), so it makes NO further recursive call — the base case is reached and handled immediately.

Short answer 6
Why does the recursive version of Factorial closely resemble its original mathematical definition, unlike the iterative version?
Reveal answer

Because the mathematical definition itself IS recursive (n! = n × (n-1)!) — the recursive pseudocode directly translates that same structure, while the iterative version has to express the same idea using a completely different mechanism (a loop with an accumulator).
