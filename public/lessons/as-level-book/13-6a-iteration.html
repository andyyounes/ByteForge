13.06 Iteration
FOR, REPEAT…UNTIL, WHILE — and Python's genuine gap: no post-condition loop at all.
Theory

Count-controlled (FOR) loops

FOR <control variable> ← s TO e STEP i // STEP is optional <statement(s)> ENDFOR
  • The control variable starts at s, increases by i each pass, and finishes once it reaches e.
  • Python: for x in range(s, e, i): — but Python's range STOPS BEFORE e is reached (exclusive upper bound), unlike the pseudocode version which counts up TO and including e. This is a genuine, common source of off-by-one mistakes when translating.

Post-condition loops — REPEAT…UNTIL

  • Executes the loop body AT LEAST once. The condition is checked AFTER each pass — while it's FALSE, the loop repeats; once TRUE, execution moves on.
  • You MUST ensure something inside the loop will eventually make the condition TRUE — otherwise it runs forever.
REPEAT <statement(s)> UNTIL <condition>
  • Genuine gap: Python has NO post-condition loop at all — a pre-condition (WHILE) loop must be used instead, restructured so the condition can be checked up front.

Pre-condition loops — WHILE…ENDWHILE

  • Checks the condition BEFORE running the loop body. Runs WHILE the condition is TRUE; stops the moment it's FALSE.
  • Can run ZERO times, if the condition is already false the first time it's checked. Any variable used in the condition must NOT be undefined when the loop is first reached.
Pseudocode: Python: WHILE <condition> while <condition>: <statement(s)> <statement(s)> ENDWHILE

Which loop structure to choose?

  • If you KNOW how many times you need to loop when execution reaches it — use a COUNT-CONTROLLED (FOR) loop.
  • If termination depends on a CONDITION determined by what happens inside the loop — use a CONDITIONAL loop.
  • A pre-condition (WHILE) loop has the added benefit that the loop might not run AT ALL, if the condition doesn't require it.
Practice — Test Yourself

These questions only cover what THIS subsection taught — FOR, REPEAT…UNTIL, and WHILE loops (completes Section 13.06).

Short answer 1
Which loop type does Python NOT provide at all, and what must be used instead?
Reveal answer

Python has no post-condition (REPEAT…UNTIL) loop — a pre-condition WHILE loop must be used instead.

Short answer 2
Why can a pre-condition (WHILE) loop run zero times, but a post-condition (REPEAT) loop cannot?
Reveal answer

WHILE checks its condition BEFORE the first pass, so if it's already false, the body never runs. REPEAT checks its condition AFTER the first pass, so the body always runs at least once regardless.

Fill in the blank 3
Python's range(s, e, i) stops BEFORE reaching ______ — this is a genuine, common trap when translating a pseudocode FOR loop.
Reveal answer

e (the end value).

Spot the error 4
A student translates pseudocode FOR i ← 1 TO 10 directly into for i in range(1, 10): in Python. What subtle bug has been introduced?
Reveal answer

The pseudocode loop runs from 1 UP TO AND INCLUDING 10 (10 iterations), but range(1, 10) stops BEFORE 10, only running 9 times (1 through 9). It should be range(1, 11) to correctly include 10.

Applied / scenario 5
You need to keep asking a user for input until they type "Y". Which loop type fits best, and why?
Reveal answer

A post-condition (REPEAT…UNTIL) loop — the user must be asked AT LEAST once, and the termination condition (typing "Y") depends on what happens inside the loop, not a known count.

Short answer 6
What must you ensure exists inside any conditional loop (REPEAT or WHILE), to avoid an infinite loop?
Reveal answer

A statement that will, at some point, change the value of the controlling condition — without this, the loop runs forever.
