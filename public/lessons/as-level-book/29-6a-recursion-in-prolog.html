29.08 Recursion in Prolog
A rule that uses itself as a sub-goal — the same base-case/general-case discipline as imperative recursion.
Theory

What recursion means for a rule

  • Recursion in declarative programming: a rule is defined by ITSELF — more precisely, a rule uses ITSELF as one of its own sub-goals.
  • The SAME discipline from Chapter 25 still applies: a recursive rule must have a BASE CASE, a GENERAL CASE, and must reach the base case after a FINITE number of self-calls.

Worked example — the "ancestor" rule

  • Building on the Family knowledge base: "A is an ancestor of B" needs to cover NOT just direct parents, but parents of parents, and so on, indefinitely.
% Base case: a parent IS an ancestor ancestor(A, B) :- parent(A, B). % General case: A is an ancestor of B if A is a parent of SOME X, % and X is (recursively) an ancestor of B ancestor(A, B) :- parent(A, X), ancestor(X, B).
  • The GENERAL case calls ancestor AGAIN — but on X, which is CLOSER to B in the family tree than A was — this satisfies the "must get closer to the base case" requirement, exactly like imperative recursion.

Worked example — factorial in Prolog

factorial(0, 1). % base case: 0! = 1 factorial(N, Result) :- M is N - 1, factorial(M, PartResult), % recursive call — closer to 0 Result is PartResult * N. ?- factorial(5, Answer). Answer = 120.
  • Compare this DIRECTLY to the imperative recursive version from Chapter 25 — the same base case / general case shape, just expressed in Prolog's clause syntax.
  • is performs ARITHMETIC evaluation and instantiation (e.g. M is N - 1) — different from plain =, which just tests/performs unification without arithmetic.
Practice — Test Yourself

These questions only cover what THIS subsection taught — recursion in Prolog (completes Section 29.08).

Short answer 1
What does it mean for a Prolog rule to be recursive?
Reveal answer

The rule uses itself as one of its own sub-goals within its body.

Short answer 2
What are the three rules a recursive Prolog rule must still satisfy, just like imperative recursion?
Reveal answer

It must have a base case, have a general case, and reach the base case after a finite number of calls to itself.

Fill in the blank 3
In the ancestor rule's general case, ancestor(A, B) :- parent(A, X), ancestor(X, B)., the recursive call uses ______ instead of A, moving closer to the base case.
Reveal answer

X.

Spot the error 4
A student writes factorial(N, Result) :- M is N - 1, factorial(N, PartResult), Result is PartResult * N. (calling factorial(N, ...) instead of factorial(M, ...)). What goes wrong?
Reveal answer

The recursive call never actually gets CLOSER to the base case (N is never reduced in the recursive call itself) — this would cause infinite recursion, since N stays the same value forever instead of counting down toward 0.

Applied / scenario 5
What is the base case of the factorial rule shown above?
Reveal answer

factorial(0, 1). — 0! = 1, stated explicitly with no recursive call needed.

Short answer 6
What does the "is" operator do in Prolog, that plain "=" does not?
Reveal answer

It performs arithmetic evaluation of the expression on its right-hand side, then instantiates the result — plain "=" just tests/performs unification, without evaluating arithmetic expressions.
