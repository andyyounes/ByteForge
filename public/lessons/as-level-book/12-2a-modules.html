12.02 Modules
Procedures do a job; functions do a job AND hand back one value.
Key Terms
Procedure
A sequence of steps given an identifier, called to perform a sub-task — no value is returned.
Function
A sequence of steps given an identifier, resulting in a single value RETURNED — called as part of an expression/assignment.
Local variable
A variable used only within a single module.
Global variable
A variable used throughout the whole solution.
Theory

Decomposing into modules

  • An alternative way to develop a solution: decompose the problem into SUB-TASKS. Each sub-task is a "module", refined separately.
  • Modules are either PROCEDURES or FUNCTIONS.
  • Module identifier naming follows the SAME rules as variable identifiers (Section 11.03).

Procedures — grouping steps under one name

CALL SetValues
  • Calling a procedure by name runs its whole sequence of steps.

Worked Example — the pyramid, rebuilt as four procedures

CALL SetValues REPEAT CALL OutputSpaces CALL OutputSymbols CALL AdjustValuesForNextRow UNTIL NumberOfSymbols > MaxNumberOfSymbols
  • The TOP-LEVEL solution becomes remarkably short and readable — it just calls four named procedures.
  • Each called procedure then needs its OWN full definition elsewhere (SetValues, InputMaxNumberOfSymbols, OutputSpaces, OutputSymbols, AdjustValuesForNextRow) — this is the exact same detailed pseudocode from Section 12.01, just now organised under names.

Functions — a procedure's cousin that hands back a value

  • A function performs a sequence of steps and returns a SINGLE value — it's called as part of an EXPRESSION or ASSIGNMENT, not as a standalone statement.
  • Example use case from a real game: a function that CHECKS whether a chosen column number is valid, returning TRUE or FALSE for use directly inside a condition.

Local vs. global variables — why the distinction matters

  • A LOCAL variable exists only WITHIN one module. A GLOBAL variable is usable throughout the entire solution.
  • Using local variables and parameters (rather than making everything global) keeps modules SELF-CONTAINED — changes to a variable inside one module then can't accidentally affect a variable's value somewhere else in the program.
Practice — Test Yourself

These questions only cover what THIS subsection taught — procedures, functions, and local/global variables (completes Section 12.02).

Short answer 1
What is the key difference between a procedure and a function?
Reveal answer

A function returns a single value and is used as part of an expression/assignment; a procedure performs a sequence of steps but does NOT return a value, and is called as a standalone statement.

Short answer 2
Why does breaking the pyramid solution into procedures make the TOP-LEVEL solution easier to read?
Reveal answer

The top level becomes a short sequence of named CALLs (SetValues, OutputSpaces, OutputSymbols, AdjustValuesForNextRow) — the reader immediately sees the overall shape of the solution without wading through every low-level detail at once.

Fill in the blank 3
A variable that exists only within ONE module is called a ______ variable; one usable throughout the whole solution is called a ______ variable.
Reveal answer

Local; global.

Spot the error 4
A student writes a function that checks whether a chosen column is valid, then calls it as a standalone statement: CALL ColumnNumberValid, ignoring its result entirely. What's wrong with this usage?
Reveal answer

A function's whole purpose is its RETURNED value — it should be used inside an expression or assignment (e.g. IF ColumnNumberValid(Col) THEN …), not called as a bare statement whose result is thrown away.

Applied / scenario 5
Why does using LOCAL variables (rather than making everything global) reduce bugs in a large program with many modules?
Reveal answer

Local variables keep each module self-contained — a change made to a variable INSIDE one module can't accidentally leak out and affect a variable's value used elsewhere in the program, unlike global variables which are visible (and modifiable) everywhere.

Short answer 6
What rule governs how a module identifier must be named?
Reveal answer

The same rules as variable identifiers (Section 11.03) — no spaces, only letters/digits/underscore, and the name should reflect the module's purpose.
