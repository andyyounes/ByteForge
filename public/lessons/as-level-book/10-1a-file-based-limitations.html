10.01 Limitations of a File-Based Approach
A theatrical agency's messy text file — every database concept in this chapter exists to fix one of its problems.
Key Terms
Data redundancy
The same data stored more than once.
Data dependency
A program's structure being tied to the exact way its data files are organised.
Theory

The running scenario for this whole chapter

  • A theatrical agency books bands for gigs. It stores band-member data in a text file: one line per member, containing name, contact details, banking details, band name, agent name, agent contact details.

What's actually wrong with this data — three genuinely different problems

  • "Graham Vandana" — the given/family names were entered in the WRONG ORDER originally, and a later correct entry was added WITHOUT deleting the wrong one. No validation technique could have caught this — it's a genuinely correct-LOOKING but wrong entry.
  • Dylan Stoddart's missing band name — THIS one validation genuinely could and should have caught (a simple presence check).
  • Precious Olsen appearing with TWO different bands — an example of duplication AND inconsistent data.
  • There's also an error not visible just from looking at the file: a band name could be entered here that doesn't actually correspond to any real, existing band.

Data privacy — a genuinely separate problem from data integrity

  • The SAME file was meant to serve two departments: finance (needs banking details) and recruitment (needs contact details).
  • The problem: a file has no way to control access to just PART of itself — so recruitment staff can also see banking details they have no need to see.
  • A database system properly handles this kind of access control; a plain file cannot.

Splitting into department files — solves privacy, creates data redundancy

  • To fix the privacy problem, the agency splits data into separate files per department — but department files inevitably OVERLAP in what they store (e.g. member names and band name needed by multiple departments).
  • This duplication across files is DATA REDUNDANCY — once data is stored, there's no NEED to store it again, yet here it's stored multiple times.
  • Redundancy causes DATA INCONSISTENCY when one copy is edited/corrected but another copy isn't — a different root cause of lost integrity than the original single-file errors.
  • One of the PRIMARY aims of the database approach: eliminating data redundancy.

Data dependency — the OTHER category of file-based problem

  • Traditionally, a programmer writes a program AND defines the data files it needs — the programmer must know exact file structure (e.g. "the fourth item on a line is a band name"). This tight coupling is DATA DEPENDENCY.
  • Consequence 1 — changing needs: if the agency wants to start storing data about session musicians, the EXISTING files must be rewritten, which then forces the EXISTING programs to also be rewritten. In a database, existing programs could keep running even as new data is added — only new programs handling the new data would be needed.
  • Consequence 2 — new applications: file structures designed for one specific program don't suit NEW applications. Building a new report analysing gig success over the years, from this file-based system, would be complex and slow.
Practice — Test Yourself

These questions only cover what THIS subsection taught — limitations of file-based systems (completes Section 10.01).

Short answer 1
Why couldn't validation have caught the "Graham Vandana" name-order error?
Reveal answer

"Graham" and "Vandana" are both perfectly valid-LOOKING names — the error is about which field they went into, not whether the data itself is a valid type/format. Validation can't detect a factually wrong but well-formed entry.

Short answer 2
What is data redundancy, and why is it a problem?
Reveal answer

The same data stored more than once. It's a problem because it can lead to data INCONSISTENCY — if one copy is corrected/edited but another copy isn't, the data no longer agrees with itself.

Fill in the blank 3
A programmer needing to know the EXACT structure of a data file (e.g. "the fourth item is a band name") is an example of data ______.
Reveal answer

Dependency.

Spot the error 4
A student says: "Splitting the file by department completely SOLVES the agency's data problems." What genuine NEW problem does this lesson say it creates?
Reveal answer

Data redundancy — the department files inevitably duplicate some of the same data (e.g. member names, band name) across multiple files, creating a new risk of inconsistency between the copies.

Applied / scenario 5
The agency wants to start tracking session musicians. In the file-based system, what TWO things does this force to happen, in order?
Reveal answer

First, the existing data files must be rewritten to hold the new data. Second, this forces the existing PROGRAMS that read those files to also be rewritten, since they depend on the exact old file structure.

Short answer 6
Why is extracting data for a brand-new report (e.g. gig success analysis) hard in a file-based system?
Reveal answer

The existing file structures were designed to suit the SPECIFIC programs that already use them — they aren't suited to supporting new applications, making extraction for a new purpose a complex, time-consuming task.
