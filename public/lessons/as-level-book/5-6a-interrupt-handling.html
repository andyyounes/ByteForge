5.06 Interrupt Handling
The processor only checks for interrupts at one precise moment — the end of a fetch-execute cycle. Completes Chapter 5.
Key Terms
Interrupt
A signal that requests the processor's attention, generated for reasons like errors, hardware faults, or I/O needs.
ISR
Interrupt Service Routine — the program that handles a specific interrupt.
Theory

Five example causes of an interrupt

  • A fatal error in a program.
  • A hardware fault.
  • A need for I/O processing to begin.
  • User interaction.
  • A timer signal.

Identifying WHICH interrupt has occurred

  • Different interrupts need different handling, and might have different PRIORITIES — so the processor needs a way to identify the interrupt TYPE.
  • One approach: an interrupt register in the CPU, working like the status register — each bit acts as a FLAG for a specific interrupt type.

WHEN interrupts get checked — only at one specific moment

  • The existence of an interrupt is only DETECTED at the END of a fetch-execute cycle — never mid-cycle.
  • This allows the currently running program to be interrupted and left in a well-DEFINED state that can be returned to later.

The interrupt-handling sequence, step by step

  1. Store the contents of the PC and any other relevant registers somewhere safe in memory.
  2. Load the START ADDRESS of the appropriate interrupt handler / Interrupt Service Routine (ISR) into the PC, so it begins executing.
  3. Once the ISR has finished, IMMEDIATELY check whether further interrupts need handling.
  4. If none remain, restore the safely-stored register contents back to the CPU, and RESUME the originally running program exactly where it left off.
Practice — Test Yourself

These questions only cover what THIS subsection taught — interrupt handling (completes Section 5.06 and Chapter 5).

Short answer 1
At exactly what point in the fetch-execute cycle is the existence of an interrupt detected?
Reveal answer

Only at the END of a fetch-execute cycle — never mid-cycle.

Short answer 2
What is the FIRST step in handling a detected interrupt?
Reveal answer

Store the contents of the program counter (and any other relevant registers) somewhere safe in memory.

Fill in the blank 3
To begin running an interrupt handler, its ______ address is loaded into the program counter.
Reveal answer

Start.

Spot the error 4
A student says: "As soon as an ISR finishes, the processor immediately resumes the original interrupted program." What step is being skipped?
Reveal answer

Immediately after an ISR finishes, the processor must first CHECK whether any FURTHER interrupts need handling. Only if none remain does it restore the saved register contents and resume the original program.

Applied / scenario 5
Why does detecting interrupts only at the END of a fetch-execute cycle (rather than at any random moment) matter for correctly resuming the interrupted program later?
Reveal answer

It ensures the interrupted program is left in a well-DEFINED, complete state (a whole instruction has just finished, nothing is half-executed) — making it possible to safely save its state and resume it correctly later.

Short answer 6
Describe one way the processor can identify WHICH type of interrupt has occurred.
Reveal answer

An interrupt register in the CPU, similar to the status register, where each individual bit acts as a flag for a specific interrupt type.
