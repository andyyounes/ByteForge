13.02 Programming Basics
From pseudocode DECLARE to real code — declarations, constants, assignment, arithmetic, I/O, and comments.
Theory

Declaring variables

  • Most languages require declaring a variable's TYPE, so the compiler reserves the right amount of memory. Pascal and VB.NET require declaration before use.
  • Python is different — it "tags" values rather than declaring types, so Python has NO variable declarations. Good practice is still to COMMENT what each variable will hold.
  • Pseudocode: DECLARE <identifier> : <dataType>
DECLARE Number1 : INTEGER DECLARE YourName : STRING DECLARE N1, N2, N3 : INTEGER // declares 3 integers at once

Constants — a name for a value that never changes

  • Pseudocode: CONSTANT <identifier> = <value>, e.g. CONSTANT Pi = 3.14.
  • In Python, constants are just ordinary assignment (PI = 3.14) — by CONVENTION written in ALL CAPITALS, but the value CAN technically still be changed; you should simply treat it as fixed.

Assignment — same idea as Chapter 11, now in real code

  • Pseudocode: <identifier> ← <expression>. In Python, the assignment operator is a plain =.
  • Python and VB.NET both allow shorthand increment: B += 1 instead of writing B = B + 1 out in full.

Rules of precedence

  • When an expression mixes operators, evaluation order follows: parentheses, exponentiation, multiplication, division, addition, subtraction.
  • Rules of precedence: define the order calculations are performed in — e.g. 4 * 3 - 3^2 ≠ (4 * 3 - 3)^2 ≠ 4 * (3 - 3^2), three genuinely different results from the same numbers.

Output — mixing strings and variables in one statement

  • Pseudocode: OUTPUT <string> or OUTPUT <identifier(s)> — a "print list" can mix literal strings and variable values, separated by commas.
  • Python: print(<printlist>) — items separated by commas; add end='' to avoid moving to a new line afterwards.
OUTPUT "Hello", YourName, ". Your number is", Number1 // newline OUTPUT "Hello" // no new line

Input — always prompt the user

  • Pseudocode: INPUT "Prompt: " A — note the SPACE between the colon and closing quote, giving a visual gap before the user types.
  • Python: the prompt is passed directly as a parameter to input(), e.g. A = input("Prompt: ").
  • Important: input is ALWAYS returned as a string in Python — converting to a number (if needed) requires a separate function (Section 13.08).

Comments

  • Good practice to explain code where necessary. Python uses # for a comment.
Practice — Test Yourself

These questions only cover what THIS subsection taught — declarations, constants, assignment, arithmetic, I/O and comments (completes Section 13.02).

Short answer 1
Why does Python not require variable declarations, unlike Pascal or VB.NET?
Reveal answer

Python "tags" values rather than requiring a variable's type to be fixed in advance — the type is associated with the VALUE, not permanently declared for the variable name.

Short answer 2
What data type does Python's input() function always return, regardless of what the user typed?
Reveal answer

A string — even if the user types a number, it must be separately converted to use it in a calculation.

Fill in the blank 3
In pseudocode, integer division uses the keyword ______, and getting the remainder uses the keyword ______.
Reveal answer

DIV; MOD.

Spot the error 4
A student writes a Python "constant": pi = 3.14 in lowercase. What convention have they missed, and does it actually stop the value being changed?
Reveal answer

Python convention writes constant identifiers in ALL CAPITALS (e.g. PI) — but even correctly capitalised, Python doesn't technically PREVENT the value being reassigned later; it's purely a convention signalling "treat this as fixed".

Applied / scenario 5
Evaluate 4 * 3 - 3 ^ 2 following the correct rules of precedence.
Reveal answer

3^2 = 9 first (exponent before multiplication), then 4*3 = 12 (multiplication before subtraction), then 12 - 9 = 3.

Short answer 6
Why does the pseudocode INPUT "Prompt: " A deliberately include a space before the closing quote?
Reveal answer

So there's a visible gap between the prompt text and whatever the user types next, rather than their input running directly up against the colon.
