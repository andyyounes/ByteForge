6.01 Machine Code Instructions
Every instruction the CPU actually runs splits neatly into an opcode and an operand.
Key Terms
Machine code instruction
A binary code with a defined number of bits, comprising an opcode and (most often) one operand.
Theory

Machine code is the ONLY language the CPU truly understands

  • When an instruction is fetched from memory, it must already be in the exact binary format matching that specific CPU's machine code.
  • Different processors have DIFFERENT instruction sets. Even where two processors share an instruction NAME, the actual machine code binary will differ — though the overall STRUCTURE of the code tends to be similar across processors.

Four things defined for every machine code instruction on a given processor

  • The total number of bits/bytes for the whole instruction.
  • The number of bits that define the opcode.
  • The number of operands defined in the remaining bits.
  • Whether the opcode occupies the MOST significant or LEAST significant bits.
  • In general, up to THREE operands are possible — but this course's simple system uses only ONE or ZERO operands.

A concrete simple instruction format — 8-bit opcode, 16-bit operand

  • Opcode: 4 bits for the OPERATION, 2 bits for the ADDRESS MODE (Section 6.03), 2 bits for REGISTER addressing.
  • This allows 16 different operations, each with one of 4 addressing modes.
  • The opcode occupies the MOST significant bits of the instruction.
  • The operand gets 16 bits — matching the 16-bit address bus, since the operand is often a memory address.

Register transfer notation needs a small extension for this

  • Because an instruction now has TWO components (opcode + operand), RTN needs to be able to refer to just PART of a register's contents.
  • Example: CU ← [CIR(23:16)] means only bits 16 to 23 of the CIR's content are transferred to the control unit — bits 0 to 15 aren't needed for this particular step.
Practice — Test Yourself

These questions only cover what THIS subsection taught — machine code instruction structure (completes Section 6.01).

Short answer 1
What are the two main parts a machine code instruction is split into?
Reveal answer

An opcode and an operand.

Short answer 2
In the example 8-bit opcode format, how many bits are used for the operation, and how many operations does this allow?
Reveal answer

4 bits for the operation, allowing 16 (2⁴) different operations.

Fill in the blank 3
CU ← [CIR(23:16)] means only bits ______ to ______ of the CIR's content are transferred to the control unit.
Reveal answer

16; 23.

Spot the error 4
A student says: "Since two different processors both have an ADD instruction, the actual binary machine code for ADD must be identical on both." What's wrong?
Reveal answer

Even where the instruction NAME/concept matches, the actual binary machine code will genuinely differ between different processors — only the overall STRUCTURE tends to be similar, not the exact bit patterns.

Applied / scenario 5
Why is the operand given a full 16 bits in this simple instruction format, matching the address bus width from Chapter 5?
Reveal answer

Because the operand will often BE a memory address, so it needs to be wide enough to specify any of the addressable memory locations — matching the 16-bit address bus keeps this consistent.

Short answer 6
How many operands does a machine code instruction have in the simplified system used throughout this course?
Reveal answer

Either one or zero (even though real processors can allow up to three).
