23.08 Hash Tables
Calculating an array address directly from a record's key, and handling collisions with open hashing.
Theory

The core idea

  • Calculate an ADDRESS (array index) directly from a record's KEY value, and store the record there. To find it again, recalculate the SAME address from the key.
  • Calculating an address from a key is called HASHING.

Collisions

  • Finding a hash function that gives every possible key a UNIQUE address is very hard in general. When two DIFFERENT keys hash to the SAME address, that's a COLLISION.
  • Three main ways to resolve collisions: CHAINING (a linked list starting at the hashed address for every colliding record), CLOSED HASHING (all collisions stored in a separate OVERFLOW area), OPEN HASHING (linear search from the hashed address to the next EMPTY slot).

Worked example — a simple hashing function

FUNCTION Hash(Key) RETURNS INTEGER Address ← Key MOD (n + 1) RETURN Address ENDFUNCTION // n = 9, so Index ← CustomerID MOD 10 // Customer IDs to store: 45876, 32390, 95312, 64636, 23467 // 45876 MOD 10 = 6 → slot 6 // 32390 MOD 10 = 0 → slot 0 // 95312 MOD 10 = 2 → slot 2 // 64636 MOD 10 = 6 → COLLISION with 45876! → next available slot (7) // 23467 MOD 10 = 7 → COLLISION with 64636's new slot! → next available slot (8)
  • This resolves collisions using OPEN HASHING — each colliding record moves to the next empty slot found by a linear search.
  • When SEARCHING later, an unoccupied slot encountered along that same linear path tells you the record does NOT exist in the table.

Inserting into a hash table (open hashing, pseudocode)

PROCEDURE Insert(NewRecord) Index ← Hash(NewRecord.Key) WHILE HashTable[Index] NOT empty Index ← Index + 1 IF Index > Max THEN Index ← 1 // wrap around to the beginning ENDIF ENDWHILE HashTable[Index] ← NewRecord END PROCEDURE

Finding a record (open hashing, pseudocode)

FUNCTION FindRecord(SearchKey) RETURNS Record Index ← Hash(SearchKey) WHILE (HashTable[Index].Key <> SearchKey) AND (HashTable[Index] NOT empty) Index ← Index + 1 IF Index > Max THEN Index ← 0 ENDIF ENDWHILE IF HashTable[Index] NOT empty THEN RETURN HashTable[Index] ENDIF END FUNCTION
  • Both procedures follow the SAME linear path from the hashed address — this is essential: insertion and lookup must use identical logic, or records could never be found again.
Hashing: calculating an address from a key value.
Collision: when two different key values hash to the same address.
Practice — Test Yourself

These questions only cover what THIS subsection taught — hash tables, hashing, and collision resolution (completes Section 23.08).

Short answer 1
What is a collision in the context of a hash table?
Reveal answer

When two different key values hash to the same calculated address.

Short answer 2
Describe how open hashing resolves a collision.
Reveal answer

It performs a linear search forward from the hashed address until it finds an empty slot, and stores the colliding record there.

Fill in the blank 3
When searching for a record with open hashing, encountering an ______ slot along the linear search path means the record does not exist in the table.
Reveal answer

Empty (unoccupied).

Spot the error 4
A student's Insert procedure uses open hashing but their FindRecord function instead jumps straight to a DIFFERENT overflow area to search for collided records. What will go wrong?
Reveal answer

Insert and Find must use the EXACT SAME collision-resolution logic — if records are inserted via open hashing (linear search from the hashed address) but searched for using a different scheme (overflow area), records placed via collision resolution will never be found again.

Applied / scenario 5
Using the hash function Index ← CustomerID MOD 10, what slot does a customer with ID 78901 hash to?
Reveal answer

78901 MOD 10 = 1, so slot 1.

Short answer 6
Why does the Insert/FindRecord pseudocode wrap the index back to the start of the table once it goes past Max?
Reveal answer

So the linear search for an empty slot (or a matching record) can continue searching the WHOLE table, including slots near the beginning, rather than stopping artificially at the end of the array.
