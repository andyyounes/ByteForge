24.01 Decision Tables
Modelling every possible combination of conditions precisely — and simplifying away redundancy.
Theory

What a decision table is

  • A precise way of modelling logic: every possible COMBINATION of conditions is considered, alongside the ACTION required for each.
  • Structure: one ROW per condition, one row per possible ACTION, and one COLUMN for every possible combination of conditions. N conditions need 2ᴺ columns (2 conditions → 4 columns; 3 conditions → 8 columns).
Decision table: a precise way of modelling logic.

Worked example — exam grading

  • Rule: ≥90 marks → distinction; <20 marks → fail; otherwise → pass.
Col 1Col 2Col 3Col 4
≥ 90 marksYYNN
< 20 marksYNYN
Distinction—X
Pass—X
Fail—X
  • Y=true, N=false, X=this action is performed. A DASH means the combination is IMPOSSIBLE or irrelevant (a student can't have both ≥90 and <20 marks at once).

Finding and removing redundancy

  • The real power of decision tables shows up with MORE complex conditions. Inspecting the action rows can reveal that some conditions are actually IRRELEVANT to a particular action — these can be replaced with a DASH ("don't care").
  • Worked example: an online store — free delivery needs ALL THREE conditions true (order>$50, small package, promo code) — no redundancy there. But the "$5 charge" applies whenever order value is NOT over $50, REGARDLESS of the other two conditions — those become dashes, simplifying 4 columns down to effectively 1 rule.
  • Simplifying the table also SIMPLIFIES the resulting program code — fewer distinct cases to actually test for.

Why this matters beyond design

  • Decision tables define expected OUTPUTS for given INPUTS — making them a natural basis for TEST DATA when testing a program (Chapter 15).
Practice — Test Yourself

These questions only cover what THIS subsection taught — decision tables and simplification (completes Section 24.01).

Short answer 1
How many columns does a decision table need for 3 independent conditions?
Reveal answer

8 (2³, one column for every possible true/false combination).

Short answer 2
What does a dash ("don't care" symbol) in a decision table cell mean?
Reveal answer

The condition can be either true or false — it makes no difference to the resulting action, so it's been simplified away, or the combination is impossible.

Fill in the blank 3
Simplifying a decision table by removing redundant conditions also ______ the resulting program code.
Reveal answer

Simplifies.

Spot the error 4
A student builds a decision table for "≥90 marks" and "<20 marks" and fills in an X for BOTH distinction and fail in the same column where both conditions are Y. What's wrong?
Reveal answer

That combination (≥90 AND <20) is logically IMPOSSIBLE — a mark can't be both at least 90 and less than 20 simultaneously. That column should be marked with a dash for both conditions, not have any action filled in.

Applied / scenario 5
In the delivery-charge example, why does the "$5 charge" action allow every OTHER condition to be dashed out, once "order value over $50" is false?
Reveal answer

The rule states the $5 (standard) charge applies whenever the order is NOT over $50 — regardless of package size or promotion code, meaning those two conditions have no bearing on this particular action, making them safe to dash out.

Short answer 6
Besides program design, what else can a decision table be used as a basis for?
Reveal answer

Test data — since it defines exactly which outputs are expected for which combinations of inputs.
