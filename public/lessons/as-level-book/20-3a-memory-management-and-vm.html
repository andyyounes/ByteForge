20.03–20.04 Memory Management & Virtual Machines
Partitioning, paging, virtual memory, and the very different concept of a virtual machine.
Theory

Partitioning and paging

  • PARTITIONING: memory is divided into partitions, aiming to load a whole process into ONE partition. DYNAMIC partitioning matches partition size to process size.
  • SEGMENTATION: an extension — larger processes are split into segments, each loaded into its own dynamic partition.
  • PAGING: the process is divided into EQUAL-sized pages, and memory into FRAMES of the same size — with this method, ALL pages are loaded into memory at once.

Virtual memory — paging without loading everything

  • The most flexible approach: paging-based, but WITHOUT requiring all pages to be in memory simultaneously.
  • The CPU's usable address space becomes LARGER than physical main memory — a memory management unit translates CPU addresses to actual page locations.
Virtual memory: a paging mechanism that allows a program to use more memory addresses than are available in main memory.
  • Pages start on DISK. As a process becomes ready, one or more of its pages load into memory. During execution, if a needed page isn't in memory, another page must first be REMOVED to make room — this needs a PAGE REPLACEMENT algorithm.
  • Simple option: FIRST-IN FIRST-OUT. Better option: LEAST-RECENTLY-USED — but this requires tracking usage statistics.

Virtual memory's advantages and the "disk thrashing" risk

  • ADVANTAGE 1: a very large program can run even without an equally large amount of physical memory available.
  • ADVANTAGE 2: only PART of a program needs to be resident at once — e.g. a database's index tables could stay permanently in memory while the full tables load only when actually needed.
  • DISADVANTAGE: system overhead. The worst case is DISK THRASHING — a page is removed, but is needed again almost immediately, causing near-constant loading/unloading cycles. Algorithms guard against this, but it can still occur (rarely).

Virtual machines — a completely different concept

  • IMPORTANT: virtual memory and a virtual MACHINE are unrelated concepts — don't confuse them. (The Java virtual machine, from Chapter 7, is yet another different underlying concept again.)
  • A process on a virtual machine interacts with a SOFTWARE interface provided by the OS — this interface presents an EXACT copy of the underlying hardware. The kernel handles all REAL interactions with the actual host hardware.
  • ADVANTAGE 1: multiple DIFFERENT operating systems can run on one physical computer — valuable for keeping legacy software running without keeping aged physical hardware.
  • ADVANTAGE 2: the SAME operating system can be made available many times over — used by mainframe companies offering SERVER CONSOLIDATION, giving different client companies their own isolated virtual server.
  • DRAWBACKS: significant implementation time/effort, and REDUCED performance compared to running directly on real hardware.
Practice — Test Yourself

These questions only cover what THIS subsection taught — memory management techniques, virtual memory, and virtual machines (completes Sections 20.03–20.04).

Short answer 1
What is disk thrashing?
Reveal answer

A situation in virtual memory where a page is removed from memory but needed again almost immediately, leading to near-constant loading and unloading of pages — severely hurting performance.

Short answer 2
Why must virtual memory and a virtual machine never be confused, despite the similar name?
Reveal answer

They are completely different concepts — virtual memory is a memory-management technique letting a program use more addresses than physical RAM provides; a virtual machine is a software interface presenting a complete simulated copy of hardware, potentially running its own separate operating system.

Fill in the blank 3
In paging, a process is divided into equal-sized ______, and memory is divided into equal-sized ______.
Reveal answer

Pages; frames.

Spot the error 4
A student says virtual memory lets a program actually access more PHYSICAL RAM than the computer has installed. What's the misunderstanding?
Reveal answer

Virtual memory gives the CPU a larger ADDRESS SPACE to work with, not more physical RAM — pages not currently needed are simply kept on disk and swapped in only when required. The actual amount of installed RAM is unchanged.

Applied / scenario 5
Why would a mainframe company use a virtual machine setup to offer "server consolidation" to multiple client companies?
Reveal answer

Each client can be given their own isolated virtual server (running the same OS, or even different ones) on shared physical hardware — far more cost-effective than dedicating a separate physical machine to each client.

Short answer 6
Between first-in-first-out and least-recently-used page replacement, which is generally more effective, and what does it require?
Reveal answer

Least-recently-used is generally more effective, but it requires tracking usage statistics for each page — extra overhead that FIFO doesn't need.
