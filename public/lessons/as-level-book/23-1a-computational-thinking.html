23.01 What Is Computational Thinking?
Abstraction, decomposition, data modelling, pattern recognition, and algorithm design.
Theory

The formal definition

  • Computational thinking is a PROBLEM-SOLVING PROCESS: reaching a solution through a number of deliberate steps, rather than relying on rote learning to draw conclusions without examining them.
  • It's built from FIVE components: abstraction, decomposition, data modelling, pattern recognition, and algorithm design.

Abstraction — filtering out the irrelevant

  • Filtering out information NOT necessary to solving the problem at hand.
  • Example: the London Underground map shows only STATIONS and which LINES connect them — not the geographical accuracy of the tracks, not the streets above ground. Only what's needed to plan a journey is kept.
  • Abstraction gives us the power to deal with complexity. An ALGORITHM is itself an abstraction of a process (inputs → steps → outputs); an ABSTRACT DATA TYPE defines an abstract set of values and operations, without specifying implementation detail.

Decomposition — breaking tasks into smaller parts

  • Another name for STEPWISE REFINEMENT (Chapter 12) — breaking a task down to explain a process more clearly.
  • This is exactly what leads to structured programming with procedures and functions taking PARAMETERS (Chapter 14).

Data modelling — analysing and organising data

  • Includes choosing appropriate data types (simple types like integer/character/Boolean; composite types like STRING), and structures (1D arrays for linear lists, 2D arrays for tables/matrices, text files, database tables from Chapter 10).
  • Extends further: abstract data types model real-world concepts like records, queues, or stacks (this chapter); object-oriented CLASSES model data (Chapter 27); facts and rules model data (Chapter 29); random files are another modelling tool (Chapter 26).

Pattern recognition and algorithm design

  • PATTERN RECOGNITION: spotting common solutions to common problems and REUSING them — e.g. recognising a problem calls for a standard insertion sort or binary search, rather than reinventing a solution from scratch.
  • ALGORITHM DESIGN: developing step-by-step instructions to solve a problem (Chapter 11).
Practice — Test Yourself

These questions only cover what THIS subsection taught — the five components of computational thinking (completes Section 23.01).

Short answer 1
What is abstraction, in the context of computational thinking?
Reveal answer

Filtering out information that is not necessary to solving the problem at hand, so that only the essential details remain.

Short answer 2
What is decomposition another name for, as covered in an earlier chapter?
Reveal answer

Stepwise refinement (Chapter 12).

Fill in the blank 3
Computational thinking has five components: abstraction, decomposition, data modelling, ______ recognition, and algorithm design.
Reveal answer

Pattern.

Spot the error 4
A student says the London Underground map is "just a badly-drawn version of the real geography, showing streets and tracks inaccurately". What's actually going on?
Reveal answer

The map is a deliberate ABSTRACTION — it intentionally leaves out geographical accuracy and street-level detail because that information isn't needed for planning a journey between stations. It's not "badly drawn"; it's precisely filtered to the essential information.

Applied / scenario 5
A programmer recognises that a new problem is essentially "find an item quickly in a large sorted list" and reaches straight for a binary search rather than designing a new algorithm from scratch. Which computational thinking component is this?
Reveal answer

Pattern recognition — spotting that this is a common, standard problem type with a known, efficient solution already available.

Short answer 6
What is an abstract data type an example of, within computational thinking?
Reveal answer

Both abstraction (it defines values and operations abstractly, without specifying implementation) and data modelling (it models a real-world concept like a queue or stack).
