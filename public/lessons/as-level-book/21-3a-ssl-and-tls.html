21.03 SSL and TLS
How HTTPS actually secures a connection — an extra layer slotted into the TCP/IP stack.
Theory

Where SSL/TLS sits

  • SSL (Secure Socket Layer) and TLS (Transport Layer Security) are CLOSELY RELATED protocols — TLS is a slightly modified, more modern version of SSL.
  • Recall from Chapter 17: the interface between an application and TCP uses a PORT NUMBER; an IP address + port number together form a "SOCKET".
  • SSL functions as an ADDITIONAL LAYER, sitting between TCP (transport layer) and the application layer.
  • When SSL is active, HTTP becomes HTTPS. Despite being called "a protocol", SSL is actually a whole PROTOCOL SUITE.

How an SSL session is set up

  • 1. TCP first establishes a normal connection between client and server.
  • 2. The HANDSHAKE PROTOCOL (part of the SSL suite) creates a SESSION allowing client and server to communicate securely.
  • 3. During the handshake, client and server AGREE which encryption algorithm(s) to use, and establish the SESSION KEYS — this exchange may involve checking DIGITAL CERTIFICATES.
  • 4. For the actual transmission, SSL provides ENCRYPTION, COMPRESSION, and INTEGRITY CHECKING.
  • 5. When the transmission finishes, the session CLOSES and all records of that session's encryption are discarded.

Why this matters in practice

  • An HTTPS application can GUARANTEE secure communication — letting users safely send confidential data (e.g. credit card details in an e-commerce transaction).
  • Crucially, the USER remains completely UNAWARE of all this happening — the whole encryption/certificate/session process is invisible, yet still delivers confidentiality and integrity.
Socket: the combination of an IP address and a port number, identifying a specific communication endpoint.
Practice — Test Yourself

These questions only cover what THIS subsection taught — SSL/TLS and how they secure HTTPS (completes Section 21.03).

Short answer 1
Where does SSL sit in relation to TCP and the application layer?
Reveal answer

As an additional layer sitting BETWEEN TCP (transport layer) and the application layer.

Short answer 2
What is the role of the Handshake Protocol at the start of an SSL connection?
Reveal answer

It creates a session allowing the client and server to communicate, during which they agree on encryption algorithms and establish the session keys to be used.

Fill in the blank 3
A socket is the combination of an ______ and a ______ number.
Reveal answer

IP address; port.

Spot the error 4
A student says "SSL is a single protocol, just like HTTP or FTP". What's the correction?
Reveal answer

Despite the name, SSL is actually a PROTOCOL SUITE — a collection of related protocols (including the Handshake Protocol) working together, not a single protocol.

Applied / scenario 5
Why does a user shopping on an HTTPS website not need to understand anything about certificates or session keys?
Reveal answer

The entire handshake, certificate-checking, and encryption process happens automatically behind the scenes — the browser and server handle it all, so the user experiences secure communication transparently, without needing any technical involvement.

Short answer 6
What happens to the session's encryption records once a transmission using SSL is complete?
Reveal answer

The session is closed and all records of that session's encryption disappear.
