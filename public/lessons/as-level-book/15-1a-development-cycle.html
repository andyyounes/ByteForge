15.01 Stages in the Program Development Cycle
From specification to execution — the full journey from problem to working program.
Theory

Problem solving

  • The first step is to define the problem clearly — usually in structured English, known as a SPECIFICATION.
  • Next, plan a solution — there may be more than one possible approach, and you must decide which is most appropriate.
  • Choose HOW to solve the problem: BOTTOM-UP (start with a small sub-problem and build on it) or TOP-DOWN (stepwise refinement using pseudocode, flowcharts, or structure charts — see Chapter 12).

Design

  • An identifier table is a good starting point (Chapter 11) — it leads you to think about data structures: do you need a 1D or 2D array? Do you need a file for long-term storage?
  • Plan your algorithm by drawing a flowchart or writing pseudocode.

Coding

  • Choose a suitable high-level programming language, weighing up the pros and cons of each one you know (Chapter 13).
  • Implement your algorithm by converting pseudocode into program code, ideally using a helpful editor (features covered in Section 15.02).
  • A SYNTAX ERROR is a "grammatical" error — a program statement that doesn't follow the rules of the language's constructs. Some editors flag these as you type.
Syntax error: an error in which a program statement does not follow the rules of the language.

Translation

  • Some syntax errors only become apparent when an interpreter or compiler translates the program.
  • A program that COMPILES successfully has NO syntax errors remaining.
  • An INTERPRETED program is different: only statements about to be executed are checked. If the program hasn't been thoroughly tested, syntax errors may still be lurking in code paths that haven't run yet.

Execution and testing

  • Once the program compiles, you can execute it. It may 'crash' (stop working) — this requires debugging.
  • Getting output at all is the "Eureka moment" — but does the program do what it was actually MEANT to do? Only thorough TESTING (Sections 15.03–15.05) can confirm this.
Practice — Test Yourself

These questions only cover what THIS subsection taught — the stages of the program development cycle (completes Section 15.01).

Short answer 1
What is the difference between the bottom-up and top-down approaches to solving a problem?
Reveal answer

Bottom-up starts with a small sub-problem and builds outward from it. Top-down uses stepwise refinement, breaking the overall problem down into smaller parts using pseudocode, flowcharts, or structure charts.

Short answer 2
What is a syntax error?
Reveal answer

An error in which a program statement does not follow the grammatical rules of the language's constructs.

Fill in the blank 3
A program that ______ successfully has no syntax errors remaining; but an ______ program only checks statements as they are about to be executed.
Reveal answer

Compiles; interpreted.

Spot the error 4
A programmer tests only the "happy path" of an interpreted program, sees no errors, and concludes it is bug-free. Why is this reasoning flawed?
Reveal answer

An interpreter only checks syntax for statements as they run — an untested code path (e.g. a rarely-taken ELSE branch) could still contain a syntax error that simply hasn't been reached yet.

Applied / scenario 5
Before writing any code, what document should clearly define exactly what a program is meant to do?
Reveal answer

A specification (usually written in structured English).

Short answer 6
Just because a program produces some output when run, does that mean it works correctly?
Reveal answer

No — getting output at all is only the "Eureka moment"; you still need thorough testing to confirm the program does what it was actually meant to do.
