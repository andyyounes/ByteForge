30.05–30.06 Preventing Errors & PERT Charts
Designing to avoid bugs in the first place, and mapping out a project's critical path.
Theory

Preventing errors before they happen

  • A major cause of errors: POOR REQUIREMENTS ANALYSIS — genuinely understanding the problem and what the user actually needs is essential BEFORE designing a solution.
  • Minimise errors by using: TRIED AND TESTED design techniques (structured programming, OOP design); CONVENTIONS (identifier tables, data structures, standard algorithms); and TESTED modules/objects from PROGRAM LIBRARIES rather than writing everything from scratch.

Project management — why it's needed

  • Large programs need MILESTONES and a SCHEDULE, especially when working to a DEADLINE.
  • Commercial software involves MANY people: programmers, senior designers, testers, document writers, hardware engineers/installers — a PROJECT MANAGER coordinates people, resources, and scheduling.
  • First task: break the project into individual ACTIVITIES, each taking a certain TIME, some only able to start once OTHERS finish.

PERT charts — finding the critical path

  • PERT (Program Evaluation and Review Technique) analyses the activities needed to complete a project, especially the TIME each takes, and identifies the MINIMUM time needed overall (critical path analysis).
  • A DELIVERABLE is the result of an activity (a document, report, or other building block). A MILESTONE is a scheduled event marking a deliverable's COMPLETION or submission.
Deliverable: the result of an activity, such as a document or a report.
Milestone: a scheduled event signifying the completion or submission of a deliverable.
Critical path: the longest possible continuous pathway from Start to Finish.

Reading a PERT chart

  • MILESTONES are numbered NODES. ACTIVITIES are ARROWS linking milestones, labelled with the activity code (below) and duration (above).
  • Solid arrows = DEPENDENT activities — must be completed IN SEQUENCE.
  • DOTTED lines = DUMMY activities — represent a sequencing REQUIREMENT with no resources or time of their own (e.g. "modules must be tested before installation begins" — but the TESTING time itself is accounted for elsewhere).

Worked example — the critical path

  • Given a project with paths through activities A through L, the CRITICAL PATH is the LONGEST continuous route from Start to Finish — e.g. A, B, C, E, F, G, K, L, totalling 20 weeks.
  • Any DELAY along the critical path delays the whole project's completion — activities NOT on the critical path have some "slack" and can run a little late without affecting the final deadline.
Practice — Test Yourself

These questions only cover what THIS subsection taught — error prevention and PERT charts (completes Sections 30.05–30.06 part 1).

Short answer 1
What is the critical path in a PERT chart?
Reveal answer

The longest possible continuous pathway from Start to Finish — it determines the minimum overall time needed to complete the project.

Short answer 2
What is a dummy activity, shown as a dotted line?
Reveal answer

An activity that represents a sequencing requirement but needs no resources or completion time of its own — its actual duration is accounted for on a different path.

Fill in the blank 3
A major cause of software errors is poor ______ analysis — not understanding the problem or what the user needs before designing a solution.
Reveal answer

Requirements.

Spot the error 4
A project manager says "any activity that finishes late will delay the whole project". Is this always true?
Reveal answer

No — only activities ON THE CRITICAL PATH directly delay the overall project if they run late. Activities not on the critical path have some slack time and can be delayed slightly without necessarily affecting the final completion date.

Applied / scenario 5
If the critical path total is 20 weeks and one activity ON that path takes 2 weeks longer than planned, what is the new minimum project completion time?
Reveal answer

22 weeks — any delay along the critical path directly extends the overall project completion time by the same amount.

Short answer 6
Name two conventions mentioned that help prevent programming errors.
Reveal answer

Any two of: identifier tables, standard data structures, standard algorithms (or: structured programming / OOP design, and using tested library modules).
