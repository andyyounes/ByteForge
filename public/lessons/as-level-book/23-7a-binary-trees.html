23.07 Binary Trees
A search structure where inserting a node never means moving any other node.
Theory

What makes a binary tree "binary"

  • Each node can have AT MOST TWO children — unlike a general family tree, which can have any number.
  • Terminology: the ROOT node is the top; a LEAF node has no children; each node's descendants split into a LEFT SUBTREE and a RIGHT SUBTREE.

Rule for adding a node to an ORDERED binary tree

Start at the root node as the current node. REPEAT IF new value > current node's value THEN follow the RIGHT branch IF new value < current node's value THEN follow the LEFT branch UNTIL the current node has no branch to follow in that direction. Add the new node in this position.
  • Worked example: adding value D to a tree rooted at F — D < F (turn left), D > C (turn right), D < E (turn left) — since E has no left child yet, D becomes E's new left child.

Why binary trees are useful as search trees

  • Just like binary search on a sorted array, a binary SEARCH TREE gives a FASTER search than a linear search or searching through a linked list.
  • Bonus advantage over a plain linked list: inserting a new node NEVER requires moving other nodes — only ONE pointer (left or right) needs setting to link the new node in.

Array-based implementation

  • Same idea as the linked list: an array of RECORDS, where each record represents a node holding its data PLUS a LeftPointer and a RightPointer.
  • Unused nodes are again tracked via a FREE LIST.
TYPE TreeNode DECLARE Data : STRING DECLARE LeftPointer : INTEGER DECLARE RightPointer : INTEGER ENDTYPE DECLARE RootPointer : INTEGER DECLARE FreePtr : INTEGER DECLARE Tree[1:7] OF TreeNode

Inserting and finding — following the same left/right rule

  • INSERT: take a node from the free list, set both its pointers to NULL, then walk down from the root following left/right comparisons exactly as before, remembering the LAST node visited and whether the final move was left or right — that determines which pointer field gets updated to link in the new node.
  • FIND: walk down from the root, comparing at each node and following LEFT or RIGHT accordingly, until either the item is found or a NULL pointer is reached (item not present).
Practice — Test Yourself

These questions only cover what THIS subsection taught — binary tree structure, insertion, and searching (completes Section 23.07).

Short answer 1
What is the maximum number of children a node in a binary tree can have?
Reveal answer

Two.

Short answer 2
When adding a new value to an ordered binary tree, which direction do you go if the new value is SMALLER than the current node's value?
Reveal answer

Left.

Fill in the blank 3
A node in a binary tree with no children is called a ______ node.
Reveal answer

Leaf.

Spot the error 4
A student says inserting into a binary search tree is exactly as costly as inserting into an array-based linear list. What's wrong?
Reveal answer

Inserting into a binary tree only needs ONE pointer updated to link in the new node — no other nodes move. Inserting into a linear (array-based) list may require shifting many existing items to make room, which is far more costly.

Applied / scenario 5
Starting at a root node with value M, trace the path to insert a new value G, given: G < M (go left) leads to node C; G > C (go right) leads to node K; G < K (go left) and K has no left child. Where is G inserted?
Reveal answer

G becomes the new LEFT child of node K.

Short answer 6
In the array implementation, what does each TreeNode record store, besides its own data?
Reveal answer

A LeftPointer and a RightPointer, linking to its left and right child nodes (or the null pointer if there is no child in that direction).
