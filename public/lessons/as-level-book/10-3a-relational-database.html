10.03 The Relational Database
Primary keys enforce entity integrity; foreign keys enforce referential integrity.
Key Terms
Relation
The special type of table used in a relational database.
Attribute
A column in a relation that contains values.
Primary key
An attribute (or combination) with a unique value in every tuple.
Foreign key
An attribute in one table that refers to the primary key in another table.
Theory

Naming and structure — where table definitions come from

  • A relational database is a collection of RELATIONS (a special type of table) — the odd name comes from mathematical theory.
  • When designing, a table gets a name with its attribute names listed in brackets, e.g. Member(MemberID, MemberGivenName, MemberFamilyName, BandName, …).
  • Each attribute maps to one column; a row is technically a TUPLE (though often loosely called a "record", with attribute values called "fields").
  • A tuple must be a set of ATOMIC values — each attribute holds exactly one value, or no value.

Primary keys — the most important relational feature

  • Every table MUST have a primary key; every tuple MUST have a unique value for it.
  • If an attribute's values are naturally guaranteed unique, it's a CANDIDATE key. If there's no natural candidate key, one must be CREATED (e.g. MemberID above — no natural attribute guarantees uniqueness for people, so an artificial ID is introduced).
  • The DBMS will REJECT any attempt to insert a duplicate primary key value — this is ENTITY INTEGRITY, one way the relational model directly enforces data integrity.
  • The primary key also gives a unique reference for whatever a query is selecting.

Foreign keys — linking tables, enforcing referential integrity

  • Most databases have MULTIPLE related tables — foreign keys implement these relationships.
  • Example: Band table is created first, with BandName as its primary key (guaranteed unique). Member table is created with MemberID as ITS primary key, and BandName as a FOREIGN KEY referencing Band's primary key.
  • Once this link exists, the DBMS will PREVENT any BandName value in Member that doesn't already exist in Band — this is REFERENTIAL INTEGRITY, another way the relational model enforces data integrity.
Practice — Test Yourself

These questions only cover what THIS subsection taught — relations, primary keys, and foreign keys (completes Section 10.03).

Short answer 1
What is the difference between a "candidate key" and a "primary key"?
Reveal answer

A candidate key is ANY attribute whose values are guaranteed unique. The primary key is the ONE candidate key actually CHOSEN to serve that role for the table (if multiple candidates exist).

Short answer 2
What does "entity integrity" mean, and which key enforces it?
Reveal answer

Every tuple is genuinely unique, because the DBMS refuses to allow a duplicate primary key value. The PRIMARY key enforces this.

Fill in the blank 3
A tuple must be a set of ______ values — each attribute has one value or no value.
Reveal answer

Atomic.

Spot the error 4
A student says: "MemberGivenName and MemberFamilyName together would make a fine primary key for the Member table, since together they identify a person." Why doesn't this hold up in general?
Reveal answer

Two DIFFERENT real people can share the same given name AND family name — the combination isn't GUARANTEED unique, which is exactly why the table introduces an artificial MemberID as the primary key instead.

Applied / scenario 5
Someone tries to insert a new Member row with BandName = "RockStars", but no "RockStars" row exists in the Band table. What happens, and why?
Reveal answer

The DBMS prevents the insertion — BandName is a foreign key referencing Band's primary key, and referential integrity means a foreign key value must already exist as a primary key value in the referenced table.

Short answer 6
What is the correct technical term for a "row" in a relation, even though "record" is often used loosely instead?
Reveal answer

A tuple.
