30.06 Gantt Charts
A visual schedule of every activity's start and end time. Completes Chapter 30 — and the entire AS & A Level Computer Science coursebook.
Theory

What a Gantt chart shows

  • A HORIZONTAL BAR CHART (developed by Henry Gantt) — a graphical schedule of a project's activities.
  • The HORIZONTAL axis represents TIME (days, weeks, or months, depending on the project's scale).
  • Each ACTIVITY gets its OWN ROW, shown as a horizontal BAR spanning its start-to-end time.

Overlapping and dependent activities

  • Activities CAN overlap — e.g. module testing can begin BEFORE all program code is finished; documentation can start before ALL testing is complete.
  • Other activities have a STRICT dependency — e.g. integration testing can only START once ALL modules have been successfully tested; installation only after integration testing succeeds.

Revising the schedule when things go wrong

  • If activities take LONGER than planned, the Gantt chart must be REVISED to reflect the new schedule.
  • Example: if ACCEPTANCE TESTING fails seriously, the plan may need to loop BACK — adding extra time for further design, coding, module testing, and integration testing, before re-attempting acceptance.

Gantt vs. PERT — complementary tools

  • PERT is best for identifying DEPENDENCIES and the CRITICAL PATH (the minimum overall time).
  • Gantt is best for VISUALISING the actual SCHEDULE — who's doing what, and WHEN, on a simple timeline that's easy to communicate to a whole team.
  • Project managers commonly use PERT FIRST to establish the critical path, THEN a Gantt chart to schedule the actual activities against a calendar.

Chapter 30 — and the coursebook — summary

  • Program generators and libraries speed up development by reusing tested tools and code.
  • Errors stem from coding mistakes, poor requirements, design flaws, bad UI design, or hardware failure — testing can reveal bugs but never prove their total absence.
  • Testing progresses from module-level dry-runs through integration, alpha, and (acceptance or beta) testing.
  • A rigorous test plan uses normal, abnormal, and boundary test data — never combining two conditions in one test.
  • Errors are best PREVENTED through good requirements analysis, tried-and-tested design techniques, and reusable libraries.
  • PERT charts find the critical path; Gantt charts visualise the schedule — together they support effective project management for large software developments.
Practice — Test Yourself

These questions cover Gantt charts and draw together the whole of Chapter 30 (completes Section 30.06 and Chapter 30 — the final chapter of the coursebook).

Short answer 1
What does the horizontal axis of a Gantt chart represent?
Reveal answer

Time — measured in whatever unit suits the project's scale (days, weeks, or months).

Short answer 2
Give an example of two activities that can overlap on a Gantt chart.
Reveal answer

Module testing can begin before all program code is written; documentation can start before all testing is complete.

Fill in the blank 3
PERT charts are best for finding the ______ path; Gantt charts are best for ______ the actual schedule.
Reveal answer

Critical; visualising.

Spot the error 4
A project manager plans integration testing to START before ALL individual modules have finished being tested. What problem does this create?
Reveal answer

Integration testing should only begin once module testing is FULLY complete — starting it early risks testing the interaction of modules that haven't yet been individually verified, potentially wasting effort chasing bugs that are actually still-untested module-level issues.

Applied / scenario 5
If acceptance testing fails and requires an extra week of design, two extra weeks of coding, and a week of re-testing, what should happen to the Gantt chart?
Reveal answer

It should be REVISED — the affected activity bars extended or new bars added to reflect the additional design, coding, and testing time, and all DEPENDENT activities (like installation) pushed back accordingly.

Short answer 6
Why might a project manager use BOTH a PERT chart and a Gantt chart, rather than just one?
Reveal answer

They serve complementary purposes — PERT reveals dependencies and the minimum possible project duration (critical path), while Gantt provides an easy-to-read visual timeline for scheduling and communicating progress to the team.
