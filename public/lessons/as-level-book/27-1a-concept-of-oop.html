A Level · Chapter 27 · Object-Oriented Programming (OOP)
27.01 Concept of OOP
Grouping data AND the code that operates on it into one unit: encapsulation, classes, and objects.
Theory

From records to objects

  • Procedural programming groups related STATEMENTS into subroutines, and groups related DATA into record structures — but keeps the two SEPARATE.
  • OOP goes one step further: it groups the DATA structure TOGETHER WITH the subroutines that operate on it. This combined group is called an OBJECT.
  • This combining of data with the subroutines that act on it is called ENCAPSULATION.
Encapsulation: combining data and subroutines into a class.
Class: a type that combines a record with the methods that operate on the properties in the record.

The problem with plain records

  • With a plain record, you CAN write a procedure to update a field properly (e.g. UpdateRegistration) — but nothing STOPS you from bypassing it and changing the field DIRECTLY: ThisCar.EngineSize ← 2500, with no validation at all.
  • OOP's classes fix this: attributes can ONLY be accessed through methods defined as part of the class — there is NO direct path to the data.

Private attributes, public methods

  • ATTRIBUTES (the data items of a class) are PRIVATE — inaccessible from outside the class.
  • METHODS (the subroutines of a class) are PUBLIC — made available for other code to call.
  • A CLASS is a TEMPLATE — once defined, it can be used to create one or more OBJECTS of that class type.
Attributes: the data items of a class.
Methods: the subroutines of a class.
Object: an instance of a class.

Why OOP produces more robust code

  • Because attributes can ONLY be changed via methods, they're PROTECTED from accidental/careless changes — validation logic can live in one place (the setter method) and is guaranteed to run every time.
  • Classes provided in tested MODULE LIBRARIES are already thoroughly verified — reusing them means you're building on TESTED foundations rather than writing everything from scratch, reducing the chance of introducing new bugs.
  • The syllabus-prescribed OOP languages are Python 3, VB.NET, and Delphi/Object Pascal.
Practice — Test Yourself

These questions only cover what THIS subsection taught — encapsulation, classes, objects, attributes, and methods (completes Section 27.01).

Short answer 1
What is encapsulation?
Reveal answer

Combining data (attributes) and the subroutines (methods) that operate on it into a single class.

Short answer 2
What is the relationship between a class and an object?
Reveal answer

A class is the template/blueprint; an object is one specific INSTANCE created from that template.

Fill in the blank 3
In OOP, attributes are declared ______, and methods are declared ______.
Reveal answer

Private; public.

Spot the error 4
A student writes a class but allows other code to directly write ThisCar.EngineSize = 2500, bypassing any method. What OOP principle has been broken?
Reveal answer

Encapsulation — attributes should be PRIVATE, accessible only through the class's own methods, so validation and controlled access can be enforced. Allowing direct field access defeats the whole purpose of encapsulation.

Applied / scenario 5
Why does reusing classes from a tested module library tend to reduce bugs, compared to writing equivalent code from scratch?
Reveal answer

Library classes have already been thoroughly tested by others — building on these verified foundations is less likely to introduce new bugs than writing and testing equivalent functionality yourself from the beginning.

Short answer 6
Name the three programming languages the syllabus prescribes for OOP.
Reveal answer

Python 3, VB.NET, and Delphi/Object Pascal.
