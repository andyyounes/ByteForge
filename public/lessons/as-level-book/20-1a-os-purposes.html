20.01 The Purposes of an Operating System
Resource management, user facilities, and how an OS is structured internally.
Theory

Getting the OS running in the first place

  • At power-on, there's no OS loaded — but ROM holds the BIOS (Basic Input Output System), which starts a BOOTSTRAP program.
  • The bootstrap program LOADS the operating system into memory and sets it running.
  • MULTI-PROGRAMMING: more than one program held in memory at once (only one accesses the CPU at any instant, others wait their turn) — for ONE user.
  • TIME-SHARING: a system designed for MANY users simultaneously logged in.

Two viewpoints on OS purpose

  • INTERNAL viewpoint: how the OS organises its activities to best use available resources.
  • EXTERNAL viewpoint: the facilities made available for actual system usage.

Resource management — the three fundamental resources

  • The CPU: managed via SCHEDULING for efficient usage.
  • Memory: managed for OPTIMUM usage of main memory.
  • The I/O system: covers not just direct user I/O, but also I/O to storage devices during program execution. Data can be routed via the CPU, or — for large quantities — transferred DIRECTLY between memory and an I/O device.

  • A GHz-speed CPU executes over a TRILLION clock cycles per second. I/O is dramatically slower than this — which is exactly why managing CPU usage during I/O waits is vital, so the CPU never sits idle unnecessarily.

What the OS provides for users

  • A USER INTERFACE (command line, graphical, or voice) letting the user interact with running programs.
  • DEVICE DRIVERS — the user just expects a connected device to "work", without needing to understand it.
  • A FILE SYSTEM — the user chooses filenames and organises folders, but never has to manage the physical layout of data on disk.
  • A PROGRAMMING ENVIRONMENT (for programmers) — letting a program be created and run without needing to understand processor internals.
  • SYSTEM CALLS — the interface a running program (itself a kind of "user") uses to request OS services, e.g. reading a file.
  • An APPLICATION PROGRAMMING INTERFACE (API) — a higher-level layer built on one or more system calls, aimed at giving programs PORTABILITY.

OS internal structure

  • USER MODE: available to ordinary users/applications. KERNEL MODE (or "privileged mode"): has sole access to certain protected memory and system functions user mode cannot reach.
  • The KERNEL runs at all times; the rest of the OS runs in user mode.
  • A LAYERED structure requires each higher layer to be fully serviced by the layer below (like a network protocol stack) — hard to achieve cleanly in practice.
  • A more flexible MODULAR structure lets the kernel call individual services only when needed — sometimes paired with a MICRO-KERNEL design, where the kernel itself is reduced to the absolute minimum.
Practice — Test Yourself

These questions only cover what THIS subsection taught — OS bootstrapping, resource management, user facilities, and structure (completes Section 20.01).

Short answer 1
What role does the bootstrap program play when a computer is switched on?
Reveal answer

It is started by the BIOS in ROM, and its job is to load the operating system into memory and set it running.

Short answer 2
What is the key difference between user mode and kernel mode?
Reveal answer

Kernel mode has sole access to certain protected memory and system functions that user mode cannot access — user mode is the restricted mode used by ordinary applications.

Fill in the blank 3
The three fundamental resources managed by an operating system are the ______, the ______, and the ______ system.
Reveal answer

CPU; memory; I/O (input/output).

Spot the error 4
A student says an API is just another name for a system call. What's the distinction being missed?
Reveal answer

An API call is a HIGHER-LEVEL, more specific function (e.g. "create a screen icon") that may internally use ONE OR MORE system calls to be fulfilled — an API sits above the raw system-call interface, aiming to give programs greater portability.

Applied / scenario 5
Why is managing CPU usage during I/O so critical, given the numbers in the data-rate table above?
Reveal answer

I/O devices operate orders of magnitude slower than the CPU's GHz clock — if the CPU simply waited idle for I/O to finish, it would waste enormous amounts of processing capacity; scheduling lets it do other useful work during those waits instead.

Short answer 6
What advantage does a modular OS structure have over a strict layered structure?
Reveal answer

A layered structure requires every higher layer to be fully serviced by the layer directly below it, which is hard to achieve cleanly in practice. A modular structure is more flexible — the kernel calls individual services only when actually needed, without a strict layering requirement.
