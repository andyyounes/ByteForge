20.05 Reverse Polish Notation (RPN)
Converting expressions to postfix form, and evaluating them with a stack. Completes Chapter 20.
Theory

Why RPN?

  • RPN (postfix) NEVER requires brackets and has NO precedence rules — a huge simplification for a compiler evaluating expressions, especially on processors with stack-handling instructions.

Converting infix to RPN by hand

a + b * c (precedence: convert b*c first) → a + "bc*" → "abc*+" (final RPN) (a + b) * c (brackets force + to happen first) → "ab+c*"

The shunting-yard algorithm — infix to RPN using a stack

  • Scan tokens left to right. IDENTIFIERS pass straight through to the RPN output.
  • OPERATORS: if the stack is empty or holds a LOWER-precedence operator, push the new operator onto the stack.
  • If the stack holds an EQUAL or HIGHER-precedence operator, POP it to the RPN output first, then push the new operator.
  • At the end, pop all remaining stack operators to the RPN output, one by one.
Infix remainingStackRPN output
a+b*c
+b*c+a
*c+ *ab
+abc*
abc*+
  • Had the expression instead been a * b + c, the * would be popped BEFORE + could ever be pushed, since + is NOT higher precedence than the * already on the stack.

Evaluating an RPN expression with a stack

  • Scan left to right. Push each VALUE onto the stack. When an OPERATOR is met, POP the top TWO values, apply the operator, and PUSH the result back.
RPN: x 2 * y 3 * + 6 / (x=3, y=4) Push 3, push 2 → stack: [3,2]. See *: pop 3,2 → 3*2=6 → push 6. Stack: [6] Push 4, push 3 → stack: [6,4,3]. See *: pop 4,3 → 4*3=12 → push 12. Stack: [6,12] See +: pop 6,12 → 6+12=18 → push 18. Stack: [18] Push 6 → stack: [18,6]. See /: pop 18,6 → 18/6=3 → push 3. Stack: [3] Result: 3

Why this matters for real compilers

  • RPN would be of little practical value on the very SIMPLE processor from Chapter 6 — but modern processors include STACK-HANDLING instructions, so a compiler can convert expressions to RPN knowing the resulting machine code can exploit efficient stack processing at execution time.

Chapter 20 summary

  • An OS manages CPU, memory, and I/O resources, and provides a user interface, file system, and APIs.
  • A process moves through five states: new, ready, running, waiting, terminated — controlled by long/medium/short-term schedulers.
  • Memory management ranges from partitioning through paging to virtual memory; a virtual MACHINE is an entirely separate concept.
  • A compiler's front end analyses (lexical, syntax, semantic) and generates intermediate code; the back end synthesises and optimises machine code.
  • BNF is a text-based, algorithm-friendly way to define a language's grammar.
  • RPN removes the need for brackets/precedence rules, enabling simple stack-based expression evaluation.
Practice — Test Yourself

These questions cover RPN conversion and evaluation, and draw together the whole of Chapter 20 (completes Section 20.05 and Chapter 20).

Short answer 1
What two things does RPN never require, unlike infix notation?
Reveal answer

Brackets, and rules of precedence.

Short answer 2
When evaluating an RPN expression with a stack and an operator token is encountered, what happens?
Reveal answer

The top two values are popped from the stack, the operator is applied to them, and the result is pushed back onto the stack.

Fill in the blank 3
In the shunting-yard algorithm, an operator is pushed onto the stack immediately only if the stack is empty or holds a ______ precedence operator.
Reveal answer

Lower.

Spot the error 4
Converting a * b + c with the shunting-yard algorithm, a student expects both * and + to end up on the stack together at some point. Why won't that happen?
Reveal answer

When + is encountered, the stack already holds * (higher precedence) — the rule requires popping * to the RPN output FIRST before + can be pushed, so they're never both on the stack simultaneously in this case.

Applied / scenario 5
Convert the infix expression a + b to RPN, and then convert the RPN expression a b + back to infix, to confirm they match.
Reveal answer

Both directions give the same pair: infix "a + b" ↔ RPN "a b +" — a single operator with two operands converts straightforwardly either way.

Short answer 6
Why is RPN of little practical value on the very simple processor described in Chapter 6, but valuable on modern processors?
Reveal answer

Modern processors include dedicated stack-handling instructions in their instruction set, letting compiled RPN expressions be evaluated efficiently via the stack — a simple processor without such instructions gains no such benefit.
