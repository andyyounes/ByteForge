1.02 Coding Signed Integers: Two's Complement
How a computer represents negative numbers — and why this specific scheme was chosen.
Key Terms
Sign and magnitude
Using one bit purely for +/- sign, the rest for the value — simple, but has real drawbacks.
One's complement
Every bit individually flipped (0↔1).
Two's complement
The one's complement PLUS 1 — the scheme real computers actually use for signed integers.
Theory

Unsigned vs. signed — the basic choice

  • An UNSIGNED integer is stored simply as a plain binary number — the only real decision is how many bytes to use. Two bytes (16 bits) gives a range of 0 to 2¹⁶−1 = 65535.
  • A SIGNED integer needs a way to represent both positive AND negative — the obvious idea (sign-and-magnitude: one bit for sign, the rest for value) has real problems, most notably TWO representations of zero (+0 and −0).

Two's complement — the scheme actually used

  • One's complement: flip every bit (each 0 becomes 1, each 1 becomes 0).
  • Two's complement: take the one's complement, then add 1.
  • Shortcut: starting from the LEAST significant bit, copy every bit unchanged up to and including the first 1 you hit; flip every bit AFTER that.
Worked example — two's complement of 10100100

From the right: the trailing "100" is copied unchanged (up to and including the first 1). The remaining bits "10100" get flipped to "01011".

Reading the comparison table — three real observations

  • Sign-and-magnitude has BOTH +0 and −0 — a genuine problem, since two different bit patterns are meant to mean the same value, complicating comparisons.
  • Two's complement has NO separate −0 — but gains an EXTRA negative value instead (−8 in this 4-bit example) that sign-and-magnitude can't represent at all.
  • Positive values are IDENTICAL in both schemes — only the negative encodings differ.
  • In two's complement, counting UP from the most negative value (adding 1 repeatedly) naturally rolls over from all-1s straight to all-0s — exactly like a real digital counter reaching its maximum and wrapping around.

The key property: two's complement is self-complementary

  • Taking the two's complement of a NEGATIVE number's code gives you the code for the corresponding POSITIVE number — and vice versa. Apply the exact same operation twice and you're back where you started.
Worked example — converting 10110001 (two's complement) to denary

Method 1 — flip to positive first: take the two's complement of 10110001: the trailing "1" stays, the rest "0110001" → wait, more precisely: copy the "1" (first 1 from the right) unchanged, flip everything before it: 10110001 → 01001111. That's binary for 79 (using double-and-add: 1→2→4→9→18→38→78→79... following the book's working). So the ORIGINAL number is −79.

Method 2 — treat the top bit as negative directly: −2⁷ + 2⁵ + 2⁴ + 2⁰ = −128 + 32 + 16 + 1 = −79. Same answer, without converting to positive first.

Why two's complement specifically — the real payoff

  • The whole point of choosing two's complement is that it makes SUBTRACTION trivial: subtracting one signed integer from another is done by converting the number being subtracted into its two's complement form, then simply ADDING.
  • This means a computer's hardware only needs to know how to ADD — subtraction is "free" once two's complement and addition both exist.
Practice — Test Yourself

These questions only cover what THIS subsection taught — sign-and-magnitude vs. two's complement.

Short answer 1
What is the key problem with sign-and-magnitude representation that two's complement avoids?
Reveal answer

Sign-and-magnitude has TWO representations of zero (+0 and −0), which complicates comparing values. Two's complement has only one representation of zero.

Short answer 2
What is the real, practical reason two's complement is used, beyond just representing negatives?
Reveal answer

It makes subtraction reduce to addition: to subtract B from A, convert B to its two's complement form and ADD it to A — hardware only needs to implement addition, not a separate subtraction circuit.

Fill in the blank pseudocode 3
Complete the shortcut method: copy bits unchanged from the right up to and including the first ______; flip every bit ______ that point.
Reveal answer

Copy unchanged up to and including the first 1; flip every bit AFTER (to the left of) that point.

Spot the error 4
A student claims 4-bit two's complement can represent the same RANGE of values as 4-bit sign-and-magnitude, just shifted. Using the table above, show this is false.
Reveal answer

Sign-and-magnitude (4 bits) represents −7 to +7 (15 distinct values, with two codes for zero). Two's complement (4 bits) represents −8 to +7 (16 distinct values, one code per value) — two's complement has an EXTRA representable value (−8) that sign-and-magnitude cannot represent at all, so the ranges are not simply "shifted" versions of each other.

Applied / scenario 5
Take the two's complement of the 4-bit binary code for −5 (1011) and confirm you get the code for +5.
Reveal answer

1011 → one's complement (flip all): 0100 → add 1: 0101, which is +5. Confirmed — two's complement is self-complementary.

Applied / scenario 6
Using one byte per value, subtract denary 35 from denary 67 using two's complement binary arithmetic (convert 35 to two's complement, then add it to 67's binary form).
Reveal answer

67 = 01000011. 35 = 00100011 → two's complement of 35 = 11011101. Adding: 01000011 + 11011101 = (1)00100000 — discard the overflow carry bit, leaving 00100000 = 32 in denary. 67 − 35 = 32. ✓
