2.1a Data Packets & Packet Switching
Why data is broken into packets before being sent, what's inside one, and how packets find their own way across a network.
Key Terms
Data packet
A small chunk (typically ~64 KiB) of a larger message, sent separately across a network. Also called a datagram.
Packet header
Contains sender/receiver IP addresses, sequence number, and packet size.
Payload
The actual data being sent inside the packet (~64 KiB).
Packet trailer
Marks the end of the packet and holds an error-checking value (a cyclic redundancy check, CRC).
Router
A network device that receives a packet and decides, from its header, where to send it next.
Packet switching
Sending a message as independently-routed packets that are reassembled at the destination.
Theory

Why data is split into packets

  • Data sent over long distances is usually broken into data packets (or "datagrams") — typically around 64 KiB each — since small packets are much easier to control than one long continuous stream.
  • Splitting data this way means each packet can travel a DIFFERENT route to the destination — a real benefit if one particular route is out of action or very busy.
  • The one clear drawback: the packets must be REASSEMBLED correctly once they all arrive.
Structure of one data packet: header → payload → trailer.

What's inside each part of a packet

  • Header contains: the sender's IP address, the receiver's IP address, the packet's sequence number (so packets can be reassembled in the correct order), and the packet size (so the receiver can check nothing's missing). It often also states the total number of packets in the transmission.
  • Payload is simply the actual data being carried — usually about 64 KiB.
  • Trailer contains a way of marking the packet's end (so packets can be separated from each other), plus an error-checking method — a cyclic redundancy check (CRC).
  • How CRC works: the sender adds up all the 1-bits in the payload and stores this as a hex value in the trailer. The receiver recalculates the same count on arrival and compares it to the stored value — if they match, no error occurred; if not, the packet must be re-sent.

Packet switching

  • Packet switching: a message is broken into packets, each sent INDEPENDENTLY from start to end point, then reassembled at the destination using the header's sequence information.
  • At each stage, a router receives a packet and decides — from the header — which way to send it next.
  • Routing selection depends on how many packets are already waiting at each node; the shortest AVAILABLE path is chosen (not necessarily the shortest path overall, since some routes may be too busy or unsuitable).
  • Because each packet can take a different route, packets can genuinely arrive at the destination in a DIFFERENT ORDER than they were sent — the receiver must reassemble them correctly using their sequence numbers.
  • Hopping (not on the syllabus, but useful for understanding): each packet starts with a maximum "hop number" in its header, reduced by 1 at every router it passes through. If the hop number hits zero before reaching the destination, the packet is deleted — preventing lost packets from endlessly bouncing around and clogging the network. The receiver then requests the missing packet be re-sent.
Benefits of packet switching
  • No single communication line is tied up
  • Failed, busy, or faulty lines can be avoided by re-routing
  • Easy to expand usage
  • High data transmission rate possible
Drawbacks of packet switching
  • Packets can be lost and need re-sending
  • More error-prone for real-time streaming (e.g. a live sports broadcast)
  • Delay at the destination while packets are re-ordered
Practice — Test Yourself

These questions only cover what THIS subsection taught — data packets and packet switching.

Short answer 1
Name the three parts of a data packet's structure, in order.
Reveal answer

Header, then payload, then trailer.

Short answer 2
Explain how a cyclic redundancy check (CRC) detects a transmission error.
Reveal answer

The sender counts all the 1-bits in the payload and stores this count (as hex) in the trailer. The receiver recalculates the same count when the packet arrives and compares it to the stored value — a mismatch means a transmission error occurred, and the packet must be re-sent.

Fill in the blank 3
A router decides where to send a packet next based on the information in its ______, and always selects the ______ available path.
Reveal answer

Blank 1: header. Blank 2: shortest (available).

Spot the error 4
A student claims: "Since packets always take the shortest path, they always arrive at the destination in the same order they were sent." What's wrong with this claim?
Reveal answer

Packets do NOT all take the same route — different packets can travel different paths depending on network congestion at each node — so they genuinely CAN arrive in a different order than they were sent. This is exactly why the header's sequence number is needed, to let the receiver reassemble them correctly.

Applied / scenario 5
A live sports broadcast is being streamed over the internet using packet switching, and viewers notice occasional freezing/stuttering. Using this lesson's content, explain why packet switching can cause this, and name one drawback of packet switching that's directly responsible.
Reveal answer

Packet switching is more prone to errors with real-time streaming — packets can be lost and need re-sending, and there's a genuine delay at the destination while out-of-order packets are reassembled. For a live broadcast, this delay/re-sending is exactly what causes the viewer-visible freezing or stuttering, since the video can't display until the correct packets have all arrived and been put back in order.

Short answer 6
What problem does "hopping" solve, and how does it solve it?
Reveal answer

Hopping prevents lost packets from endlessly bouncing between routers and clogging the network forever. Each packet gets a maximum hop number that's reduced by 1 at every router it passes through — once it hits zero without reaching the destination, the packet is deleted, and the receiver requests it be re-sent.
