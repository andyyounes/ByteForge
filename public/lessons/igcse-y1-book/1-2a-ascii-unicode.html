1.2a ASCII & Unicode
How a computer represents text as numbers, and why one character set alone isn't enough for the whole world.
Key Terms
ASCII
American Standard Code for Information Interchange — a 7-bit character set (0-127) for English letters, digits, and symbols, set up in 1963.
Extended ASCII
An 8-bit version of ASCII (0-255) — the extra 128 codes allow non-English characters and graphical symbols.
Unicode
A character set designed to represent every language in the world, using up to 4 bytes per character.
Character set
The complete list of characters a coding system can represent, each mapped to a unique binary/denary/hex code.
Theory

ASCII — the original standard

  • ASCII was set up in 1963 for communication and computer systems, with a newer version published in 1986.
  • Standard ASCII uses 7-bit codes — 0 to 127 in denary, or 00 to 7F in hex — covering the letters, numbers, and characters on a standard keyboard.
  • 32 of those codes (0-31 denary, 00-19 hex) are reserved control codes, not printable characters.
  • Character sets like a-z and 0-9 are deliberately grouped together in sequence, which makes them easier to work with programmatically.
Worked example — the uppercase/lowercase pattern
CharacterBinaryHexCase
a110000161lowercase
A100000141uppercase
y111100179lowercase
Y101100159uppercase

Notice: only the SIXTH bit ever changes (highlighted) between a letter's uppercase and lowercase version — a genuinely deliberate design choice that makes converting between cases an easy, fast operation.

Extended ASCII — filling in more characters

  • Extended ASCII uses 8-bit codes — 0 to 255 (00 to FF in hex) — giving 128 EXTRA codes beyond standard ASCII.
  • These extra codes were used for characters from non-English alphabets and some graphical characters.
  • A real limitation: different systems (e.g. DOS and Windows) sometimes used DIFFERENT characters for the SAME extended code — a genuine source of real compatibility problems.

Why ASCII wasn't enough — the case for Unicode

  • ASCII's biggest real limitation: it cannot represent characters from non-Western languages at all, e.g. Chinese characters.
  • The Unicode Consortium was set up in 1991 to solve this, with Version 1.0 having five real goals: a universal standard covering all languages/writing systems; a more efficient coding system than ASCII; uniform 16-bit or 32-bit encoding; unambiguous encoding (one code always means one character); and reserved space for private/custom characters (useful for e.g. Chinese and Japanese character sets).
  • ASCII uses ONE byte per character; Unicode can use up to FOUR bytes per character — genuinely more space, but enough to support thousands of characters from every language, including Russian, Romanian, and Croatian.
  • Unicode deliberately OVERLAPS with ASCII — the first 128 characters are identical — so existing ASCII text remains valid Unicode text too.
Practice — Test Yourself

These questions only cover what THIS subsection taught — ASCII and Unicode. Answer each one, then reveal the answer key to check.

Short answer 1
How many bits does STANDARD ASCII use per character, and what is the resulting denary range of codes?
Reveal answer

7 bits, giving a range of 0 to 127.

Short answer 2
Name TWO of Unicode's five original design goals from 1991.
Reveal answer

Any two of: a universal standard covering all languages/writing systems; a more efficient coding system than ASCII; uniform 16-bit or 32-bit encoding; unambiguous encoding; reserved space for private/custom characters.

Fill in the blank 3
Extended ASCII uses ______ bits per character, giving a denary range of 0 to ______.
Reveal answer

Blank 1: 8. Blank 2: 255.

Spot the error 4
A student claims: "Unicode completely replaced ASCII, so a text file saved in ASCII would no longer be valid once opened as Unicode." What real fact from this lesson does this claim get wrong?
Reveal answer

Unicode deliberately keeps the first 128 characters IDENTICAL to standard ASCII — there's genuine overlap, not a total replacement. This means an ASCII text file genuinely remains completely valid when read as Unicode; nothing about it breaks or changes.

Applied / scenario 5
A company builds a text-messaging app intended ONLY for English-speaking users in one country, prioritising the smallest possible file size per message. A separate global social media platform needs to support every world language. (a) Which character set is the better real choice for EACH app, and (b) why?
Reveal answer

(a) The English-only messaging app: ASCII (or Extended ASCII). The global platform: Unicode.

(b) ASCII uses only 1 byte per character, genuinely keeping message file sizes small — a real, deliberate trade-off that's fine ONLY because every character needed is covered by ASCII's limited character set. The global platform genuinely needs Unicode's much wider language support (up to 4 bytes per character) since its users need characters ASCII simply cannot represent at all.

Short answer 6
What real, deliberate design choice makes converting a letter between uppercase and lowercase in ASCII a fast, easy operation?
Reveal answer

Only ONE specific bit (the sixth bit) ever differs between a letter's uppercase and lowercase ASCII code — everything else stays the same, so converting case is genuinely just a single-bit flip, not a full recalculation.
