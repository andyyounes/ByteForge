1.1d Logical Binary Shifts
Shifting bits left or right — genuinely multiplying or dividing by 2 — and when a shift loses information.
Key Terms
Logical shift
Moving every bit in a binary number one or more places left or right within its register.
Most significant bit
The left-most bit in a binary number — the one worth the largest place value.
Least significant bit
The right-most bit in a binary number — the one worth the smallest place value (1).
Theory

What a logical shift actually does

  • A logical shift moves every bit in a register a fixed number of places left or right.
  • Each shift left is exactly equivalent to multiplying the binary number by 2.
  • Each shift right is exactly equivalent to dividing the binary number by 2.
  • As bits move, any position left empty is filled with a 0.
  • There's a real limit to how many shifts a register can perform correctly — eventually, real bits get pushed clean off the end of the register and are permanently lost.
Worked example — shifting left (multiplying)

The denary number 21 is 00010101 in an 8-bit register. Shift it ONE place left:

00010101 → shift left → 00101010

00101010 = 42 in denary — exactly 21 × 2¹. Shifting two places left gives 01010100 = 84 (21 × 2²); three places left gives 10101000 = 168 (21 × 2³).

When a left shift goes wrong

Shift the SAME original number, 00010101 (21), FOUR places left:

1286432168421
01010000

This gives 01010000 — but the real answer to 21 × 2⁴ (which is 336) genuinely needs more than 8 bits. The left-most 1-bit from the original number has been pushed clean off the register and lost — the register now holds an incorrect value, exactly the same kind of error as overflow in addition.

Worked example — shifting right (dividing)

The denary number 200 is 11001000. Shift it ONE place right:

11001000 → shift right → 01100100

01100100 = 100 in denary — exactly 200 ÷ 2¹. Two places right gives 00110010 = 50 (200 ÷ 2²); three places right gives 00011001 = 25 (200 ÷ 2³).

Shifting the same number a FOURTH place right loses the right-most 1-bit off the end of the register — the result (12) is wrong, since 200 ÷ 2⁴ is really 12.5, and the lost bit is the clear sign the shift has gone one step too far.

Practice — Test Yourself

These questions only cover what THIS subsection taught — logical binary shifts. Answer each one, then reveal the answer key to check.

Short answer 1
Write 24 as an 8-bit binary number, then show the result of shifting it 2 places LEFT. What denary value does the shifted result represent?
Reveal answer

24 = 00011000. Shifted 2 left: 01100000 = 96 (which is 24 × 2² = 96 — correct, no bits lost).

Short answer 2
Take the same 24 (00011000) and shift it 3 places to the RIGHT instead. What denary value results, and is it correct?
Reveal answer

00011000 shifted 3 right → 00000011 = 3, which IS correct (24 ÷ 2³ = 3, and no 1-bits were lost off the right-hand end).

Fill in the blank 3
Each shift to the left is equivalent to ______ the number by 2; each shift to the right is equivalent to ______ the number by 2.
Reveal answer

Blank 1: multiplying. Blank 2: dividing.

Spot the error 4
A student shifts 00010101 (21) four places left in an 8-bit register, gets 01010000 (80), and confidently states "21 × 2⁴ = 80, so this is correct." What's actually wrong with this conclusion?
Reveal answer

21 × 2⁴ is genuinely 336, not 80 — the student has mistaken a WRONG, bit-losing result for a correct one. The real left-most 1-bit was pushed off the register and lost during the shift, which is exactly why the 8-bit result (80) doesn't match the true mathematical answer (336). Getting a number back out doesn't automatically mean the shift was valid — it has to be checked against the real multiplication.

Applied / scenario 5
A programmer wants to quickly double a small number stored in an 8-bit register using a single left shift, instead of using a slower general multiplication instruction. (a) Which numbers, roughly, is this trick actually SAFE to use for? (b) Why does using it on a large starting value risk a wrong result?
Reveal answer

(a) It's safe for values where doubling still fits within 8 bits — genuinely, any starting value up to 127, since 127 × 2 = 254 still fits in an 8-bit register (max 255).

(b) For a starting value of 128 or more, doubling it would need a 9th bit — the most significant bit gets pushed off the register and lost, giving a wrong, smaller-than-expected result, the same overflow-style error covered in this lesson.

Short answer 6
When bits are shifted, what value fills the newly-empty position(s) left behind — and does this happen the same way for both a left shift and a right shift?
Reveal answer

A newly-empty position is always filled with a 0 — this is true for both directions: a left shift fills in new 0s on the right-hand end, and a right shift fills in new 0s on the left-hand end.
