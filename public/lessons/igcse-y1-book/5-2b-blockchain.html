5.2b Blockchain
Why changing ONE block breaks the whole chain — hash values, proof-of-work, and mining explained.
Key Terms
Blockchain
A decentralised database storing all networked members' transactions across many interconnected computers.
Hash value
A unique "fingerprint" generated for each block by a cryptographic algorithm (e.g. SHA-256).
Genesis block
The very first block in a chain — it points to no previous block.
Proof-of-work
A deliberately slow (~10 min) verification process required before a new block can be added.
Miners
Special network users who police proof-of-work and earn commission for each new block created.
Theory

What blockchain is

  • A DECENTRALISED database — all networked members' transactions are stored here, across interconnected computers with NO central server.
  • ALL transaction data is stored on ALL computers in the network. A new transaction is copied to EVERY networked computer, so it can't be changed without every network member's consent.
  • This removes major security risks like hacking. Used in: cryptocurrency exchanges, smart contracts, pharmaceutical research, politics, education.

What's inside a block

  • Data: e.g. sender/recipient names, amount transferred.
  • Hash value: a unique fingerprint generated by a cryptographic algorithm (usually SHA-256), including a TIMESTAMP.
  • Previous hash value: points BACK to the previous block in the chain — this is what actually links the chain together.
1
hash: A4BF
prev: 0000
2
hash: 6AB1
prev: A4BF
3
hash: 34EE
prev: 6AB1
4
hash: FF12
prev: 34EE
5
hash: AA00
prev: FF12
Block 1 is the "genesis block" (points to nothing). Each later block's "previous hash" must exactly match the block before it — this chain of matches is what makes tampering detectable.

Why the chain is so hard to tamper with

  • If block 2's DATA changes, its hash value CHANGES too (no longer 6AB1) — this instantly breaks the link, since block 3's "previous hash" field (still 6AB1) no longer matches.
  • Every block AFTER the tampered one becomes INVALID.
  • Real defence against a hacker "recreating" a new valid chain fast: proof-of-work — deliberately takes about 10 MINUTES to verify each new block before it's added. This is policed by miners (special users earning commission per new block), which slows the whole process down enough to foil attackers.
  • To successfully hack the blockchain, an attacker would need to attack EVERY SINGLE block in the chain SIMULTANEOUSLY — genuinely close to impossible.
  • When a new block is created, it's sent to EVERY networked computer and checked for correctness before being added. A new network user receives a copy of the ENTIRE blockchain.
Worked example — what happens if block 2 is hacked

Original chain: Block 1 → Block 2 (hash 6AB1) → Block 3 (previous hash 6AB1) → Block 4 → Block 5.

If a hacker changes Block 2's data, its hash value changes — it's no longer 6AB1. Now Block 3's "previous hash" (still 6AB1) doesn't match Block 2's NEW hash. The chain is broken between Block 2 and Block 3, and every block from 3 onwards becomes INVALID — instantly revealing the tampering.

Practice — Test Yourself

These questions only cover what THIS subsection taught — blockchain.

Short answer 1
What is the "genesis block"?
Reveal answer

The very first block in a blockchain — it doesn't point back to any previous block.

Short answer 2
What happens to a block's hash value if its data is changed?
Reveal answer

The hash value changes to a completely different value — this instantly breaks the link with the NEXT block, whose "previous hash" field no longer matches.

Fill in the blank 3
______ makes it deliberately take around ______ minutes to verify each new block before it can be added to the chain.
Reveal answer

Blank 1: Proof-of-work. Blank 2: 10.

Spot the error 4
A student claims: "A hacker just needs to change one block's hash to match its neighbour, and the whole chain would look valid again." What real defence from this lesson defeats this attempt?
Reveal answer

Even if a hacker recalculates one block's hash, they'd then need to recalculate EVERY subsequent block's hash too (since each links to the one before it) — and proof-of-work deliberately slows each block's creation to about 10 minutes, policed by miners. Attacking the whole chain fast enough to beat detection would require attacking every single block simultaneously, which is close to impossible.

Applied / scenario 5
A pharmaceutical research team wants a tamper-evident record of experimental data, shared across many collaborating institutions, where no single institution can secretly alter past results. Using this lesson's content, explain why blockchain is well-suited to this.
Reveal answer

The lesson explicitly lists research (particularly pharmaceutical) as a real blockchain use case. Since all transaction/data records are copied to EVERY networked computer, and altering a record breaks the hash chain for every block afterward, no single institution could secretly change past data without it being immediately detectable across the whole network — exactly the tamper-evidence the team needs.

Short answer 6
What role do "miners" play in a blockchain network?
Reveal answer

They police the proof-of-work process and receive a commission for each new block created — their role helps slow down and secure the process of adding new blocks to the chain.
