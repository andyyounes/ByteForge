4.2c Translators: Compilers, Interpreters & Assemblers
Three different ways to turn human-readable code into something the computer can actually run.
Key Terms
Translator
A utility program that converts human-written code into machine code.
Compiler
Translates an ENTIRE high-level program into machine code in one go, producing a reusable executable.
Interpreter
Translates and runs a high-level program ONE STATEMENT at a time — re-interpreted every run.
Assembler
Translates assembly language into machine code, producing a reusable executable.
Theory

Why translation is needed

  • Humans write programs in a form THEY can understand; computers only execute BINARY machine code.
  • A translator converts the human-written program into machine code so the computer can run it.

Compilers

  • Translates an ENTIRE high-level program into machine code IN ONE GO.
  • Once compiled, the machine code can be used AGAIN AND AGAIN without recompiling.
  • If errors are found, an ERROR REPORT is produced instead of a compiled program.
  • Example: Sum := FirstNumber + SecondNumber compiles to the same 3-instruction machine code sequence seen earlier.

Interpreters

  • Reads ONE statement, translates it, PERFORMS the action, then moves to the next statement — repeating throughout the program.
  • If a statement has an error, execution STOPS immediately, with an error message (sometimes a suggested fix).
  • The program must be interpreted AGAIN every time it runs — no reusable executable is produced.

Assemblers

  • Translates an assembly language program into machine code.
  • Once assembled, the machine code can be used AGAIN AND AGAIN without re-assembling.
  • Example: LDA First / ADD Second / STO Sum assembles to the same 3-instruction machine code sequence.
Compiler vs. Interpreter vs. Assembler
CompilerInterpreterAssembler
Translates HLL → machine codeExecutes HLL one statement at a timeTranslates assembly language → machine code
Produces an executable fileNO executable file producedProduces an executable file
One HLL statement → several machine code instructionsOne HLL statement executed, then nextUsually one assembly instruction → one machine code instruction
All three translator types share this same basic purpose — turning readable source code into machine code — but differ in HOW and WHEN this happens.
Practice — Test Yourself

These questions only cover what THIS subsection taught — compilers, interpreters, and assemblers.

Short answer 1
What is the key difference in HOW a compiler and an interpreter process a program?
Reveal answer

A compiler translates the ENTIRE program into machine code in one go, producing a reusable executable. An interpreter reads, translates, and EXECUTES one statement at a time, needing to re-interpret the whole program every time it runs.

Short answer 2
What happens when an interpreter encounters a statement with an error?
Reveal answer

Execution CEASES immediately, and an error message is output — sometimes with a suggested correction.

Fill in the blank 3
An ______ translates a low-level assembly language program into machine code; a ______ translates a high-level language program into machine code.
Reveal answer

Blank 1: assembler. Blank 2: compiler.

Spot the error 4
A student claims: "An interpreted program produces an executable file, just like a compiled program does." What's wrong with this?
Reveal answer

An interpreter does NOT produce an executable file at all — it translates and runs statements one at a time, EVERY time the program is run. Only compilers (and assemblers) produce a reusable executable file of machine code.

Applied / scenario 5
A developer wants to quickly test small changes to their code, running it immediately after each edit without a separate build step, and is willing to accept it running somewhat slower. Which type of translator — compiler or interpreter — best fits this workflow, and why, using this lesson's content?
Reveal answer

An interpreter. It executes statements immediately, one at a time, with no separate compile step needed — well-suited to rapid iteration. A compiler would require the whole program to be recompiled in one go each time (producing an executable) before the change could be tested.

Short answer 6
What does a compiler produce instead of an executable, if errors are detected in the source code?
Reveal answer

An error report.
