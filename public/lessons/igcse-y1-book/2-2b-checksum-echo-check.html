2.2b Checksum & Echo Check
Two more ways to catch transmission errors — one that checks a whole block at once, and one that's simple but genuinely unreliable.
Key Terms
Checksum
A value calculated from a block of data using an agreed algorithm, sent alongside the data, and recalculated by the receiver to check for errors.
Echo check
Sending received data back to the original sender, who compares it to the original to check for transmission errors.
Theory

Checksum

  • A checksum is a value used to check whether a block of data has been changed or corrupted during transmission.
  • The process: before sending, the sender calculates a checksum from the block of data using an algorithm AGREED in advance between sender and receiver.
  • The checksum is transmitted along with the data block.
  • At the receiving end, the same algorithm is used to recalculate the checksum from the data actually received.
  • The recalculated checksum is compared to the one sent — if they MATCH, no transmission error occurred; if they DIFFER, the block must be re-sent.
Checksum flow: a value is computed before sending, recomputed after receiving, and compared.
Pseudocode — checksum verificationDECLARE sentChecksum, calculatedChecksum : INTEGER DECLARE dataBlock : ARRAY OF BYTE RECEIVE dataBlock, sentChecksum calculatedChecksum ← CALCULATE_CHECKSUM(dataBlock) IF calculatedChecksum = sentChecksum THEN OUTPUT "No error - data accepted" ELSE OUTPUT "Error detected - request re-transmission" ENDIF

Echo check

  • With echo check: data sent to another device is sent straight BACK to the original sender.
  • The sender's computer compares the returned copy against the original data.
  • If there's NO difference, the data was transmitted without error.
  • If the two copies DIFFER, an error occurred SOMEWHERE during transmission.
  • The genuine reliability problem: if a difference is found, it's impossible to tell whether the error happened on the WAY THERE (sender → receiver) or on the WAY BACK (receiver → sender) — the check can't distinguish between the two.
Echo check: data travels both ways, and the sender does the final comparison.
Practice — Test Yourself

These questions only cover what THIS subsection taught — checksum and echo check.

Short answer 1
What must be agreed between sender and receiver before checksum can be used?
Reveal answer

The ALGORITHM used to calculate the checksum from the data block — both sides must use the identical method for the comparison to be meaningful.

Short answer 2
In an echo check, why can the sender not tell WHERE an error occurred, even when one is detected?
Reveal answer

Data travels in both directions — sender to receiver, then receiver back to sender — so a mismatch could genuinely have been introduced on EITHER leg of that round trip. The check alone cannot distinguish which leg caused it.

Fill in the blank pseudocode 3
Complete this checksum pseudocode condition:
IF calculatedChecksum ______ sentChecksum THEN OUTPUT "Error detected"
Reveal answer

IF calculatedChecksum <> sentChecksum THEN (i.e. "not equal to") — an error is flagged only when the two values genuinely differ.

Spot the error 4
A student claims: "Echo check is just as reliable as checksum, since both compare two values to detect errors." What real difference in reliability does this ignore?
Reveal answer

Echo check is explicitly described as unreliable, because when a mismatch is found, it's genuinely impossible to tell whether the error happened on the outward trip or the return trip. Checksum doesn't have this ambiguity — the checksum is calculated directly from the data actually received, so a mismatch clearly indicates the received block itself is corrupted.

Applied / scenario 5
A system transfers a large data file in blocks and needs a reliable, single-trip way to confirm each block arrived correctly, without waiting for data to be sent back to the sender. Which method — checksum or echo check — is more suitable here, and why?
Reveal answer

Checksum — it only requires a single trip (data + checksum sent once), with the receiver doing its own recalculation and comparison locally. Echo check requires a full round trip (data sent back to the sender) and carries genuine ambiguity about where an error occurred, making it less suitable here.

Short answer 6
Describe, in your own words, the full echo check process from start to finish.
Reveal answer

Data is sent from the sender to the receiver. The receiver sends that same data straight back to the sender. The sender compares the returned data against its original copy — if they match, no error occurred; if they differ, an error occurred somewhere during the round trip.
