2.2a Why Check for Errors, and Parity Checks
Why transmitted data can never be assumed correct — and how a single extra bit can catch (some) corruption.
Key Terms
Data corruption
Data being changed, lost, or even gained during transmission — due to interference, packet-switching problems, or skewing.
Parity
Whether a byte has an EVEN or ODD number of 1-bits. Agreed in advance between sender and receiver.
Parity bit
An extra bit (usually the leftmost) added to a byte to force it to have the agreed parity.
Parity block
Checking parity both horizontally (per byte) AND vertically (per bit position) across a block of bytes — this can locate exactly which bit is wrong.
Theory

Why errors need to be checked for

  • Whenever data is transmitted, there's always a risk it becomes corrupted, lost, or even gained.
  • Errors can occur due to: interference (any cable can suffer electrical interference, corrupting or losing data), problems during packet switching (can lose OR gain data), and skewing (bits arriving out of sync during parallel transmission).
  • Checking matters because a computer, unlike a human, cannot make sense of scrambled text at all — even text a human can still read despite scrambled middle letters would be complete nonsense to a computer.
  • The three main methods covered: parity checks, checksum, and echo check.

How a basic parity check works

  • Parity checking is based on counting the 1-bits in a byte. Parity is either EVEN (an even number of 1-bits) or ODD (an odd number).
  • One bit in the byte (usually the leftmost/most significant bit) is reserved as the parity bit, set to whatever value makes the byte match the agreed parity.
  • Sender and receiver AGREE in advance which parity (even or odd) is being used — this makes parity checking a form of transmission protocol.

Detecting an error with parity

Assume even parity is agreed. Byte sent: 01011100 (four 1-bits — correct even parity).

Byte received: 01001100 (only three 1-bits — now ODD).

Since the received byte's parity no longer matches the agreed EVEN parity, the receiver's computer flags a transmission error and can request a re-send.

The limitation of basic parity — and the fix

  • If exactly ONE bit changes, parity checking reliably catches it. But if TWO bits change, the byte can still end up with the CORRECT parity by coincidence — meaning the error goes completely undetected.
  • Even when an error IS detected, a basic parity check can't tell you WHICH bit is wrong — only that something changed.
  • The fix: parity blocks. A block of bytes is sent together with an extra "parity byte" — parity is checked both HORIZONTALLY (across each byte's own bits) and VERTICALLY (down each bit position across all the bytes).
  • Wherever a row AND a column both show incorrect parity, their INTERSECTION is exactly the corrupted bit — meaning the error can be located, and even automatically corrected by flipping that one bit.
Worked example — locating an error with a parity block

Even parity agreed. After checking every row and column, byte 8 (row) has incorrect parity, and bit 5 (column) also has incorrect parity.

The bit at the intersection of row 8 and column 5 is the corrupted one — it should be 0, not 1. Flipping just that bit fixes BOTH the row's parity and the column's parity at once — this is exactly how the error is located and corrected.

Practice — Test Yourself

These questions only cover what THIS subsection taught — why errors are checked for, and parity checks (including parity blocks).

Short answer 1
What must sender and receiver agree on BEFORE using parity checking, and why does this make it a kind of "protocol"?
Reveal answer

They must agree whether EVEN or ODD parity is being used. This is a protocol because both sides must follow the same rule for the check to mean anything — the receiver can only detect an error by comparing against the SAME parity rule the sender used.

Fill in the blank pseudocode 2
For the 7-bit data 1110000 (three 1-bits) using EVEN parity, the parity bit should be set to ______, making the full byte have ______ 1-bits in total.
Reveal answer

Blank 1: 1 (to make the count even). Blank 2: four 1-bits total.

Fill in the blank 3
A parity block checks parity both ______ (across each byte) and ______ (down each bit position), which allows it to actually locate WHICH bit is wrong.
Reveal answer

Blank 1: horizontally. Blank 2: vertically.

Spot the error 4
A student claims: "Parity checking always detects every transmission error, no matter how many bits change." What real limitation does this ignore?
Reveal answer

If exactly TWO bits change, the byte can coincidentally end up with the SAME (correct) parity it started with — meaning the error goes completely undetected by a basic parity check. Basic parity only reliably catches an ODD number of bit changes (most commonly, a single bit change).

Applied / scenario 5
A system sends 9 bytes as a block using even parity, plus a parity byte. After transmission, row 3 (byte 3) shows incorrect parity, and column 6 (bit 6) also shows incorrect parity, with no other row or column affected. Explain what this tells you, and what the system can do about it.
Reveal answer

The corrupted bit is exactly at the intersection of row 3 and column 6 — that single bit's value flipped during transmission. The system can locate it precisely using the parity block method, and can automatically correct it by flipping that one bit back — restoring both row 3's and column 6's correct even parity — without needing to request a full re-transmission.

Short answer 6
Name three real causes of data corruption during transmission mentioned in this lesson.
Reveal answer

Interference (electrical interference on cables), problems during packet switching (can lose or even gain data), and skewing (bits arriving out of sync during parallel transmission).
