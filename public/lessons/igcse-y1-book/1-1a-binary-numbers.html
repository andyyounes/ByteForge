1.1a Binary Numbers
Why computers use binary, and how to convert between binary and denary (decimal).
Key Terms
Bit
A single binary digit — either 0 or 1. Short for "binary digit".
Byte
A group of 8 bits, treated as one unit — e.g. 11101110.
Denary
The normal counting system with ten digits (0-9) — also called decimal. A base 10 system.
Binary
The number system computers use internally — only two digits, 0 and 1. A base 2 system.
Base
The number of distinct digits a number system uses. Denary is base 10; binary is base 2.
Place value
What a digit's position is "worth" — in binary, each position is worth a power of 2 (1, 2, 4, 8, 16...).
Theory

Why computers use binary in the first place

  • Any form of data — text, sound, images, instructions — has to be converted into a binary format before a computer can process it.
  • The basic building block of every computer is the binary number system, because it only needs two digits: 1 and 0.
  • A computer is built from millions of tiny electronic switches, and each switch can only genuinely be in one of two states: ON or OFF.
  • A switch in the ON position is represented by 1; a switch in the OFF position is represented by 0 — binary maps perfectly onto how the hardware itself actually works.

Eight real switches, ON/OFF — this is genuinely one byte: 11101110.

The denary (base 10) system, as a reminder

  • Denary uses ten separate digits, 0–9, to represent every value — it's a base 10 system.
  • Each position in a denary number is worth a power of 10: reading right to left, the headings are 1, 10, 100, 1000, 10 000, and so on (10⁰, 10¹, 10², 10³, 10⁴...).

The binary (base 2) system

  • Binary is a base 2 system — only the two digits 0 and 1 exist, so only two "values" can ever appear in any single position.
  • Using the same idea as denary, binary positions are worth powers of 2: reading right to left, the headings are 1, 2, 4, 8, 16, 32, 64, 128 (2⁰, 2¹, 2², 2³...) for an 8-bit number.
  • A typical 8-bit binary number looks like: 11101110.
Worked example — binary to denary

Convert the binary number 11101110 into denary. Write the place-value headings above the bits, then add together the headings wherever there's a 1:

1286432168421
11101110

Only the columns with a 1 count: 128 + 64 + 32 + 8 + 4 + 2 = 238. So 11101110 in binary is 238 in denary.

This method works for a binary number of any length — an 8-bit, 12-bit, or 16-bit number is converted exactly the same way, just with more place-value headings.

Pseudocode — the binary-to-denary algorithm
total ← 0
placeValue ← 1
FOR each bit, starting from the RIGHTMOST digit
    IF bit = 1 THEN
        total ← total + placeValue
    ENDIF
    placeValue ← placeValue * 2
NEXT bit
OUTPUT total

Converting denary to binary — two valid methods

  • Method 1 — successive subtraction of powers of 2. Subtract the largest possible power of 2 (128, 64, 32...) from the number, mark that position as 1, and repeat with what's left until you reach exactly 0.
  • Method 2 — successive division by 2. Divide the number by 2 repeatedly, writing down the remainder (0 or 1) each time, until the result reaches 0. Reading the remainders in reverse order (bottom to top) gives the binary number.
  • Both methods always agree — they're just two different ways of arriving at the same binary number.
Worked example — denary to binary (Method 1: subtraction)

Convert the denary number 142 into an 8-bit binary number.

142 − 128 = 14 → 14 − 8 = 6 → 6 − 4 = 2 → 2 − 2 = 0. We used 128, 8, 4, and 2.

1286432168421
10001110

So 142 in denary is 10001110 in binary.

Worked example — denary to binary (Method 2: division)

Convert the same number, 142, using successive division by 2 — write the remainder each time:

142 ÷ 2 = 71 r0 → 71 ÷ 2 = 35 r1 → 35 ÷ 2 = 17 r1 → 17 ÷ 2 = 8 r1 → 8 ÷ 2 = 4 r0 → 4 ÷ 2 = 2 r0 → 2 ÷ 2 = 1 r0 → 1 ÷ 2 = 0 r1

Reading the remainders from the last one back to the first: 1 0 0 0 1 1 1 0 — exactly the same answer as Method 1, confirming both approaches genuinely agree.

Practice — Test Yourself

These questions only cover what THIS subsection taught — binary/denary conversion. Answer each one, then reveal the answer key to check.

Short answer 1
Convert the binary number 10110101 into denary. Show your place-value working.
Reveal answer

Headings: 128, 64, 32, 16, 8, 4, 2, 1 → bits: 1 0 1 1 0 1 0 1

128 + 32 + 16 + 4 + 1 = 181

Answer: 181

Short answer 2
Convert the denary number 91 into an 8-bit binary number, using EITHER method.
Reveal answer

Subtraction: 91 − 64 = 27, 27 − 16 = 11, 11 − 8 = 3, 3 − 2 = 1, 1 − 1 = 0 → used 64, 16, 8, 2, 1.

Answer: 01011011

Fill in the blank — pseudocode 3
Complete this pseudocode for the binary-to-denary algorithm by filling in the two blanks:

placeValue ← 1
FOR each bit, starting from the rightmost digit
    IF bit = 1 THEN total ← total + ______ ENDIF
    placeValue ← placeValue ______ 2
NEXT bit
Reveal answer

Blank 1: placeValue — you add the CURRENT place value to the running total, not a fixed number.

Blank 2: * (multiply) — each place value doubles as you move one position left, since binary place values are powers of 2.

Spot the error 4
A student converts 1101 to denary like this: they line it up as 1-1-0-1 under headings 8-4-2-1, and calculate 8 + 4 + 1 = 13, but then write down the FINAL answer as 14. What exactly went wrong?
Reveal answer

The working (8 + 4 + 1 = 13) is actually correct — the error is a simple arithmetic/transcription slip at the very last step, writing "14" instead of the "13" they had just correctly calculated.

This is the single most common real mistake in these questions: getting the METHOD right, then making a small slip copying the final number down. Always double-check your own last line matches your own working.

Applied / scenario 5
A memory chip's status register uses one bit per switch to record whether 8 real hardware components are ON or OFF. The register currently reads 10010001. (a) How many of the 8 components are currently ON? (b) What real-world reason from this lesson explains why a single bit is enough to record one component's ON/OFF status?
Reveal answer

(a) Three components are ON — there are three 1s in 10010001.

(b) A single bit is genuinely enough because it only needs to represent TWO states, and a bit's own two possible values (0 and 1) map perfectly onto exactly two real states — a switch that's OFF and a switch that's ON. No more information than that is needed for a simple ON/OFF fact.

Short answer 6
Why can a denary number system NOT be built directly into a computer's electronic switches the way binary can?
Reveal answer

A denary digit needs to represent TEN different values (0–9), but a simple electronic switch only has two genuine physical states (ON/OFF) — there's no direct, reliable way for one switch to represent ten different states the way it naturally represents two. Binary's two digits map exactly onto a switch's two real states; denary's ten digits don't.
