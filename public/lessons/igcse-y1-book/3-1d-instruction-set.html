3.1d Instruction Sets
The limited vocabulary of operations a CPU actually understands — opcodes, operands, and why X86 CPUs from different makers still "speak" the same language.
Key Terms
Instruction set
The limited, fixed set of opcodes (operations) a particular CPU design understands.
Opcode
The part of an instruction telling the CPU WHAT operation to perform (e.g. ADD, JMP).
Operand
The part of an instruction giving the data to act on, or a register/memory reference.
X86
A common CPU instruction-set standard, shared by very differently-designed CPUs like Intel Pentium and AMD Athlon.
Theory

Opcodes and operands

  • Instructions are operations decoded in sequence, each instructing the ALU and CU.
  • Every operation is made of an opcode and an operand.
  • The opcode tells the CPU WHAT operation to carry out.
  • The operand is the DATA to act on — or it may refer to a register or memory location.
  • Since the CPU must understand each operation, there's a genuinely LIMITED number of opcodes available — this fixed list is called the instruction set.
  • All software eventually gets converted into these binary instructions, processed one at a time via the Fetch-Decode-Execute cycle.
An example instruction: the opcode names the operation, the operand supplies the data/register(s) it acts on.

X86 — a shared instruction set across different CPUs

  • Different manufacturers design their own internal electronics, but if a CPU is based on the X86 standard, its instruction set is almost IDENTICAL to other X86 CPUs.
  • Example: Intel Pentium and AMD Athlon CPUs use nearly identical X86 instruction sets, despite being based on very different electronic designs internally.
  • Important distinction: instruction sets are NOT the same as programming code. Instruction sets are low-level instructions the CPU directly understands. Program code (written by a human) needs an interpreter or compiler to convert it into the CPU's instruction set. Example instruction-set operations: ADD, JMP, LDA.
Practice — Test Yourself

These questions only cover what THIS subsection taught — instruction sets, opcodes, and operands.

Short answer 1
What are the two parts of every CPU operation, and what does each one do?
Reveal answer

The opcode (tells the CPU WHAT operation to do) and the operand (the data to act on, or a register/memory reference).

Short answer 2
Why is a CPU's instruction set described as "limited"?
Reveal answer

Because the CPU can only understand a fixed, finite set of opcodes — there is genuinely a limited number of distinct operations any given CPU design can carry out.

Fill in the blank 3
Program code written by a human needs an ______ or ______ to convert it into the CPU's instruction set.
Reveal answer

Blank 1: interpreter. Blank 2: compiler (either order).

Spot the error 4
A student claims: "Instruction sets and programming code are the same thing, just described differently." What real distinction does this ignore?
Reveal answer

Instruction sets are the LOW-LEVEL instructions the CPU directly understands (e.g. ADD, JMP, LDA). Programming code is written at a higher level by humans, and must be CONVERTED (via an interpreter or compiler) into the instruction set before the CPU can run it — they are genuinely different things at different levels.

Applied / scenario 5
A software company wants their application to run correctly on both an Intel Pentium CPU and an AMD Athlon CPU without major changes. Using this lesson's content, explain why this is realistically achievable.
Reveal answer

Both CPUs are based on the X86 standard, and the lesson states that X86 CPUs share almost IDENTICAL instruction sets, even though their internal electronic designs are very different. Since the software's low-level instructions ultimately target the same shared instruction set, it can realistically run on both without needing separate low-level versions.

Short answer 6
Give two examples of actual instruction-set operations mentioned in this lesson.
Reveal answer

Any two of: ADD, JMP, LDA.
