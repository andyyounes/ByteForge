4.2d Compiler vs. Interpreter — Advantages & Disadvantages
Why interpreters win during development, and compilers win once the program ships.
Theory

Why the trade-off exists

Compilers and interpreters translate code in fundamentally different ways (whole program at once vs. statement-by-statement), and this genuinely leads to different real strengths at different STAGES of a program's life — development vs. final distribution.

Interpreter — Advantages
  • Easier/quicker to debug and test during development
  • Easier to edit programs during development
Interpreter — Disadvantages
  • Programs cannot run without the interpreter present
  • Programs can take longer to execute
Compiler — Advantages
  • Compiled program can be stored ready for use
  • Can be executed WITHOUT the compiler present
  • Takes up LESS space in memory when executed
  • Executes in a SHORTER time
Compiler — Disadvantages
  • Takes longer to write, test, and debug during development

Putting it together

Compiled programs are run WITHOUT the compiler; interpreted programs CANNOT run without the interpreter. A compiled program is usually DISTRIBUTED for general use; an interpreter is often used WHILE a program is being developed — this is exactly why many real development workflows use an interpreter during writing/testing, then compile the final version for release.

Practice — Test Yourself

These questions only cover what THIS subsection taught — compiler vs. interpreter advantages/disadvantages.

Short answer 1
Why is an interpreter often preferred DURING program development, even though it's slower at runtime?
Reveal answer

An interpreter is easier and quicker to debug and test, and easier to edit — since it runs statements immediately without a full recompile step, making the edit-test cycle much faster during development.

Short answer 2
Why is a compiled program usually chosen for final distribution, rather than an interpreted one?
Reveal answer

A compiled program can run WITHOUT the compiler present, uses less memory when executing, and runs in a shorter time — all genuine advantages for something being distributed to end-users who don't have (and shouldn't need) the development tools.

Fill in the blank 3
An interpreted program CANNOT be run without the ______ present; a compiled program CAN be run without the ______ present.
Reveal answer

Blank 1: interpreter. Blank 2: compiler.

Spot the error 4
A student claims: "Compilers are strictly better than interpreters in every respect, so there's never a good reason to use an interpreter." What's wrong with this?
Reveal answer

Interpreters have genuine advantages DURING development — easier and quicker debugging/testing/editing — which compilers, with their slower full-recompile cycle, don't match at that stage. Whether a compiler or interpreter is "better" depends on the STAGE (development vs. final release), not an absolute ranking.

Applied / scenario 5
A software company is finishing a large commercial application that will be sold to thousands of customers who don't have any development tools installed. Which translator type should be used for the FINAL release version, and why, based on this lesson's content?
Reveal answer

A compiler. The lesson states a compiled program can be executed WITHOUT the compiler present, and is usually the version distributed for general use — exactly matching customers who have no development tools installed, unlike an interpreted program which would require the interpreter on every customer's machine.

Short answer 6
Name one real disadvantage of using a compiler during the development stage.
Reveal answer

It takes a longer time to write, test, and debug programs during development (since the whole program must compile before it can be tested).
