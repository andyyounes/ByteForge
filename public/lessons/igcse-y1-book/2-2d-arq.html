2.2d Automatic Repeat Requests (ARQ)
A third error-checking method — acknowledgements and timeouts working together to guarantee data eventually arrives correctly.
Key Terms
ARQ
Automatic Repeat Request — uses acknowledgements and timeouts to detect errors and automatically request re-transmission.
Positive acknowledgement
A message telling the sender the data was received correctly (no error detected).
Negative acknowledgement
A message telling the sender an error WAS detected — requests re-transmission.
Timeout
The time interval the sender waits for any acknowledgement before automatically re-sending the data.
Theory

How ARQ works

  • ARQ is a THIRD method (alongside parity checks and echo checks) to verify data arrived unchanged.
  • It uses positive and negative acknowledgements — messages telling the sender whether data has/hasn't been received correctly — plus a timeout, the time allowed to elapse before an acknowledgement must arrive.
  • The receiving device gets an error-detection code with the data (typically a Cyclic Redundancy Check, CRC) to check for transmission errors.
  • If NO error is detected: a positive acknowledgement is sent back to the sender.
  • If an error IS detected: the receiver sends a negative acknowledgement, requesting re-transmission.
  • The sender waits a pre-determined time (the timeout). If NO acknowledgement of any kind arrives within that time, the sender automatically RE-SENDS the data.
  • This repeats until either a positive acknowledgement is received, OR a pre-determined maximum number of re-transmissions has been reached.
  • ARQ is commonly used by mobile phone networks to guarantee data integrity.
ARQ's three possible outcomes after data is sent: positive ACK, negative ACK, or silence (timeout triggers automatic resend).
Pseudocode — sender-side ARQ logicDECLARE maxRetries, attempts : INTEGER DECLARE ackReceived : BOOLEAN attempts ← 0 ackReceived ← FALSE WHILE ackReceived = FALSE AND attempts < maxRetries SEND data, crcCode WAIT FOR acknowledgement UNTIL timeout IF positiveAcknowledgementReceived THEN ackReceived ← TRUE ELSE attempts ← attempts + 1 // negative ACK or timeout - loop repeats and resends ENDIF ENDWHILE
Practice — Test Yourself

These questions only cover what THIS subsection taught — Automatic Repeat Requests (ARQ).

Short answer 1
What TWO mechanisms does ARQ rely on to check and correct transmission errors?
Reveal answer

Acknowledgements (positive/negative) and a timeout (the time allowed before an acknowledgement must arrive).

Short answer 2
What error-detection code does the receiving device typically use to check the incoming data in ARQ?
Reveal answer

A Cyclic Redundancy Check (CRC).

Fill in the blank 3
If NO acknowledgement of any kind is received within the ______, the sender automatically ______ the data.
Reveal answer

Blank 1: timeout (time limit). Blank 2: re-sends.

Spot the error 4
A student claims: "ARQ will keep re-sending data forever until it succeeds, no matter what." What real limit from this lesson does this ignore?
Reveal answer

ARQ re-sends data until EITHER a positive acknowledgement is received OR a pre-determined MAXIMUM number of re-transmissions has been reached — it does not necessarily continue "forever"; there's a built-in cap on retries.

Applied / scenario 5
A sender transmits a data packet, but due to a network fault, the packet never actually reaches the receiver at all. Using this lesson's content, explain what happens next in the ARQ process.
Reveal answer

Since the packet never arrived, the receiver can send neither a positive nor a negative acknowledgement. The sender's timeout will therefore expire with NO acknowledgement received at all, which automatically triggers the sender to re-send the data — this is exactly the scenario the timeout mechanism is designed to catch (not just corrupted data, but data that never arrives).

Short answer 6
Name one real-world system mentioned in this lesson that commonly uses ARQ.
Reveal answer

Mobile phone networks — ARQ is used there to guarantee data integrity.
