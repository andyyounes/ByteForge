5.3d Phishing & Pharming
One trick needs the victim to click something; the other doesn't need them to do anything at all.
Key Terms
Phishing
Legitimate-looking emails tricking a user into clicking a link/attachment or revealing personal data.
Spear phishing
Phishing targeted at specific individuals/companies, unlike regular phishing's untargeted victims.
Pharming
Malicious code redirecting a browser to a fake site WITHOUT any user action needed.
DNS cache poisoning
Corrupting DNS records so a legitimate URL resolves to a fake website's IP address.
Theory

Phishing

  • Cybercriminal sends legitimate-LOOKING emails — links/attachments lead to a fake website, or trick the user into revealing personal data directly (bank/card details).
  • Key point: the recipient must INITIATE some action (click, open) before phishing can cause harm. Deleting/not opening suspicious emails stops the attack entirely.
  • Spear phishing: targets SPECIFIC individuals/companies (e.g. for financial info or industrial espionage) — regular phishing targets no one in particular.

Preventing phishing

  • Security AWARENESS training (especially for industry/commerce staff).
  • Don't click email links unless CERTAIN they're safe — watch for generic greetings ("Dear Customer...").
  • Run ANTI-PHISHING toolbars on browsers (including mobile).
  • Check for HTTPS/green padlock in the address bar.
  • Regularly check online accounts and update passwords.
  • Keep browsers UP TO DATE; run a firewall (desktop + network combination is most effective).
  • Be wary of pop-ups — NEVER click "cancel" (can lead to phishing/pharming); use the small × in the corner instead.

Pharming

  • Malicious code installed on the user's computer OR an infected website, redirecting the browser to a fake site WITHOUT the user's knowledge.
  • KEY DIFFERENCE from phishing: the user does NOT need to take any action for pharming to be initiated.
  • Method: DNS cache poisoning — corrupting the real IP address a URL maps to, so the browser connects to the fake site instead when a user types a completely legitimate URL.
Phishing
  • Requires user action (click/open)
  • Fake emails trick the user
  • Deleting suspicious emails stops it
Pharming
  • Needs NO user action at all
  • Redirects via corrupted DNS/malicious code
  • Typing the CORRECT URL doesn't protect you if DNS is poisoned

Mitigating pharming

  • Anti-virus software can detect unauthorised website-address alterations.
  • If the DNS SERVER itself is infected (not the user's own computer), mitigation is much HARDER.
  • Modern browsers can alert users to pharming/phishing.
  • Check website SPELLING carefully.
  • HTTPS/green padlock is an additional defence, same as phishing.
Practice — Test Yourself

These questions only cover what THIS subsection taught — phishing and pharming.

Short answer 1
What is the single most important difference between phishing and pharming?
Reveal answer

Phishing REQUIRES the victim to take an action (click a link/attachment). Pharming needs NO user action at all — it redirects via malicious code or corrupted DNS records without the user doing anything.

Short answer 2
What is "spear phishing", and how does it differ from regular phishing?
Reveal answer

Spear phishing targets SPECIFIC individuals or companies (e.g. for financial information or industrial espionage). Regular phishing is not targeted — it's sent broadly, without picking specific victims.

Fill in the blank 3
Pharming can redirect a user using ______ ______, which corrupts the real IP address a legitimate URL maps to.
Reveal answer

DNS cache poisoning.

Spot the error 4
A student claims: "If a user types their bank's URL perfectly correctly and never clicks a suspicious link, they can never fall victim to a redirect attack." What's wrong with this?
Reveal answer

Pharming can still redirect them even with a perfectly typed, correct URL — if DNS cache poisoning has corrupted the DNS records, that correct URL will resolve to the FAKE website's IP address instead, with no user action or mistake required at all.

Applied / scenario 5
A pop-up appears while a user is browsing, and it looks suspicious. Using this lesson's content, describe the correct way to close it, and why clicking "cancel" is a real risk.
Reveal answer

The user should click the small × in the top-right corner of the pop-up window, NOT the "cancel" button — the lesson explicitly warns that clicking "cancel" on a malicious pop-up can ultimately lead to phishing or pharming sites, since the "cancel" button itself may be a disguised malicious link.

Short answer 6
Why is pharming much harder to mitigate if the DNS server itself (rather than the user's own computer) has been infected?
Reveal answer

Because the corruption happens outside the user's control entirely — anti-virus software on the user's own computer can only protect against alterations it can actually detect on that device; it cannot fix a poisoned DNS server elsewhere on the network.
