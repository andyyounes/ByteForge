1.1c Binary Addition & Overflow
Adding two 8-bit binary numbers, carrying correctly, and recognising when a result has genuinely overflowed.
Key Terms
Carry
A 1 passed to the next column left when a column's sum is greater than 1 (the binary equivalent of carrying past 9 in denary).
Overflow
An error that happens when a binary addition produces a result too large to fit in the register's number of bits.
Theory

Adding two binary digits

Just like denary addition, binary addition can carry a value to the next column. The full set of rules for adding two bits:

AdditionCarrySum
0+000
0+101
1+001
1+110

Extended to adding THREE bits at once (needed once a carry is coming in from the column on the right):

AdditionCarrySum
0+0+000
0+0+101
0+1+001
0+1+110
1+0+001
1+0+110
1+1+010
1+1+111

The method — same discipline as denary column addition

  • Add the bits in the right-hand column first.
  • If the sum is greater than 1 (i.e. it's 2 or 3, once a carry is involved), carry a 1 into the next column to the left.
  • Keep moving left, adding any incoming carry into each column, until every column has been added.
Worked example — binary addition

Add 00100111 + 01001010. Working from the right, column by column, tracking carries:

111
A00100111
B01001010
=01110001

Answer: 01110001

Overflow — when the answer doesn't fit

  • The maximum denary value an 8-bit binary number can hold is 255 (that's 2⁸ − 1).
  • If adding two 8-bit numbers genuinely needs a 9th bit to hold the true result, that 9th bit simply has nowhere to go in an 8-bit register — it's lost, and the 8 bits left over give the WRONG answer.
  • Generating a 9th bit during addition is the clear, reliable sign that overflow has occurred — the true sum was too big to fit.
  • The more bits a register has, the bigger a number it can correctly hold: a 16-bit register's maximum is 65 535 (2¹⁶ − 1); a 32-bit register's maximum is 4 294 967 295 (2³² − 1).
Real overflow example

Adding 01101110 (110) and 11011110 (222) genuinely needs a 9th bit. What's left in the 8-bit register is 01001100, which is only 76 in denary — but the REAL answer, 110 + 222, is 332. The register simply couldn't hold a number that large, and the wrong, too-small answer is exactly what overflow looks like.

Practice — Test Yourself

These questions only cover what THIS subsection taught — binary addition and overflow. Answer each one, then reveal the answer key to check.

Short answer 1
Add 00011101 and 01100110, showing your carry values.
Reveal answer

29 + 102 = 131. Binary: 10000011

Short answer 2
What is the LARGEST denary number a 16-bit register can correctly store, and how is this figure calculated?
Reveal answer

65 535, calculated as 2¹⁶ − 1 — one less than the next power of 2, the same pattern as an 8-bit register's maximum of 255 (2⁸ − 1).

Fill in the blank 3
A genuine sign that overflow has occurred during an 8-bit binary addition is that the calculation generates a ______ bit, which has nowhere to be stored in an 8-bit register.
Reveal answer

9th — an 8-bit register can only ever hold 8 bits; a genuine 9th bit is exactly what gets lost, causing overflow.

Spot the error 4
A student adds 0+1+1 (a column with an incoming carry) and writes down carry = 0, sum = 1. What's actually wrong with this?
Reveal answer

Per the three-bit addition table, 0+1+1 is genuinely carry = 1, sum = 0 — the student has swapped the carry and sum values around. Two 1s in the column always total 2, which in binary is written 10 — carry 1, sum 0 — not the other way round.

Applied / scenario 5
An 8-bit register adds 11111111 (255) and 00000001 (1). (a) What real denary answer SHOULD this addition give? (b) Explain, using what this lesson taught, exactly why the 8-bit register cannot correctly store that real answer.
Reveal answer

(a) 255 + 1 = 256.

(b) 256 needs a 9th bit to represent in binary (100000000) — but an 8-bit register only has 8 bit positions available, so that 9th bit is lost. This is a genuine overflow: the register is left holding 00000000, making it silently and wrongly look like the answer was 0.

Short answer 6
Why does a computer system with MORE bits per register genuinely reduce how often overflow happens, for the same everyday calculations?
Reveal answer

More bits means a much higher maximum storable value (each extra bit roughly doubles the maximum) — so genuinely large real sums are far less likely to exceed the register's capacity, meaning overflow becomes far less likely to occur for the same everyday numbers.
