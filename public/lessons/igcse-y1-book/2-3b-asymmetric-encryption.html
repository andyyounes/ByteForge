2.3b Asymmetric Encryption
Two keys instead of one — how public/private key pairs solve symmetric encryption's biggest weakness.
Key Terms
Asymmetric encryption
Encryption using TWO mathematically-linked keys — a public key and a private key — instead of one shared key.
Public key
A key made available to EVERYONE, used by others to encrypt messages sent to its owner.
Private key
A key known ONLY to its owner, used to decrypt messages that were encrypted with their matching public key.
Theory

Why asymmetric encryption was developed

  • Asymmetric encryption was created to solve symmetric encryption's core problem — the difficulty of safely sharing a single secret key between sender and receiver.
  • It uses TWO keys: a public key (available to everybody) and a private key (known only to that one user). BOTH keys are needed across the full encrypt/decrypt process.
  • The two keys in a pair are mathematically linked, but — critically — CANNOT be derived from each other.
Worked example — Tom sends Jane a confidential document
  1. Jane generates a MATCHING PAIR of keys (public + private) using an algorithm, and stores both on her computer.
  2. Jane sends her PUBLIC key to Tom (this is safe — the public key is meant to be shared).
  3. Tom uses Jane's public key to ENCRYPT the document, producing ciphertext, and sends it to Jane.
  4. Jane uses her own PRIVATE key (which she never shared with anyone) to DECRYPT Tom's document. This works only because her public key and private key are a matching pair generated together — Jane's public key CANNOT be used to decrypt the message; only her private key can.
Only Jane's private key can decrypt something encrypted with her public key — that's what makes this secure even though the public key is freely shared.

Sharing one public key with many people

  • Jane can share her SAME public key with any number of colleagues (Tom, Susan, Mike, Megan) — they can all encrypt messages TO her using it, and only Jane's private key can decrypt any of them.
  • But this only allows ONE-WAY communication (everyone → Jane). For genuine TWO-WAY communication between ALL parties, each person must generate their OWN public/private key pair, and everyone must exchange public keys with everyone else.
  • Each person then uses their OWN private key to decrypt anything sent to them, using their own public key.

Why this is more secure than symmetric encryption

  • The private key NEVER needs to be transmitted anywhere — it stays on its owner's computer the whole time, so it can never be intercepted in transit.
  • Only the public key travels across the network — and since the public key can't be used to decrypt anything (only to encrypt), intercepting it gives an eavesdropper nothing useful.
  • This directly solves symmetric encryption's core weakness: there's no shared secret that ever needs to be exchanged over a potentially insecure channel.
Practice — Test Yourself

These questions only cover what THIS subsection taught — asymmetric encryption (public/private key pairs).

Short answer 1
Which of the two keys — public or private — is ever shared with other people?
Reveal answer

Only the public key is shared. The private key is kept secret and never leaves its owner's computer.

Short answer 2
In the Tom-and-Jane example, which key does Tom use to ENCRYPT the document, and which key does Jane use to DECRYPT it?
Reveal answer

Tom encrypts using Jane's public key. Jane decrypts using her own private key.

Fill in the blank 3
A public key and its matching private key are mathematically ______, but one cannot be ______ from the other.
Reveal answer

Blank 1: linked. Blank 2: derived.

Spot the error 4
A student claims: "Jane can use her own public key to decrypt Tom's message, since it's the same key pair." What's wrong with this?
Reveal answer

This is explicitly false — Jane CANNOT use her public key to decrypt the message. Only her matching PRIVATE key can decrypt something that was encrypted with her public key. This asymmetry (different keys for encrypting vs. decrypting) is exactly what gives the method its name and its security.

Applied / scenario 5
Five colleagues (Tom, Jane, Susan, Mike, Megan) all want to be able to send EACH OTHER encrypted messages (fully two-way, not just to Jane). Using this lesson's content, describe what each person needs to do to set this up.
Reveal answer

Each of the five people must generate their OWN public/private key pair (not just rely on Jane's). Then everyone must exchange their public keys with everyone else, so each person holds the public key of every other colleague. Each person then decrypts incoming messages using their own private key, while encrypting outgoing messages using the recipient's public key.

Short answer 6
Explain why asymmetric encryption avoids symmetric encryption's key-sharing security risk.
Reveal answer

The private key — the one that actually matters for decryption — never has to be transmitted anywhere, so it can never be intercepted in transit. Only the public key travels across the network, and since it can't be used to decrypt anything, an eavesdropper intercepting it gains nothing useful.
