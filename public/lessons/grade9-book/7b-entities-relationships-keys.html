7.3 Entities, Relationships & Keys
Three types of relationship, and the two keys that connect tables together.

Entity

  • An entity is an independent TABLE; its fields are called attributes.
  • Example: a Payroll database has an "Employees" entity with attributes like EmployeeID, Name, Designation, Salary.
Theory — Three Types of Relationship

One-to-One

One record in an entity connects to exactly ONE record in another. Uncommon — used to split a large entity into smaller ones.

One-to-Many

One record in an entity connects to MANY records in another. The most common relationship type in relational databases.

Many-to-Many

Many records in one entity connect to many in another. Usually needs a third "junction table" to implement.

Primary Key vs. Foreign Key

  • Primary Key — uniquely identifies a record in an entity. Rules: the value must be UNIQUE (no two records share it), and it can NEVER be null.
  • Foreign Key — defines the CONNECTION between two entities. A foreign key in one entity is configured to match the primary key of another entity.

Worked example — Students, Class, Teachers

  • Students table — has Id as Primary Key, and ClassId as a foreign key linking to Class.
  • Class table — has Id as Primary Key. A student is in only ONE class → Students has a One-to-One relationship with Class.
  • Teachers table — has Id as Primary Key. Many teachers can teach many classes → a Many-to-Many relationship is needed with Class.
  • TeachersClass table — a JUNCTION table (its own Primary Key) that implements the Many-to-Many relationship between Teachers and Class, via a One-to-Many relationship with each.
Practice — Test Yourself

These questions only cover what this subsection taught — entities, relationship types, and primary/foreign keys.

Short answer 1
What are the two rules that apply to any field with a Primary Key?
Reveal answer

Its value must be unique (no two records share it), and it can never be null.

Short answer 2
Why is a junction table usually needed for a Many-to-Many relationship?
Reveal answer

Because a direct Many-to-Many link can't be cleanly represented between just two tables — a third "junction" table breaks it into two One-to-Many relationships instead, one with each original table.

Fill in the blank 3
In database terms, an entity's fields are known as ______.
Reveal answer

attributes.

Spot the error 4
A student says a foreign key must be unique in its own table, just like a primary key. What's wrong?
Reveal answer

A foreign key's job is to MATCH a primary key value in another table — it does NOT need to be unique within its own table (many records can share the same foreign key value, e.g. many students in the same class).

Applied / scenario 5
A library has many books, and each book can be borrowed by many different members over time (and each member can borrow many books). What type of relationship is this, and what extra table would likely be needed?
Reveal answer

A Many-to-Many relationship — it would need a junction table (e.g. a "Loans" table) connecting Books and Members.

Short answer 6
Why is One-to-Many the MOST common relationship type in relational databases?
Reveal answer

Because most real-world connections naturally work that way — e.g. one class has many students, one teacher may have many classes — making it the most frequently needed relationship shape.
